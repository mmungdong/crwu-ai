## 1. 前置与工具链（依赖说明）

**解释器口径（先读）**：本技能所有 Python 脚本都用 **DSH 自带的 Python** 执行 ——
自动审核模式用启动指令注入的**绝对路径**；独立使用技能时先调一次 `load_workspace_dependencies`
并用返回的 `python` 字段，复用同一个路径。**禁止**裸 `python3` 名字、任何解释器查找、
以及静默降级到系统解释器；本技能**不安装** Python、也不执行 pip。下面写的 `python3 scripts/<文件>`
一律按这个路径执行。

- `.xlsx`：用上面的解释器 + **第三方运行时依赖 `openpyxl`**（读缓存值 `data_only=True`；再开一档读公式串做公式审查）。
  **缺 `openpyxl` 时 fail closed**：该文件**不读值、不读公式、不重算、不生成工作版**，按"缺依赖"登记
  结构化 `capability gap`（依赖名 / 受影响格式 / 本次未核 / 未生成工作版），**不是**"材料缺失"。
  **不得**改成用 Python 标准库直接解析 OOXML 包来读单元格值或公式继续审核，也**不得**自行 pip 安装、
  不得切换/回退到系统解释器（解释器口径见上）。
- **C7 计算链重算引擎**：`<上面的解释器路径> scripts/recalc_check.py --workbook <raw.xlsx> [--out <diff.json>]`
  （随本技能安装、依赖第三方 `openpyxl`，对 `.xlsx` **可见区**公式独立重算，H0 安全；缺 `openpyxl` 时
  **清晰非零退出、且不产出差异文件**；见主流程 C7）。
- `.xls`（老二进制）与**公式重算**：需 LibreOffice headless：
  `soffice --headless --convert-to xlsx --outdir <dir> <file.xls>`（含 `.xls→xlsx`、公式重算需 `--convert-to xlsx:Calc MS Excel 2007 XML` 后以 data_only 读取，或用 macro 强制重算）；
  环境中无 soffice → 如实声明"该表未能重算/未能解析"，计入未核表清单，禁止猜测。
- **媒体/版式类证据不得据工作版判"缺失"**（重建法必然丢 `xl/media`、`word/media`、页眉页脚、批注、形状、图表）：
  询价截图、位置图、现场照片等**内嵌图/独立图片**已由编排层导出到 `媒体证据/` 并列入 `<阶段>媒体索引.json`；
  本能力**只按该放行清单的 `locator`/`localPath` 消费**，经宿主多模态读图（DSH `read_image`）判读——
  **不得自行解析 raw 原件包**（raw 只由编排层持有），也**不得**只看单元格（含 raw 的单元格）：
  那会把"证据在图片里"误判为"为空/缺失"。清单外（未导出）或宿主无视觉能力时只能出「**未核验**」，
  并逐条进 `scope.notCheckedItems`（`reasonCode=unreadable|unsupported`）——**未核 ≠ 缺失**。
  锚点落在隐藏区的媒体按 H0 **不进清单、不得引用**（隐藏区事项的定级与去向见 叶子共同约束 `12-leaf-common-contract.md` §7.1（由 router 持有；本技能运行时不读取它））。
  （真实失效 2026-302150-LX9757-BG8677：`MKT-004` 判"位置图为空、询价截图缺失"，
  而原件实有 26 个媒体对象、位置图带 4.6/5.4/3.8 km 标注。）
- `openpyxl` 由 **DSH 运行时自带**：缺失时记 capability gap 并停下，**不要**自行 pip 安装（判据见主流程与 `crwu-audit` 的「脚本运行时（Python）」）。LibreOffice 仍需按系统安装。

## 2. 主流程（含 C1–C9 检查目录与公式）
0. **隐藏区安全（最小铁律 · 最先执行）**
   > **隐藏区内容不得读取、解析、核对、引用或输出；发现未隔离隐藏区时停止该工作簿处理并登记 capability gap。**

   - **默认消费上游产物**：本技能默认只接收**上游已生成的可见区工作版**与隐藏结构元数据，
     **不自行**重新识别隐藏区（不解析 raw 包结构去猜隐藏范围）。
   - **fail closed**：收到的如果**仍含隐藏区、隔离状态未知，或隐藏元数据不可用** → 停止该工作簿处理，
     登记 `capability gap`（不继续解析、不出差异、不猜值）。
   - **合计口径**：合计勾稽只看**可见区**；合计公式引用范围覆盖隐藏行/列时，只核可见引用范围，
     并注明"该合计含隐藏区引用，仅核可见部分"（不因隐藏部分报漏/报错）。
   - **忽略清单（仅元数据，无内容值）**：`已跳过隐藏 sheet N 个（名单）、隐藏行 M 行、隐藏列 K 列（段位）`。
   - **定级与去向**：隐藏区相关事项的**定级、状态与去向唯一权威** =
     叶子共同约束 `12-leaf-common-contract.md` §7.1（由 router 持有；本技能运行时不读取它） —— 本技能**不复述**其状态表，按名回指。
1. **清单盘点**：列出材料包全部表格文件，标注每张表角色（明细/计算/汇总/填表说明/模板残留）。
2. **解析**：按工具链读取**可见区**的值与公式；按 H0 记录隐藏元数据并生成忽略清单；记录每表
   sheet 名、可见行数、可见区含公式/错误单元格数量。
3. **九类检查（只在可见区执行；公式/引用坐标基准=raw 原件坐标，见文首声明）**（命中才记差异）：

   > **编号冲突声明（2026-09-26 实核）**：下表 `C1`–`C9` 是**本技能自有的操作步骤编号**（输出契约
   > `类型(C1..C9)` 用的就是它）；权威根 `06-规则库/M-计算表审核/` 另有一套 `C1`–`C22` 检查点编号，
   > **两套编号不同、不得互读**（例：本技能 `C7` = 计算链重算，根 `C7` = 引用错行/错列/漏行）。每条口径
   > 一律以下表的"权威根对应检查点"为准：

   | 本技能步骤（自有编号） | 权威根对应检查点 | 库内文件 |
   | --- | --- | --- |
   | C1 合计／勾稽 | C2 可见区合计范围完整性；C11 明细表 ↔ 汇总表 | `01-工作簿结构与完整性审核`、`03-跨表跨文件勾稽审核` |
   | C2 跨表一致 | C11 明细表 ↔ 汇总表；C12 明细表 ↔ 报告/说明正文；C14 跨文件同名口径 | `03-跨表跨文件勾稽审核` |
   | C3 公式错误 | C8 错误码 | `02-公式链与重算审核` |
   | C4 单位／小数 | C17 单位与量级；C22 小数位与舍入 | `04-单位税率精度与符号审核` |
   | C5 跨项目模板串扰 | C5 工作簿版本与文件名一致性 | `01-工作簿结构与完整性审核` |
   | C6 口径与假设残留 | C3 空白与占位单元格 | `01-工作簿结构与完整性审核` |
   | C7 计算链重算 | C6 公式被常数覆盖；C7 引用错行/错列/漏行；C9 循环引用与外部链接；C10 重算值差异阈值判定 | `02-公式链与重算审核` |
   | C8 表单要素完整性 | **技能自有观察项**：库内**无权威判据** → 只出 `capability gap` 与 `pending_verification`，见该条说明 | — |
   | C9 增减值／增值率与符号 | C13 增减值与增值率勾稽；C21 正负号约定 | `03-跨表跨文件勾稽审核`、`04-单位税率精度与符号审核` |

   - C1 合计/勾稽：可见明细行求和 vs 表内合计 vs 汇总表合计 vs 报告结论金额/面积（单位一致）；
   - C2 跨表一致：同一口径（面积、租金单价、月/年租金、含税与否、物业费是否含入）在各表与报告间一致；
   - C3 公式错误：只扫**可见区**单元格（`#REF!`、`#DIV/0!`、`#N/A`、`#VALUE!` 等）；
     隐藏 sheet / 隐藏行 / 隐藏列中的错误单元格**不扫描、不报**（H0 铁律）；
   - C4 单位/小数：元 vs 万元、㎡ vs ㎡/月、单价×面积≈总价（±舍入）等；
   - C5 跨项目模板串扰：只扫**可见区** 项目名/坐落/房屋名称/权证号/页码 等是否残留**其他项目**内容
     （如同一机构同系列模板漏替换，如"红桂路2087"出现在"红宝路39号"表内）；
   - C6 口径与假设残留：只扫**可见区** 模板固定文字、占位（xxxx号文号、日期序列号未格式化、无关表数据 0 值大行）。
   - C7 计算链重算（只对 `.xlsx` raw 原件**可见区**公式格；`<上面的解释器路径> scripts/recalc_check.py --workbook <raw.xlsx> [--out <diff.json>]`）：
     独立重算可见区公式并与缓存值比对，**只报差异、不下判断**（引擎不自判谁对谁错）；
     支持算术 `+ - * / ^`、括号、比较、`SUM/PRODUCT/ROUND/IF/MAX/MIN`、单元格/绝对引用 `$A$1`、跨表引用 `'表名'!A1`；
     其余（百分比 `%`、文本拼接 `&`、未列函数）不实现 → 标「未重算」，绝不猜值；
     引用隐藏 sheet/行/列、外部工作簿、不支持的函数、解析失败、除零、**类型不匹配（日期−文本等，Excel 报 `#VALUE!` 的同类）** → 一律标「未重算(原因)」，**绝不判通过、绝不猜值**；
     其中"引用隐藏区而未能重算"的可见格**不作为差异**，只作**人工建议检查项**交出
     （去向与定级按 叶子共同约束 `12-leaf-common-contract.md` §7.1（由 router 持有；本技能运行时不读取它） 执行；本技能不复述该口径）；
      任何异常都不得中断整表：引擎自身未能处理的格单独计数（摘要 `engineErrors`），**非 0 须排查引擎缺陷**、不得当作"该表数据问题"；
     重算值≠缓存值（或无缓存值）→ 记差异 `C7-计算链`，交人工复算；一致 = 已核。`.xls` 先经 soffice 转 `.xlsx` 再核（见前置工具链）。
   - C8 表单要素完整性（只对**可见区**封面／页脚与明细表头；**不依赖表内是否含公式，属基础检查项，不得因无公式而跳过**）：
     逐项枚举并给出状态——产权持有人、产权持有人填表人、填表日期、项目负责人、签字资产评估师、各类评估人员、
     金额单位、表号、页码；序号是否自 1 起连续唯一并与项目名称一一对应；与本项目无关的资产类别栏目是否精简或说明。
     **口径缺口（2026-09-26 实核，不得再声称有库内口径）**：`M-计算表审核/` 全部 11 份正文中**没有任何**
     「表单要素」主题（全库检索 `表单要素` 命中 **0**），`01-工作簿结构与完整性审核` 的检查点是
     C1 工作表可见性／C2 可见区合计范围／C3 空白与占位／C4 重复维护同名口径／C5 版本与文件名一致性，
     **不含封面页脚、签字、页码、表号**；兼容入口也已声明"**不再单独定义检查点**"。因此本项属**技能自有的
     操作检查项、库内暂无口径**。
     **结论边界（2026-09-26 · R3 收紧）**：本项是**操作性观察**，不是公司强制规则 —— 缺项只能输出
     ① 可见区坐标；② 在件值或"该要素缺失"这一**事实**；③ `capability gap`（库内无权威判据）；
     ④ `pending_verification`，并在移交项里写明**人工确认去向**（交评估项目组/审核负责人）。
     **不得**因本项缺项直接下 `不符合`、不得据此出规则意见、不得计入"已确认问题"；**不得**为它
     伪造 RULE/CHK 来源（本条列出的要素是技能自列的观察清单，不是库内规则）。库内补上「表单要素」
     主题后，应改指该文件、按该口径重新界定结论去向，并删除本缺口声明。
   - C9 增减值／增值率勾稽与符号校验（只对**可见区**含「账面价值／评估价值／增减值／增值率」列的明细表、分类汇总表与万元汇总表；**不依赖表内是否含公式，属基础检查项，不得因无公式而跳过**）：
     **先定口径、再套对应公式**（顺序不可颠倒；库内依据见 `06-规则库/M-计算表审核/` 的 `03-跨表跨文件勾稽审核`「C13 增减值与增值率勾稽」与 `04-单位税率精度与符号审核`「C21 正负号约定」）：
     (a) **无条件前置**（对全部口径都成立）：
        - `增减值 = 评估价值 − 账面价值`；
        - **账面价值为 0**：不得计算比率（不得留 `#DIV/0!`，也不得目测补一个比率）；
        - **账面价值为负**、或账面价值为正但口径特殊，且缺少明确说明时：记 `pending_verification` 转人工，**不套任何比率公式**；
        - **必须先确认**本次采用哪种符号口径。来源限于报告正文／表头／表注备注／本次实时下载的知识库正文；**不得**凭行业惯例假定。
     (b) **口径 A · 有符号增值率**（报告列名与口径声明都是带符号的「增值率」）：
        - `增值率 = 增减值 ÷ 账面价值`；
        - 账面价值为正常正值时，**增减值与增值率同号**（账面 100 → 评估 80：增减值 −20、增值率 −20%）；
        - **减值时出现负增值率本身不是错误**；只有符号关系不符才算差异。
     (c) **口径 B · 正数幅度（减值幅度）**（必须有明确标签或口径声明，例如「减值率」「减值幅度」，或明示正数代表减值）：
        - `减值幅度 = (账面价值 − 评估价值) ÷ 账面价值`，等价于 `abs(增减值 ÷ 账面价值)`
          （账面 100 → 评估 80：增减值仍为 −20，**减值幅度为 +20%**）；
        - **不得要求**减值幅度与增减值同号；
        - 报告正文、摘要、明细表、分类汇总表、万元汇总表必须使用**同一标签与约定**；
        - **不得**把一处有符号的「增值率」与另一处正数的「减值率／幅度」当作同一字段直接比较。
     (d) **口径 C · 无法确认公司口径**：**不选** A 或 B；输出 `capability gap` 与 `pending_verification` 并转人工；
        **不作判断**（不得直接判 `不符合`）、不得凭行业惯例自选口径。
     (e) **减值不得漏披露**：出现减值（增减值为负）而报告正文／结论处未作增减值原因分析的，记差异交报告披露轴。
4. **输出差异清单**（不下价值判断）：每条 = 表名/sheet/位置(行或单元格) + 类型(C1..C9) +
   证据值（表内 vs 表外/报告值）+ 建议核验动作。供调用方（rent 等技能）按 CHK/RULE 出规则意见，
   例如：汇总数与报告结论不符 → 反证报告数字污染（RULE-01-02-561/576/254 语境）；
   修正系数表与说明不一致 → CHK-MKT-013；公式错误表参与汇总或重算不一致 → 高优复算。
5. **收尾**：明确列出"已核表 / 未核表（含原因）"与"已跳过隐藏区（仅元数据）"；差异条数进入台账 `data_diff_count`。

  （233,000）为污染；可见区"报告说明用表/页眉"残留红桂路2087；畸形户型备注"半折"与折扣率 0.03
  语义需澄清。隐藏模板区（如办公房产案例表等隐藏 sheet/行/列）内容按 H0 强制跳过，不报。
