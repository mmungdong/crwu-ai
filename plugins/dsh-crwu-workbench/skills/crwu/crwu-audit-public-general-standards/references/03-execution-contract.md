# 通用准则公共能力 · 执行契约（本 Skill 本地）

| 版本 | v1.0 | 状态 | 2026-09-25 立规 | 维护 | crwu-audit-public-general-standards |
| --- | --- | --- | --- | --- | --- |

> 本文件是**本能力自己的、自包含的执行契约**：只保留 `public` 轴通用准则能力真正需要的共同口径
> （输入边界、执行顺序、条目状态、来源优先级、证据字段、capability gap）。
> 资产/业务叶子共同约束里的**轴边界、一级根装配与二级选择对本能力不适用**，因此不在此复制。
> 本 Skill 运行时**只读取自己目录内的文件**，不读取任何 sibling Skill 的文件，也不把它们的文件当作优先级来源。

## 1 调用边界与输入边界

- **仅经 `crwu-audit` router 编排调用**，禁止单独调用；不查询报告记录、不自行获取材料、不重新下载规则。
- 输入只有三项，缺任一项记 capability gap，不自行补取：
  1. 编排层冻结的 `route_profile`（本能力只消费 `report_form`、`record_context` 与材料分区，
     不消费具体专业轴标签）；
  2. 编排层已准备并隔离的报告、评估说明、测算明细表等材料路径；
  3. 编排层已验证的**本次** DWS manifest 及其文件路径、`exportedAt`。
- 不得沿用上一轮下载物、目录缓存或历史摘录充当本次正文。
- 本能力**不做外部取数**，也不依赖任何外部数据核验能力的规程；交付件涉及外部数据核验结论时只引用编排层给出的回执。

## 2 执行顺序

1. 按 `00-applicability.md` 界定适用范围，不改变编排层已确定的任何轴标签；
2. **先判规则版本**：新旧两版施行日期不同时，按报告基准日／报告日所属期间选定**整段**引用版本，
   禁止新旧条款混引；版本无法确定时记录冲突并转人工判断，不任选一版；
3. 用本次 manifest 验证 `01-kb-assembly.md` 所需文件；缺失项按路径与原因记 gap，对应检查不引用、不编造；
4. 报告披露层与程序质控层**各自独立**执行、各自独立出条目状态；一层缺依据不影响另一层执行；
5. 按 `02-review-focus.md` 分别审核报告、评估说明、测算明细表，不以"未发现问题"笼统概括。

## 3 条目状态

命中审核文件后，其中**每一项**必须产生一条状态，不得以"未发现问题"笼统概括。

必检项 / 必检项要点：

| 字段 | 允许值或要求 |
| --- | --- |
| `status` | `符合`、`不符合`、`不适用`、`无法核验` |
| `report_evidence` | 当前报告页码、章节、表格或附件位置 |
| `rule_source` | 对应来源路径及 RULE/CHK 标识 |
| `reason` | `不适用`、`无法核验` 时必填 |
| `finding` | `不符合` 时必填，描述当前项目具体问题 |

历史高频复核问题：

| 状态 | 含义 |
| --- | --- |
| `涉及` | 当前报告存在对应风险迹象，并给出本项目证据 |
| `未涉及` | 已检查，当前报告未出现 |
| `无法核验` | 资料不足，并列明缺失资料 |

- 来源写有"待补"、`TODO`、空文档时：**登记知识库内容缺口**，不根据标题、经验或历史补造要求，
  该层覆盖记为不完整。
- 索引卡类文件**不构成规则条目**，不得作为规则性缺陷的 `rule_source` 依据；模板参考类文件只做格式基线对照。
- 相同检查点稳定去重，但保留全部 `source_skills[]` 与 `rule_source`。

## 4 来源优先级与冲突

1. 现行法律法规、执业准则和有效监管规则（硬约束）；
2. 必检项（确保约束与业务要求被完整执行）；
3. 历史高频复核问题（防止重复发生既往缺陷）；
4. 审核经验（补充视角，不得降低或覆盖更高层级要求）。

来源冲突、失效或版本不明时：停止形成确定性结论，记录冲突双方与来源，转人工判断；
不得用低层级经验覆盖准则。历史次数、旧项目名称与案例只用于提示检查方向，**不是当前事实，也不是现行准则**。

## 5 证据字段与出处

- 每条 finding 的出处至少包含：**本次下载文件、实际行号、库内路径、本次运行返回的 `nodeId`、`exportedAt`**。
- 运行时值（`nodeId` 等）不得写回技能文件。
- 技能文件只写 RULE/CHK 编号与库内层级路径寻址键，以及基于本次真实读取归纳的要点；**不得逐字复制知识库正文**。
- 每条 finding 带 `source_skills[]`（至少包含 `crwu-audit-public-general-standards`）、
  `report_evidence`、`rule_source`、`status`；按报告 / 评估说明 / 测算明细表分区组织，不混写。

## 6 capability gap

以下情形必须留 gap，且**只影响对应检查**，不得让其他可用能力停止执行：
目录未完整、递归下载失败、空目录、不支持导出的节点、审核文件缺失、内容为占位/待补、
规则版本不明、来源冲突、报告证据不足。

gap 要写清：缺什么、在哪个库内层级路径、影响哪些检查、需要谁补。

## 7 输出前自检

- 报告披露层与程序质控层是否**各自**有独立条目状态；
- 版本选择结论（选定版本与依据）是否显式记录，便于人工复核；
- 必检项是否逐项有状态、gap 是否登记；
- 索引卡 / 模板参考类是否被误用为规则性缺陷依据。
