# 叶子技能共同约束（资产轴 / 业务轴通用）

| 版本 | v1.0 | 状态 | 2026-09-10 定稿 | 维护 | crwu-audit + crwu-dev-audit-skill-maintainer |
| --- | --- | --- | --- | --- |

> 本文件是**所有 `crwu-audit-asset-*` 与 `crwu-audit-biz-*` 叶子**的共同约束：公共部分只写一份，
> 由确定性同步命令复制为每个叶子的本地副本 `references/03-common-contract.md`；**运行时只读取本 Skill 目录内的这一份**。
> 叶子自己的 `SKILL.md` 只写"本轴/本标签特有"的内容，其余按本文件执行。
>
> **位置与维护关系（源码维护口径，不是运行时依赖）**：源仓中的规范源位于
> `crwu-audit/references/12-leaf-common-contract.md`，由 `crwu-dev-audit-skill-maintainer` 的
> `scripts/kb_tool.py sync-leaf-common-contract --write` 同步到各叶子，`kb_tool.py validate` / `--check` 阻止缺失与漂移。
> 规范源与各叶子副本**逐字节相同**，是一个内容的多个副本，**不是多个独立事实源**。
>
> **自包含边界**：本文件不把任何 sibling Skill 内的文件当作运行时读取对象或优先级来源。
> 文中出现的「router / 编排层」一律只描述**调用方提供的输入接口**（即叶子收到什么），不要求叶子去读取调用方的文件。
> 与调用方在**分发与交付**层面的规则冲突时以调用方为准，但这类规则只经叶子收到的
> `route_profile` / 本次 manifest / 材料路径体现；叶子**不需要、也不得**为此打开任何外部文件。

## 1 调用边界

- **仅经 `crwu-audit` router 编排调用**，禁止单独调用；叶子 `SKILL.md` 必须显式声明该门禁。
- 不查询报告记录、不自行获取材料、不重新下载规则正文之外的东西。
- **不自行外部取数**：普通资产/业务叶子一律不得连接任何外部数据源，也不得自行探测取数入口。
  报告引用的外部公开数据由**独立的外部数据核验能力**负责，该能力由编排层按画像条件另行装配；
  它的执行路径、数据源、凭据归属与降级口径**不在本契约内定义**，叶子不得依赖它、不得复制其规程，
  也不得把「未做外部核验」写成本叶子自己的缺失。交付件涉及外部数据核验结论时，只引用编排层给出的回执。
- 不产出面向委托方的审核意见：叶子只产出 findings，由 router 汇总、去重并交付。
- 不修改任何运行时技能目录；改动只落源仓。

## 2 输入契约

叶子只接受这三项，缺任一项记 capability gap，不自行补取：

1. router 冻结的一级 `route_profile`（五轴标签 + 证据 + `confidence`/`review_required`）；
2. router 已准备并隔离的报告、评估说明、测算明细表等材料路径；
3. router 已验证的**本次** DWS manifest 及其文件路径、`exportedAt`。

不得沿用上一轮下载物、目录缓存或历史摘录充当本次正文。

## 3 轴边界

| 轴 | 只管 | 不管 |
| --- | --- | --- |
| 资产轴 `crwu-audit-asset-*` | 对象/资产类型的专业规则：权属、实物与经济特征、资产特有方法前提、对象特有风险 | 评估目的与经济行为（业务轴）；方法与监管正文（method/overlay 轴）；表格勾稽（public 轴） |
| 业务轴 `crwu-audit-biz-*` | 评估目的、经济行为与场景规则：租赁、处置、拍卖、清算、抵押、财务报告目的等对口径、材料和判断的影响 | 对象专业规则（资产轴）；方法与监管正文；表格勾稽 |

- **禁止创建 `资产 × 业务` 组合 Skill**。同一报告命中多轴时由 router 做稳定并集；任一轴都不得替代另一轴。
- 业务目录内的"资产专项"只按 `route_profile.asset_types[]` 与二级对象结果**条件使用**，不得据此新建组合技能，也不得取代资产轴。
- 跨轴冲突并列呈现交人工复核，不以后加载的来源覆盖先加载来源。

## 4 装配契约（一级根）

- 每个叶子**恰好登记一个一级根**：资产 = `02-资产类型/<一级资产>/`，业务 = `01-业务路线/<一级业务>/`。
- 一级根必须是 `request_kind=directory`、`recursive=true`、`required=true`；**递归下载根内全部支持正文**，不退回逐文件挑选。
- 细分对象与子业务**不各建 Skill、不各占 registry 行**；它们是父级叶子在已下载目录包内的二级选择索引。
- 全局执行契约、方法正文、监管正文由 router 的其他轴装配，不复制进本轴的根映射；财务报告覆盖规则是唯一按 `business_types[]=财务报告` 动态追加的业务补充包，仍不登记为叶子的第二个一级根。
- 路径键一律用**库内层级路径**写法；禁止本地知识库根字面、`KB/<相对路径>` 引用、个人绝对路径。

## 5 二级选择契约

叶子在**已下载目录包内**完成二级分类，不改变一级路由，返回：

```json
{
  "parent_label": "<一级标签>",
  "label": "<细分对象或子业务>",
  "evidence": [{"source": "<材料类型>", "location": "<报告:页码或章节>"}],
  "confidence": "high|medium|low",
  "review_required": false,
  "selected_relative_paths": ["<相对路径>"]
}
```

- 数组名：资产轴 `asset_subobjects[]`，业务轴 `business_subroutes[]`。
- 证据以**评估对象、资产明细、权属材料、评估目的原文**等原始材料为准，不得只凭文件名或报告标题判断。
- **同时命中多项全部保留**，不使用"首次命中即停止"。
- 低置信度标记 `review_required=true`，并审阅全部合理候选，不猜唯一分类。
- 结果只并入本次审核运行记录，**不回写或篡改** router 已冻结的一级 `route_profile`。

## 6 执行顺序契约

统一按「**一级共用层 → 命中二级条目**」执行，不得颠倒、不得因为只命中一个二级项就跳过共用层：

| 轴 | 一级共用层 | 命中后的二级条目 |
| --- | --- | --- |
| 资产 | `01-共性参考/` 下全部文档（对象准则、定义分类、共性评估审核条目及相关复核条目） | 每个命中 `02-细分对象/<对象>/` 的 `评估审核条目` |
| 业务 | 一级根直接文档 `共同审核点`（**若库内存在**） | 每个命中子业务的 `01-业务通用审核要点` 及其同目录关联文件（资产专项、方法适用索引、监管适用索引） |

- 一级共用层缺失：资产缺 `01-共性参考/` 记内容缺口；业务缺 `共同审核点` **不记缺口**（条件性约定）。
- 已下载但未命中的二级资料：登记"未选用及原因"，不强行套用。

## 7 条目状态契约

命中审核文件后，其中**每一项**必须产生一条状态，不得以"未发现问题"笼统概括。

必检项 / 必检项要点：

| 字段 | 允许值或要求 |
| --- | --- |
| `status` | `符合`、`不符合`、`不适用`、`无法核验` |
| `report_evidence` | 当前报告页码、章节、表格或附件位置 |
| `rule_source` | 对应来源路径及 RULE/CHK 标识 |
| `reason` | `不适用`、`无法核验` 时必填 |
| `finding` | `不符合` 时必填，描述当前项目具体问题 |

历史高频复核问题：

| 状态 | 含义 |
| --- | --- |
| `涉及` | 当前报告存在对应风险迹象，并给出本项目证据 |
| `未涉及` | 已检查，当前报告未出现 |
| `无法核验` | 资料不足，并列明缺失资料 |

- 来源写有"待补"、`TODO`、空文档时：**登记知识库内容缺口**，不根据标题、经验或历史补造要求；该子业务的必检覆盖记为不完整。
- 相同检查点稳定去重，但保留全部 `source_skills[]` 与 `rule_source`。

### 7.1 隐藏区相关条目的定级与去向（2026-09-15 立规 · 2026-09-16 用户口径修订）

人工隐藏的 sheet／行／列／折叠分组由员工手动隐藏，**整体排除审核范围**（H0：禁读禁报——不读取、不解析、
不核对、不引用其中任何值或公式，也不对其产生意见、不写入证据值；对隐藏区既不报错也不报漏）。
凡结论涉及隐藏区，按下列三档处理，**不得再按普通缺陷定级**：

| 情形 | 定级 | 去向 | 备注 |
| --- | --- | --- | --- |
| **隐藏区内容本身的判断**（含读取隐藏格取值、对隐藏列/表下结论） | 不作为意见 | 必要时登记「待人工复核事项」 | 需 H1 书面授权方可读取；未获授权不得进入结论 |
| **不确定项**：可见结果是否依赖隐藏输入、隐藏区取数口径/用途不明、隐藏结构元数据与实际不一致而影响可复核性 | **S3（最低等级）** | **`manualConfirmationItems[]`（`decision=pending_confirmation`、`review_required=true`）** | 不计入 `fail`／不进入「需要处理的问题」；标题须写明"待人工确认" |
| **被可见公式引用的隐藏区**：可见格公式**确实**引用了隐藏行/列/隐藏工作表，该可见结果的计算输入不可见 | **S3（最低等级）** | **`manualConfirmationItems[]`（人工建议检查项，`review_required=true`）** | **2026-09-16 口径**：审核只要公式计算正确即可——**不得**将其出成 `issues[]`、不得据此升级严重度；建议人工核对隐藏区公式与结果 |

纪律：

1. **两类必须分开**：第 2 行（不确定）与第 3 行（被引用的隐藏区）不得混为一条；同一发现同时涉及两者时拆成两条。
2. **默认取不确定档**：只要"是否依赖隐藏输入"本身无法在不读隐藏区的前提下判定，就按第 2 行处理，不得推测。
3. **可见区自身算错照常出问题**：可见区勾稽不符、重算值≠缓存值等**可见区**缺陷，仍按普通可见区缺陷定级进 `issues[]`——
   **不因涉及隐藏区而加严，也不因涉及隐藏区而放松**；本表只约束"隐藏区相关"的去向。
4. **建议项只为被引用的隐藏区出**：表内存在隐藏行/列/sheet 但不参与任何可见公式计算的不出建议项（避免噪声）。
5. **元数据可信度**：隐藏结构以**原件 raw XML 的真实区段**（`<col min max hidden>`／`<row hidden>`）为准；
   工具给出的隐藏集合若与 raw XML 不一致，按 raw XML 判定，并**另记一条 `capability gap`**（工具缺陷），
   不得把工具缺陷产生的差异写成被审件缺陷。
6. 定级只影响"处理去向与优先级"（走人工确认、不占不通过数），**不影响证据留痕**：仍须给出被审件在件位置与原始摘录 —— **只允许摘录可见结果、可见公式或其它可见证据**；**不得摘录隐藏区内容**（隐藏区既禁读，也不得进入任何摘录、证据值或引用）；
   `材料盘点.json` 的 `hiddenRefs` / `calcChainNotReproducible` 是**审计元数据**，供生成上述建议项，本身不构成 AI 问题。

### 7.2 程序层条目的判据深度与跨文件语义一致性（2026-09-16 立规）

程序层条目（现场调查、资料核查验证、引用其他机构报告、资产核实、权属查验等）**不得只做"环节是否披露"的齐备性核对**，须再核"程序内容是否与本项目评估对象类型、业务场景相适配"：

| 维度 | 须核到什么 | 不满足时的去向 |
| --- | --- | --- |
| 环节齐备性 | 按当次选定版本的程序准则，要求披露的环节是否均有披露 | 缺环节 → `不符合` |
| 程序适配性 | 程序手段是否匹配评估对象类型与业务场景，是否沿用其他资产类型的模板化表述（示例：对以数据、权利或系统记录为标的的对象，仍通篇写"现场实地勘查／账、表相符"即属未适配） | 模板化且不匹配 → `不符合`，并在条目中写明应补的专项手段 |

**跨文件语义一致性**：结论性表述（评估说明的核实结论、评估假设、方法理由）须与测算明细表数值、报告披露相互一致。凡出现"核实结果与账面记录一致"而账面价值为 0、"权属证明文件齐全"而权属登记于基准日后取得等**同一事实在不同文件间相互矛盾**的情形，即出条目——数值勾稽通过不等于语义自洽。

纪律：本节核对只引用当次选定版本的程序准则 RULE 编号与库内层级路径寻址键；**各资产类型应核的具体专项手段以知识库对应条目的检查点为准，本文件不复制清单正文**。

### 7.3 基础要素一致性必查项（叶子公共 · 2026-09-16 立规）

下列五类属**跨全部资产轴与业务轴的公共必查项**，任何命中叶子都必须逐项执行并按 §7 产生状态；它们对应的历史复核问题在 ≥380 个项目上逐字出现（公司复核表固定检查项），不是某个资产的专属事项。各资产／业务条目的专属检查点不因本节存在而免检：

| # | 必查项 | 核到什么 | 不满足时的去向 |
| --- | --- | --- | --- |
| 1 | **数值四表勾稽** | 报告正文、报告摘要、评估说明、评估明细表（含万元汇总表）四处同一口径的评估值／账面值／增减值／增值率必须同值；万元汇总表与明细表在万元口径下一致 | 任一处不符 → `不符合`，写明两处位置与各自数值 |
| 2 | **基础日期四处一致** | 封面报告日、正文末尾报告日、签字盖章日、评估师承诺函日期四处一致；且评估组核实工作期间落在评估基准日之后、报告日之前且期间合理；承诺函／有关事项说明签署日期不晚于报告日 | 不一致 → `不符合`；期间不合理 → `不符合` 并写明实际期间 |
| 3 | **增减值与增值率自洽（先定符号口径、再套对应公式）** | **无条件前置**：`增减值 = 评估价值 − 账面价值`；**账面价值为 0** 不得计算比率（不得臆造，也不得目测补一个比率）；**账面价值为负**、或账面价值为正但口径特殊且缺少明确说明 → `pending_verification` 转人工，**不套任何比率公式**；**必须先确认**报告采用哪种符号口径（来源限于报告正文／表头／表注备注／本次实时下载的 `06-规则库/M-计算表审核/` 之「C13 增减值与增值率勾稽」「C21 正负号约定」），**不得**凭行业惯例假定。**口径 A · 有符号增值率**：`增值率 = 增减值 ÷ 账面价值`，账面价值为正常正值时增减值与增值率**同号**，**减值时出现负增值率本身不是错误**。**口径 B · 正数幅度（减值幅度）**（须有「减值率」「减值幅度」等明确标签或声明，或明示正数代表减值）：`减值幅度 = (账面价值 − 评估价值) ÷ 账面价值`（等价 `abs(增减值 ÷ 账面价值)`），**不得要求**减值幅度与增减值同号；报告正文、摘要、明细表、分类汇总表、万元汇总表须使用**同一标签与约定**；**不得**把有符号「增值率」与正数「减值率／幅度」当作同一字段直接比较。**口径 C · 无法确认公司口径**：**不选** A 或 B，记 `capability gap` 与 `pending_verification` 转人工，**不作判断**（不得直接判 `不符合`）。 | 违反**已明确选定**的口径（A 的同号关系不符；B 的标签或跨文件约定不一致）→ `不符合`；口径未确认 → **不作判断**、转人工；增减值恒等式不成立 → `不符合`；出现减值而结论处未作增减值原因分析 → `不符合` |
| 4 | **目录与页码** | 报告目录与说明目录均为最新且与各部分内容对应；页码连续、无重复、无漏页；页眉与所属文件一致 | 任一项不符 → `不符合`，写明页码位置 |
| 5 | **单位与小数位** | 全文金额单位（元／万元）标注完整且前后一致；单价、面积、比率的小数位符合公司口径且表间一致 | 不符 → `不符合` |

纪律：

1. 本节只定**执行要求与去向**；具体条目编号、检查点文本与公司口径**一律按装配表从知识库实时下载后只读引用**，本文件不复述、不列举。
2. 第 3 项的口径可能随公司要求调整；**口径缺失或库内条目未就位时记 capability gap 并转人工**，不得凭行业惯例自定符号写法。
3. 表格侧的机械核验由编排层按需叠加**表格勾稽能力**（其 C1／C2／C4／C9 覆盖本表第 1、3、5 项的表内部分）；
   叶子不得因编排层已调用该能力而省略本表第 2、4 项。


## 8 来源优先级与冲突

1. 现行法律法规、执业准则和有效监管规则（硬约束）；
2. 必检项（确保约束与业务要求被完整执行）；
3. 历史高频复核问题（防止重复发生既往缺陷）；
4. 审核经验（补充视角，不得降低或覆盖更高层级要求）。

来源冲突、失效或版本不明时：停止形成确定性结论，记录冲突双方与来源，转人工判断；不得用低层级经验覆盖准则。
历史次数、旧项目名称与案例只用于提示检查方向，**不是当前事实，也不是现行准则**。

## 9 证据与出处

- 每条 finding 的出处至少包含：**本次下载文件、实际行号、库内路径、本次运行返回的 `nodeId`、`exportedAt`**。
- 运行时值（`nodeId` 等）不得写回技能文件。
- 技能文件只写 RULE/CHK 编号与库内层级路径寻址键，以及基于本次真实读取归纳的要点；**不得逐字复制知识库正文**。

## 10 capability gap

以下情形必须留 gap，且**只影响对应检查**，不得让其他可用能力停止执行：目录未完整、递归下载失败、空目录、不支持导出的节点、审核文件缺失、内容为占位/待补、规则版本不明、来源冲突、报告证据不足。

gap 要写清：缺什么、在哪个库内层级路径、影响哪些检查、需要谁补。

## 11 输出

- 每条 finding 带 `source_skills[]`（至少包含本技能名）、`report_evidence`、`rule_source`、`status`。
- 分区（报告 / 评估说明 / 测算明细表）组织，不混写。
- 输出前自检：二级选择是否回指一级根、共用层是否执行、必检项是否逐项有状态、gap 是否登记。
