# 入口 Wiki 与知识读取契约（knowledge routing）

这一份是**技术合同**：唯一入口在哪、怎么按条件逐步读、读到什么程度算有依据、缺失怎么处置。
**它不含任何业务规则正文** —— 选法条件、案例阈值、参数取值、来源优先级、模板单元格表都不在这里。
业务规则的唯一来源是「中瑞世联业务知识库」的实时正文。

## 0. 唯一入口

| 项 | 值 |
| --- | --- |
| 知识库 | `中瑞世联业务知识库`（**不是**审核知识库；库身份由 Host 按精确库名解析） |
| 入口 Wiki | `01 估值与测算/01 房地产/wiki.adoc`（**节点真实扩展名**） |
| 入口身份 | 由**本技能自己声明一次**（就是上面这一行）；`SKILL.md` 只引用本文件、不重复路径；部署配置里的 `valuation.knowledge.wikiPath` 必须与本行逐字一致（工具回执里的 `entryWikiPath` 就是它）。随包默认值与 `DEFAULT_VALUATION_KNOWLEDGE.wikiPath` 已对齐为 `.adoc`；显式覆盖仍允许 `.md` 文本（导出链接的 textual alias 保留） |

入口 Wiki 持有：读输入的顺序、识别对象的依据、按用户选择分流到哪一份方法正文、
需要案例与参数时读哪一份、模板路由、结果协调与缺失处置。**Agent 按它的条件逐步读**：
不要求一次读完全库，也不要求它符合某个固定章节结构。

> **实读事实（2026-10-16）**：入口节点的真实扩展名是 `.adoc`；而导出 markdown 里，指向各方法 /
> 案例 / 参数 / 模板说明正文的**库内相对链接写的是 `.md`**。不能从链接后缀反推节点类型：
> 把 `wikiPaths` 逐字传给工具、再按返回的 `links[].target` / `path` 继续，才是正确做法。

## 1. 库内相对路径链接（正文的主要导航形式）

入口与各正文之间用**知识库相对路径**互链，例如：

```markdown
先读[输入与资料解释](<01 房地产估值通用/01 输入与资料解释.md>)
再读[市场法](02 估值方法/02 市场法.md#第-3-节)
```

三条硬口径：

1. **基准是当前文档所在库内目录**，不是知识库根，更不是本机路径。
   `01 房地产/wiki.adoc` 里的 `<01 房地产估值通用/01 输入与资料解释.md>` 指
   `01 估值与测算/01 房地产/01 房地产估值通用/01 输入与资料解释.md`。
2. **不许逃出知识库根**。`..` 越界、以 `/` 开头的绝对路径、本机路径都判**非法**并说明原因；
   `https://…` 是外部参考，`#小节` 是本文档内的锚点 —— 两者都**不**当成知识节点。
3. **读之前核对节点身份**。同名歧义、找不到、越界分别如实报告；**同名不许挑第一份**。

> 上面代码块里的 `.md` 是**导出正文里的链接写法**，不是节点真实扩展名；节点可能实际是 `.adoc`。
> 解析与匹配以工具返回的 `path` / 目录清单为准，**不要按链接后缀改名或改名后再传**。

解析与分类由 Host 的 `knowledge/wiki-links.ts` 完成，链接随正文条目一起返回
（`crwu_valuation_knowledge_materialize` 的 `entries[].links[]`）：`kind` 分
`knowledge` / `external` / `anchor` / `invalid`，`invalid` 的 `error` 就是处置依据。
维护者日后把路径链接换成知识库原生节点链接，两种写法指向的仍是同一份真实知识。

## 2. 读取方式：在线按需，不整库下载

- 只读**本次分支真正需要**的正文与章节；不做一次性全量导出，也不把整库拉进案例目录。
- 每次读取留下可核对的证据：实际采用的**片段**、节点身份（库内路径 / 节点名）、章节位置、
  读取时刻、来源更新时间或版本，以及**实际读取内容的摘要**。
- **分段读取的摘要只标识该片段**，不能冒充全篇指纹；本地文件修改时间也不等于远端更新时间。
- 二进制计算模板按**实际采用的方法与对象**取回（走 `crwu_valuation_template_materialize`），
  复用同源模板；不预取全部，也不限制成"一项目最多两个"。

## 3. 缺失、歧义与权限（逐条处置，不整体停）

| 现象 | 处置 |
| --- | --- |
| 入口 Wiki 读不到 / 库身份不是业务库 | **没有业务入口**：如实说明并交回人工，不用本机副本或旧内置正文顶替 |
| 入口可读，但某一篇方法正文缺失 | 只影响该方法：登记能力缺口，其余有依据的对象与方法继续 |
| 节点存在但正文为空 | `empty` ≠ `missing`，分开报；空正文不当作"该方法没有要求" |
| 同名歧义（折叠后仍有多份） | 列出全部候选路径，请人工确认；**不替用户选第一份** |
| 无权限 / 越界 / 绝对路径 | 如实报非法或不可读，不尝试绕过 |
| 参数、税率或修正系数没有出处 | 不使用模型记忆、演示数值或另一地区的数值顶替；按第 4 节登记 |

## 4. 参数与模板：只接受有出处的值

- 参数从**有依据的正文或表格**里取，并附**出处与单位**；类型化之后交给计算工具校验类型、单位与
  实际引用依据。业务维护者**不需要**先写专用 JSON 参数段 —— 正文表格就是权威来源。
- 模板的关键输入区、公式区与结果读取位置**以该模板自己的填写说明为准**；通用脚本不假定工作表数量、
  顺序或业务公式。模板字节与来源要核对，原模板只读，公式区不许硬编码。
- 缺关键参数**不是**"用默认值补上"：登记为关键参数缺失并**挂起相关计算**，其余工作继续。
- 业务阈值、税率、修正系数与案例数量判据**一律不在本技能里内置**（脚本里也没有默认值）；
  缺就按 `manual_confirmation_items[]` / `capability_gaps[]` 如实登记。
- **当前数值执行适配器的真实边界**：普通正文与表格**就是**权威来源，可正常阅读、引用与人工取值；
  可选 `stage=parameters` 目前只解析**围栏 JSON 规则段**。正文缺该段时只是"无法自动执行数值"，
  记为适配器契约缺口，**不是**知识不存在，也**不要**据此要求业务维护者改写正文或补 JSON；
  自动数值执行在缺段时未就绪，人工按正文取值照常。

## 5. 与审核知识库的区别

| 库 | 用途 |
| --- | --- |
| `中瑞世联业务知识库` | 本技能的全部业务正文与模板（估值规范、方法、案例渠道、参数、模板说明） |
| `中瑞世联评估审核知识库` | 审核链路的规则与检查点（`crwu-audit` 系列），与本技能无关 |

两个库的身份都要按**精确库名**解析；目录名像业务库不构成身份证明。本地缓存通常是**审核库**，
不得拿来当业务正文的来源；`_manifest.json` 之类的本机导出文件也不作为入口或兜底。

## 6. 结果里的知识留痕

`估值报告数据.json` 的 `knowledgeSources[]` 要能让复核者回答"这条结论依据的是哪一版、哪一节"：
每条至少给出 `routeId`（或库内路径）、实际节点名、来源（`dws` / 已验证镜像）、正文指纹、
落盘文件与本次采用的章节 / 规则标识。**只写正文 hash 不足以证明某条参数存在** ——
引用规则时必须同时给出快照指纹与节 / 规则标识。
