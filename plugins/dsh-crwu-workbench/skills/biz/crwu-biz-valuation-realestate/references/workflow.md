# 工作流（协议 42 · 启动页 → 父估值会话）

本文件说明**一次估值从「确认」到「交付」实际发生什么**，以及每一步由谁负责、调用哪个能力、
留下什么产物。业务规则不在本文（见「三、知识读取」），技术合同见
[09-output-contract.md](09-output-contract.md)。2026-10-16 的实时知识库实读证据保存在源仓的
历史评审快照里，不随技能目录分发。

## 一、职责边界

| 谁 | 负责 | 明确不做 |
| --- | --- | --- |
| 面板 / Host | 递归整理本机选择（1–30 份）、把输入**冻结**成预览、创建**一个**父估值会话并交接、门禁三操作、浏览器 profile 串行队列 | 不做分组 / 方法判定 / 取数 / 测算（那些在会话里） |
| 父估值会话 | 分析资料、识别对象、拆分方案、判方法、取数与留证、测算、组装报告数据、调用 finalize | 不改冻结输入；不自己宣布完成 |
| Host 工具 | 每一步的**真实动作**：取知识、取数、截图、算、渲染、校验 | 不做业务判断（方法适用性来自知识正文） |

**只创建一个父会话**：确认成功即交接，随后自动跳转；没有进度页、没有结果页，也没有
"交接后轮询完成度"这回事 —— 完成由 [finalize](#七完成判定) 显式判定。

## 二、阶段与产物

```text
① 确认（面板）        → 估值输入.json（冻结：方法请求 / 基准日 / 补充要求 / 资料清单 / 摘要）
② 知识（会话按入口 Wiki 逐步读） → 知识快照/（正文 + 知识来源/<routeId>.json + .知识来源.json）
③ 对象与方案（会话）  → 项目估值方案索引.json（objects / plans / tasks / 方法判定）
④ 案例与参数（会话）  → 方案/<planId>/估值案例.json、估值参数.json（+ 方案内 来源证据/、推理结果/图片/）
⑤ 测算（脚本）        → 中间值全部由脚本算，阈值来自知识快照（逐对象一份底稿）
⑥ 报告（脚本）        → 方案/<planId>/估值报告数据.json → 估值报告.html（固定模板）
⑦ 完成判定（Host）    → crwu_valuation_finalize → completed | partial | blocked | failed
```

各阶段调用的能力：

| 阶段 | 能力 | 关键约束 |
| --- | --- | --- |
| ① 材料 | `crwu_valuation_file_extract`（案例目录内的相对路径清单） | 逐份读取，**读不出来就说读不出来**：缺库 / 旧版二进制 Office / 压缩包一律进 `capabilityGaps`；PDF 逐页报文本层（见「二之一」） |
| ② 知识 | `crwu_valuation_knowledge_materialize`（`wikiPaths` 主通道 / `routeIds` 遗留 / `stage=parameters`） | `source` 只有 `dws` / `verified-mirror`；**没有本地降级**；入口 Wiki 读不到 → 中断受影响方案并输出说明原因的 HTML；在线 `dws` 就在这个 Host 工具内完成，会话不走浏览器 / shell |
| ② 模板 | `crwu_valuation_template_materialize`（`method` 必填；按索引取已发布模板） | **二进制**逐字节取回，按索引声明的指纹/大小验真；当前索引里的住宅工作簿只作**结构参考**，见「六」 |
| ③ 方案 | `crwu_valuation_project_prepare` | 分组冲突 / 价值范围重叠 / 土地能力缺失都在这里变成阻断；本工具**不做业务判断** |
| ③ 调度 | `crwu_valuation_execution_dispatch` / `_join` | 按真实 Agent 状态决定有界并行或父会话顺序；单执行租约防止重复执行与超时后重算 |
| ④ 取数 | `crwu_valuation_market_search` / `_market_capture`（**都要带 `planId`**）+ `requiredCapabilities`（方法正文声明的能力 ID） | **取数之前**逐项核对真实注册表/适配器；缺席就地阻断，不"先试试看"；通道**按来源**独立（挑战预算不共用）；`city` 提交**业务城市**（`北京`），站点标识由适配器解析；来源顺序与降级策略以入口 Wiki 为准 |
| ④ 恢复 | `crwu_valuation_browser_recover` | 只在员工完成验证后**继续同一任务**；不接受 URL / 策略 / 脚本，也不重置自动预算 |
| ⑤ 测算 | `crwu_run_python_script`（`calculate_market.py` 等） | 业务阈值**必须**显式传入；脚本没有默认值 |
| ⑥ 报告 | `build_report_data.py --input --out`、`build_report.py --data --out` | 落在 `方案/<planId>/` 下；HTML 只由受约束的报告数据渲染，数字不另誊 |
| ⑦ 完成 | `crwu_valuation_finalize`（带 `planId`） | 只读 `方案/<planId>/` 下的交付件；缺项降级并列出问题；**没有落盘的重算记录时上限就是 `partial`** |

## 二之一、资料提取：逐页事实、能力声明与缺口

扫描件（页面图像、没有文本层）**不能**用一句"PDF 无文本层，需要 OCR"结案：会话看不出哪几页读到了、
本部署又是否真能把页面转成图像。提取结果里因此有三类事实，用之前先分清它们：

| 事实 | 在哪 | 谁负责 |
| --- | --- | --- |
| 逐页文本层 | `提取结果/提取-<文件名>.json` 的 `pages[]`（`index` 从 1 起 / `hasTextLayer` / `chars` = 去空白字数）、`pageCount`、`pagesWithText`、`pagesWithoutText` | 脚本如实记录；**只有 `hasTextLayer: true` 的页才有正文可引用** |
| 本部署能力 | 同文件的 `capabilities`：`pdfText`（有没有 PDF 文本库）/ `pdfRender`（有没有页面渲染器）/ `imageOcr`（有没有可用 OCR 引擎）/ `visionFallback`（本次有没有导出可看的页面图像） | 脚本**当场探**（import + PATH），不是写死的声明；`capabilityProbe` 记录探到了什么 |
| 缺口与人工动作 | `提取汇总.json` 与工具回执的 `capabilityGaps` | 无文本层页合成**一条**：`第 3–5 页无文本层：…，请人工核对这几页的坐落/面积/权属` |

会话必须自己做的三件事（能力不到就没有替代品）：

1. **无文本层的页留空**：那些页的坐落 / 面积 / 权属只能来自人工核对或页面图像判读，
   不许从同目录别的资料、文件名或"通常如此"补值；缺就登记 `missingFields` /
   `manual_confirmation_items`，按缺失的两类处置（资料字段缺失 vs 关键参数缺失）。
2. **按缺口的页码找人工**：缺口里的页码区间就是要补的页；不要说"整份报告读不了"，
   也不要把"这几页读不到"写成"资料缺失"。
3. **页面图像只算线索，不算事实**：`visionFallback: session-images` 时可以把导出的内嵌页面图像
   （`提取结果/提取-<文件名>-页面图片/`，`description` 带 `<文件名>#第<N>页图片#<M>` 定位符）
   当**图像证据**判读；判读结论要标明来自哪一页图像，且**内容未识别**这一状态在核对前一直有效。
   `visionFallback: none` 就是**本部署拿不到页面图像**（既无渲染器、又取不到内嵌图），
   此时没有任何"再试一次"的退路，只能请人工补关键页。

`pdfText: false` 表示**连文本库都没有**：这种情况下逐页事实也无法产生（`pages` 为空），
缺口会直说"逐页文本层事实也无法产生" —— 这不是"这份 PDF 没有问题"，而是"这次没核"。

## 三、知识读取：入口 Wiki + 逐步读取

**唯一业务入口在 [knowledge-routing.md](knowledge-routing.md) 声明一次**（入口路径、库内相对链接契约、
读取证据、缺失处置都在那一份里）。入口节点与正文的实际读取只经结构化工具
`crwu_valuation_knowledge_materialize`；在线 `dws` 调用就在该 Host 工具内部完成，会话**不需要**
自己开浏览器下载、申请额外权限或走 shell。

工具的真实入参（其余都不存在）：

| 入参 | 用途 |
| --- | --- |
| `caseDir` | 本轮估值案例目录（必填，Host 校验归属） |
| `wikiPaths` | **主通道**：入口 Wiki 或上一轮 `links[].target` 解析出的库内相对路径（逐字传入） |
| `planId` | 方案 id（分组阶段可省） |
| `stage` | 可选，**当前只接受 `parameters`**：在已验真的已落盘正文上解析结构化规则段 |
| `routeIds` | **遗留通道**：manifest 槽位；省略且没给 `wikiPaths` 时只回报槽位，不下载正文 |
| `spaceName` | 业务知识库精确名称；缺省即配置值，不接受改道 |

下一步读哪一份由**入口正文的库内相对链接**决定（`entries[].links[]`）。实时实读（2026-10-16）：
入口节点的真实扩展名是 `.adoc`，而导出 markdown 里的相对链接写的是 `.md` —— 不能从链接后缀
反推节点类型，也不能按编号或本地文件名推导目标（按编号猜会让成本法读到"案例选取"且不报错）。

### 读取顺序（概念，不是工具参数）

| 顺序 | 读什么 | 时机 |
| --- | --- | --- |
| 通用口径 | 入口 Wiki 指向的通用 / 输入口径正文 | 开始就取；**缺它则停止**（没有通用口径的数字无法核对） |
| 方法选择 | 方法选择方案 | 判方法之前 |
| 方法正文 | 对应方法说明 | 采用该方法时 |
| 案例选取 | 案例选取与可比性规则 | 整理候选案例之前 |
| 参数与税费 | 参数与税费口径 | 落参数与税率之前 |
| 模板说明 | 模板的填写说明（二进制模板走 `crwu_valuation_template_materialize`） | 填表之前 |

四级尝试并**留痕**（`attempts[]`）：精确路径 → 同目录同名（空格 / 连字符变体）→ 显式别名 →
**身份已验证**的镜像（逐字节指纹 + 库身份都要对）。镜像身份或指纹不符 → 拒绝，**不降格使用**。
镜像默认不启用，只有部署配置了 `mirrorRoot` 时才作为恢复档出现。

## 三之一、候选评估、身份与列表快照

- **完整候选池**：按列表页累计，不只看列表首页或排序靠前的几条；候选台账按项目 / 方案 / 分组 / 轮次。
- **列表快照复用**：成功的列表页落快照，同一请求不再重复导航；快照损坏或身份不符时**人工修复**，
  不静默重取。
- **评估后才能采用**：`assessments`（`url` / `status=qualified|near-miss|excluded` / `reason` /
  `knowledgeRef`）是采用的唯一入口；没有评估即 `unreviewed`，不自动采用。
- **near-miss 不算合格候选**：只有知识合格且事实合格的记录才计入合格预算；相近案例（near-miss）
  单独保留、单独说明，不顶替合格案例。
- **身份只认 canonical URL**：小区 + 面积 + 价格这类弱事实只能标"疑似重复"，**不得自动合并**；
  同一对象的所有来源记录都保留、编号稳定。
- **挂牌信息保持挂牌口径**：挂牌价按挂牌价原样记录；把它转成可比参考价是**单独的人工 / 显式**步骤，
  只允许知识正文有依据的换算假设，绝不把它当成直接成交自动套用。

## 四、对象、方案与方法

1. 先识别对象（房号 / 用途 / 面积 / 权证），再按**同一口径**分组为方案，最后才判方法 ——
   顺序反过来会让"方法"先入为主地决定分组。
2. **业务不适用**与**当前未实现**分开记：前者是知识正文的判定，后者是能力缺口。
3. 用户指定方法是**约束**：结论不同必须写 `methodConflict` 并进待确认事项，**不许静默切换**。
4. 房地分别评估见 [execution-and-land-extension.md](execution-and-land-extension.md)：
   价值范围互斥（重叠即重复计价），土地能力不存在时该方案 `blocked`。

## 五、取数、详情证据与人机验证

- 检索 / 详情 / 截图都是**可调用的结构化能力**，会话不猜选择器、不反复试错；
- 同一 `browser profile` 的操作**严格串行**（同一条队列）；
- **详情取证**：`crwu_valuation_market_capture` 接收**已选定的稳定 `caseId`**，保存回读到的
  **实际详情 URL** 与不可变 PNG，并把条目写进 `推理结果/图片/图片清单.json`
  （`crwu.valuation.screenshot-manifest.v1`，按 `planId` 隔离；写入后回读核对字节）。
  页面被重定向到另一条房源、或有可见拦截时**不截图、不关联**，只记缺口；
- **列表页图片只作页面证据**：每成功列表页一张**页面级截图**，供该页每条引用；每条记录带两条定位
  说明 —— `页面截图对应列表页 <列表页 URL>` 与 `本行定位：标题「<标题>」链接 <详情 URL>`。
  它只证明当时列表页长什么样，**不是**某个案例的详情证据；
- **案例证据落到交付件**：`values.caseEvidence` 生成可见的 `案例证据` 表
  （`caseId / 显示名称 / 来源 / 详情 URL / 图片相对路径 / 指纹 / 抓取时间 / 证据类型`），
  详情 URL 用完整 URL + native 超链接，图片用**相对路径**；HTML 报告用本地图片链接展示；
- 可见人机验证：先由适配的**固定脚本**尝试（同一任务 ≤2 次自动尝试 / ≤120 秒总窗口，
  冷却与预算由程序管理），**不许模型循环 sleep 或重试**；
- 脚本退出码 0 **不等于**恢复成功：必须核对原房源、有效业务字段、无可见拦截，再重新抓正式截图；
- 未恢复 → 保存 waiting-user 断点：员工完成验证后用**同一任务**继续（不重建会话、不重传资料）；
- **挑战页截图永远不是案例证据**；截图落在 `推理结果/图片/<caseId-名称>/`，缺图如实写
  `screenshot_missing`。

## 六、计算、模板与交付

- 所有计算由脚本执行；业务阈值与参数**只来自本轮知识快照**（脚本无默认值，缺参数报缺口）；
- **模板现状（2026-10-16 实读）**：模板索引里的住宅工作簿当前只作**结构参考**，待修复与重算验收，
  **不能据此自动计价**；收益法 / 成本法没有单独验收过的模板。该限制要进 `manual_confirmation_items[]`
  与报告 `limitations[]`，不得声称自动算价就绪；
- **通用工作簿 checker 没有随包七表 profile**：只认工作簿自己的描述文件；没有描述文件就直接拒绝。
  旧七表清单已移出活动文件并作为历史存档保留，不是当前默认契约；
- 主交付件两份：**完整过程与结果的 HTML** + **计算工作簿**；
- **挂牌参考模式**是另一条**一次性**交付：走 `crwu_valuation_listing_reference`
  （固定输入、一次打包脚本、四件产物），状态只可能是 `partial`，不得当成交价或修正后的可比价。
  边界与产物见 [09-output-contract.md](09-output-contract.md) 的「挂牌参考交付」；
- 截图按案例归档，HTML 展示、Excel 记录**相对路径**；
- 底稿数字的权威性高于报告：不一致时以**重算后的底稿**为准并修报告，而不是改底稿凑报告。

## 七、完成判定

`crwu_valuation_finalize` 由 **Host** 用真实文件判定，逐项核对：冻结输入摘要（**重算**后比对）、
知识快照、模板验真、逐对象结论、计算轨迹、截图证据、计算表登记、**重算记录**、报告渲染、产物清单。

- 缺项 → 降级（`completed` → `partial` / `blocked`）并**列出逐条问题**；
- 没有落盘的重算记录 → 上限 `partial`；本机没有 Excel / LibreOffice 时如实标记，**不许**声称正式完成；
- 完成与"页面是否还开着"无关：面板不轮询，也不以页面存活为判据。

## 八、当前尚未落地的部分（诚实清单）

| 未落地 | 影响 | 现状 |
| --- | --- | --- |
| 土地估值能力 | 土地方案无法测算 | 明确阻断该方案（见 execution-and-land-extension.md），**不创建假能力** |
| 工作簿重算 | 报告上限 `partial` | 取决于本机是否有 Excel / LibreOffice；有则落 `重算结论.json` |
| 模板可用性 | 住宅工作簿只作结构参考 | 待修复与重算验收，**不能自动计价**；收益法 / 成本法无单独验收模板 |
| 非住宅 / 非市场法 | 商业、收益法、成本法方案当前无法测算 | 方法是否适用以入口 Wiki 的实时正文为准；当前缺**已验收模板 / 数值自动执行**能力，受影响的计算 `blocked`，**不改用市场法凑** |
| 数值规则自动执行 | 只能解析围栏 JSON 规则段 | `stage=parameters` 目前只认 JSON 段；普通表格 / 行文缺该段记为**适配器契约缺口**，不是知识不存在，普通阅读照常 |
| 来源适配器 | 业务库来源策略可能点名 58 等 | 当前 Provider 注册表只有 `fang` / `anjuke` / `lianjia`；未实现来源如实记缺口，不改业务来源优先级 |
| 真实站点在线验收 | 链家的真实抓取与截图尚未真机验证 | 离线 fixture 已覆盖解析与挑战恢复接线；上线前需员工授权环境验收一次 |
| Windows 运行时 | 未验证 | macOS 已实测；Windows 运行与截图未验证；Safari / Firefox 不能用 CDP 驱动 |
| 后台窗口可见性 | 不是"完全不可见" | 自有窗口为**正常态、不主动抢焦点**；macOS 实测最小化会让 `Page.captureScreenshot` 超时，故不用最小化；不承诺操作系统层面完全无窗口 / 启动 UI |
