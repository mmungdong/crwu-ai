# 08 · 业务知识路由与降级口径

本技能的知识**不写死在技能目录里**：正文来自「中瑞世联业务知识库」的实时取数，技能自带的
`references/` 只是**降级备份**。这一份说明路由、来源与"缺了怎么办"。

## 库内路由（逐字）

```text
中瑞世联业务知识库/估值与测算/房地产/
├── 01-房地产估值通用
├── 02-市场法
├── 03-收益法
├── 04-成本法
├── 05-案例选取
├── 06-参数与税费
└── 07-计算表模板
```

⚠️ **本地文件名与库内编号不一致，这是刻意的**：本地按写作顺序编号，库内按业务路由编号。
成本法在库里是 `04`、本地却是 `07-cost-method.md`。永远按
[SKILL.md](../SKILL.md) 的知识索引表逐字映射，**不要**按编号推导，也不要把本地文件名当库内节点名 ——
按编号猜会让成本法读到「案例选取」的正文，而且不会有任何报错。

## 取数与来源标注

插件通过结构化工具 `crwu_valuation_knowledge_materialize` 取正文，顺序固定：

```text
知识库有该节点且有正文 → source = dws（权威）
否则读技能自带 references → source = local（降级）
两者都没有 → 该路由记为 missing，进入 capability_gaps
```

每条来源都要写进 `估值结果.json` 的 `knowledge_sources`：

```json
{ "route": "估值与测算/房地产/02-市场法", "source": "dws", "updatedAt": "…", "digest": "sha256:…" }
```

- `source` **必须**是 `dws` 或 `local`：把本地备份说成"知识库正文"，等于把技能发布时刻
  冒充规范修订时刻；
- `updatedAt` 只在来源端真的给出时间时才有值，**不许**用本地文件 mtime 顶替；
- `digest` 是正文指纹，用于事后核对"当时读的是哪一版"。

## 缺了怎么办（硬口径）

| 情况 | 处理 |
| --- | --- |
| `01-房地产估值通用` 两边都缺 | **停止估值**。没有通用口径的结果无法核对，不许"先算个数" |
| 其它单份路由两边都缺 | 继续能算的部分，并把缺哪一份、什么时候需要它写进 `capability_gaps[]` |
| 知识库读取失败（不可达 / 权限 / 命令失败） | 记 `capability_gaps[]`（**与"没有这个节点"区分开**），再走本地备份 |
| 节点存在但导出为空正文 | 按"没有"处理，退到本地备份 —— 空上下文会让结论变成"按规范编的" |
| 任何来源不明确 | 结果里**不许**写"已按规范完成"；如实说清建立在哪一版正文上 |

## 与审核知识库的区别

审核链路的默认库是「中瑞世联评估审核知识库」，业务知识在「中瑞世联业务知识库」下 ——
**不是同一个库**。取数工具、库名与路由都不共用。
