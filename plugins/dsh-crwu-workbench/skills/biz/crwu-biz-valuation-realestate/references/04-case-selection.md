# 04 案例选取

- **来源**：力鸿花园投资性房地产公允价值测算底稿「案例」表与「J统一价值内涵、及税费正常负担的测算」
  的案例登记字段；《房地产估价规范》GB/T 50291 可比实例选取要求。
- **适用范围**：市场法可比案例的登记、来源记录、可比性判断与保留/剔除留痕；收益法租金案例同表登记。
- **更新时间**：2026-10-12。

## 1. 来源要求

- 每个案例必须有**可回溯的来源**：链接（可打开）、来源类型（挂牌平台 / 中介询价 / 成交备案 /
  实地调查 / 委托方提供）、取得日期、取得人。
- 链接必须写**完整 URL**，不能只写"链家""贝壳"。链接失效时保留记录并标注"已失效 + 失效日期"，
  同时记录当时的截图或打印留档位置。
- 每个案例必须有**截图或证据留档**：挂牌页 / 成交页 / 询价记录的截图（或打印件扫描），与 URL 一并登记；
  只有 URL 没有截图的，注明"仅链接、未截图"并说明原因。
- **询价记录必须可复核**：写明询价对象（中介门店 / 业主）、询价时间、口头还是书面、
  价格是报价还是可成交价。
- 平台挂牌价一律标记为"报价"，后续必须做交易情况修正（见 `02-市场法` 第 4 节）。
- 委托方或项目组内部提供的价格，须注明原始出处，不得作为独立来源反复引用形成"互相印证"的假象。

### 1.1 中介联系方式（公开信息，五态如实登记）

只登记页面**合法公开展示**的业务联系人、机构及联系方式，落到 `contact` 字段，
`state` 取下列五值之一（**拿不到也必须写清楚是哪一种拿不到**）：

| state | 含义 | 必填 |
| --- | --- | --- |
| `public` | 已公开获取 | `agency` 或 `person` 至少一个 + `captured_at` |
| `not-published` | 页面未公开 | —— |
| `masked` | 页面本身就是脱敏展示 | `phone`（**原样保留**，如 `138****1234`） |
| `login-required` | 需要登录才能看到 | `detail`（一句人话原因） |
| `failed` | 获取失败 | `detail`（一句人话原因） |

四条边界：

1. **脱敏号码原样保留**，不得猜测补全成完整号码 —— 那是编造证据（校验脚本会把带 `*` 的号码
   标成 `public` 判为不合格）；
2. **没有联系方式不自动排除案例**，除非知识库明确要求；
3. **不得自动联系、拨号或发送消息**：这一条只是登记公开信息；
4. `public` 的取值要写清**页面上的位置**（`source`，如「经纪人卡片」），便于复核。

## 2. 登记字段（标准计算表「案例」区）

**基本信息**

| 字段 | 说明 |
| --- | --- |
| 序号 | 全局唯一，不得重复 |
| 实例名称 / 房号 | 与估价对象可对应的描述 |
| 案例来源 | 来源类型 + 取得方式 |
| 案例链接（URL） | 完整 URL；无链接的写清留档位置 |
| 案例截图 / 证据留档 | 挂牌页/成交页/询价记录截图的文件名或留档路径，供来源复核 |
| 取得日期 / 取得人 | 可追溯 |
| 房屋坐落 | 具体到小区与楼栋 |
| 房屋用途 | 居住 / 商业 / 办公 / 工业 |
| 所在楼层 / 总楼层 | 如"低区/24 层"，含采光遮挡说明 |
| 结构 | 钢混 / 砖混 / 全钢等 |
| 建成年代 | 年份 |
| 装修状况 | 分公共区域与室内装修，分别登记 |
| 配套设施 | 电梯、安防、车位、燃气、暖气等 |

**价格与交易**

| 字段 | 说明 |
| --- | --- |
| 交易价格（万元） | 原始价格，不预做修正 |
| 价格内涵 | 必须写明：按建筑面积/套内、卖方净得价/含税成交价、是否挂牌价 |
| 面积内涵 | 建筑面积 / 套内建筑面积（㎡） |
| 交易时间 | 成交或挂牌日期，精确到月 |
| 交易情况 | 正常 / 异常（异常须注明命中场景） |
| 税费负担 | 各税种由谁负担；享受何种税收优惠（满五唯一、满二唯一、满二不唯一、无优惠等） |
| 交易单价（元/㎡） | 由价格与面积计算，口径与价格内涵一致 |

**区位与实物**（描述 + 分档）

按 `02-市场法` 第 6、7 节的区位状况与实物状况因素逐项登记**文字描述**与**档次**。
只填档次不填描述，或只填描述不填档次，都不合格。

**判断与留痕**

| 字段 | 说明 |
| --- | --- |
| 可比性判断 | 相似 / 部分相似 / 不相似 + 理由 |
| 保留 / 剔除 | 明确结论 |
| 保留或剔除理由 | 必须可独立复核，不得写"不合适"三个字 |
| 待确认事项 | 来源不可核、口径不明、面积存疑等 |

## 3. 可比性判断

可比实例须同时满足三项基本条件：

1. **用途相同、结构相近**：住宅对住宅，商业对商业；结构差异大到无法修正的（如砖混对全钢）
   不进入打分；
2. **同一供需圈**：同一区域、同一类需求人群；跨区案例须说明替代关系是否成立；
3. **成交日期接近基准日**：一般不超过一年；超过一年的必须做日期修正并说明指数口径。

逐项判断并记录：

| 判断项 | 相似 | 需修正 | 不相似 |
| --- | --- | --- | --- |
| 用途 | 一致 | 用途相近可修正 | 用途不同 |
| 结构 / 类型 | 同类 | 档次差异（板楼/塔楼） | 无法修正 |
| 供需圈 | 同小区/同片区 | 邻片区有替代性 | 跨区域 |
| 成交日期 | 3 个月内 | 一年内 | 超过一年无指数 |
| 交易情况 | 正常交易 | 报价、非正常交易 | 无法还原到正常交易 |
| 面积 | 同面积段 | 跨面积段（做面积修正） | 面积差异过大 |
| 权利状况 | 无租约无抵押 | 有租约可量化 | 权利状况不明 |

## 4. 保留与剔除

**保留**：满足三项基本条件，且可修正到同一价值内涵的案例。

**剔除**（必须写明理由，并在清单中保留记录）：

- 来源不可核、链接失效且无留档；
- 价格内涵无法还原（不知是否含税、不知是否卖方净得价、不知计价面积）；
- 交易情况异常且无法量化修正（如亲属间交易、抵债、法拍）；
- 面积差异过大导致面积修正已超出合理幅度；
- 与其他案例明显离群，且无法用可解释因素说明（修正后比值检查触发，见 `02-市场法` 第 9 节）；
- 用途或结构不相容，不可修正。

**剔除不能等于删除**：被剔除案例留在清单中并标注剔除结论与理由，供复核追溯。
底稿里"只剩 3 个案例、看不到剔除痕迹"是不可复核的。

## 5. 案例数量不足时

扩大调查范围要**按顺序、留痕**，不允许一步跳到"把条件全放宽"：

1. 同小区 / 同楼盘；
2. 同片区（同一供需圈）同用途、面积段 ±20%；
3. 面积段放宽到 ±30%（并说明为什么可以放宽）；
4. 成交时间放宽（一般不超过一年，超过必须做日期修正并说明）。

每一轮扩展都要在 `notes` 里记：**这一轮放宽了哪个条件、为什么**。
"硬条件"（用途相同、结构相近、交易正常或可修正到正常交易）**任何一轮都不许放宽** ——
放宽这些等于换了一个可比对象，那不是"补搜"，是改变结论依据。

- 候选案例不足 3 个：按上面的顺序扩展后仍不足的，按实际可核案例测算，
  并在待确认事项中写明数量不足及其对结论可靠性的影响；
- 只有 1–2 个案例：可行，但必须说明可靠性与处置方式，不得直接当"充分可比"结论呈现
  （宿主侧完成门槛也会因此不推 `completed`，见 `09-output-contract.md`）；
- 一个都不可核：登记能力缺口与待确认事项，**不得**伪造案例或用成本法顶替。

### 5.1 跨站去重（同一套房源只算一条）

链家与贝壳是同一平台的两次展示；同一套房源也可能同时出现在房天下与链家。检索工具
（`crwu_valuation_market_search`）会按「小区 + 建筑面积 + 价格档」做**跨站去重**，
只留先出现的那一条，并在留下那条的 `notes` 里写"与 <来源> 的同一房源重复"，
应答里给出 `dedupedAway`。

- **去重不等于删过程**：合并了什么要看得出来（`notes` + `dedupedAway`）；
- **拿不到面积或价格的候选不参与合并**：靠"小区相同"合并会把同小区的不同房源误判成一套 ——
  比重复更危险（案例凭空少了一条）；
- 自己再补一手时也要按同一条口径去重：**不能**把同一套房在两个站点各记一条来凑够 3 个案例。

## 6. 常见错误

- 链接写平台首页或"链家"二字，无法复查；
- 只登记一个总价，不登记价格内涵与税费负担，导致后续无法统一口径；
- 挂牌价未标注为报价，被当成成交价直接进入打分；
- 剔除案例不留痕，或理由写成"不合适"；
- 案例房号与估价对象不在同一供需圈却未说明替代关系；
- 多个案例实际来自同一次询价，被当作独立来源互相印证。
