# 执行调度、价值范围与土地扩展（协议 35）

本文件说明三件容易出错的事：**任务怎么调度**、**价值范围为什么必须互斥**、
以及**土地能力还没实现时应当怎么处理**。

## 一、任务图：房地分别评估是一张有依赖的图

一个方案里的工作是若干 `TaskNode`，节点之间有依赖（`dependsOn`）：

```text
取值（知识 + 资料） → 案例与参数 → 逐对象测算 → 汇总 → 报告与底稿 → 重算 → finalize
```

- 依赖**不满足**的节点不许开跑（`readyTaskIds` 只给出前置已完成的那些）；
- 图**不许有环**（有环即配置错误，直接报出来，不是"跑跑看"）；
- 每个节点归属明确的 `valueScope`，且**只能属于一个方案**（`taskGraphOwnsObjects`）。

## 二、价值范围互斥：重叠就是重复计价

| `valueScope` | 含义 |
| --- | --- |
| `land-only` | 只评土地 |
| `building-only` | 只评建筑物 |
| `land-and-building` | 房地合一 |

**三条互斥规则**（`validateValueScopes`）：

1. 同一项目里 `land-only` 与 `land-and-building` **不许同时出现**；
2. `building-only` 与 `land-and-building` **不许同时出现**；
3. `land-only` 与 `building-only` 可以同时出现（这正是"房地分别评估"）。

第 1、2 条不是格式要求，而是**重复计价**的入口：同一块土地价值被算进两个方案，
而两个方案各自的单价看起来都合理 —— 汇总时没有任何地方会报错。汇总口径也据此固定：
`land-only + building-only` 可以相加；任何与 `land-and-building` 并列的组合都不许相加。

## 三、调度：有界并行 vs 父会话顺序

调度决策由 `decideExecution` 给出，依据是**真实的 Agent 状态**，不是"配置里写了并发就并发"：

| 情况 | 决策 |
| --- | --- |
| Agent 状态**未知**、查询失败、或信息不足 | **顺序执行**（父会话里一个个来） |
| 达不到起跑条件（SLA 内起不来 / 没有额度 / 已有同方案执行占用） | **顺序执行** |
| 条件都成立 | 有界并行，上限 `DEFAULT_MAX_CONCURRENCY = 2` |

两个数字的**性质**要说清：

- `DEFAULT_MAX_CONCURRENCY` 是**安全上限**，不是"性能目标"：它限制同时开几个执行体，
  调大它不会让估值更准；
- `DEFAULT_START_SLA_MS`（10s）是**技术起跑窗口**，不是"CPU 要跑多快"。

### 两个执行工具

调度不是"想一想"，而是两个结构化 Tool（Host 侧真的记账）：

| 工具 | 回答什么 | 关键约束 |
| --- | --- | --- |
| `crwu_valuation_execution_dispatch` | 这一轮由谁执行哪些任务 | 只调度 `项目估值方案索引.json` 里的任务；**真的**把执行者写进租约；启动结果未知的任务留在 `start-unknown`，**父会话不许接手** |
| `crwu_valuation_execution_join` | 这些任务静止了没有 | 子会话仍在跑就不结算；父会话没有给出结论就不算做完；顺序计算开始前先等本项目活动子任务静止 |

顺序模式**同样要走 `dispatch`**：否则模型重试一次调度就会把同一个方案排两遍。
子会话只有在两件事都成立后才会被采用：provider 声明支持 `toolFilter`（事实层），
且**创建后回读**它的工具可见性齐备（`VALUATION_CHILD_TOOLS`）。回读不过就停掉它并留在未知状态。

### 单执行体租约

每次执行占用一份**租约**，状态机固定：

```text
acquire → （markStartUnknown）→ bindChild → settle → release
```

- `start-unknown`：已经发出启动动作但**还没拿到子执行体身份**。这个状态**不许被接管**
  （接管会让同一份工作跑两遍，而两遍的结论可能不同）；
- **只有已 `settle` 的租约可以被释放**：提前释放等于把"还在跑的工作"放给下一次调度；
- 驱逐只对已 settle 的租约做。

## 四、土地能力尚未实现时怎么办（当前状态）

**现状**：本技能**不提供**土地估值能力（候选技能 `crwu-biz-valuation-land` 未实现）。

处理方式固定为：

1. 识别出需要单独评土地时，生成土地方案与对应任务节点（**契约先留好**），
   但 `LAND_EXECUTION_CAPABILITY.available === false`；
2. **阻断该方案**：`blocked` + 说明缺什么（缺哪个能力、哪份知识、需要谁补），
   并把原因写进报告与待确认事项；
3. **不创建假能力**：不许用建筑物方法凑一个"土地价"，不许把土地价值并进建筑物单价；
4. **不重复计价**：土地方案被阻断时，`land-and-building` 方案照常算（它是完整的房地价值），
   但**不许**再把任何金额"补"给土地方案，也不许在汇总里对土地方案记 0 当成已算。

`BUILDING_ONLY_CAPABILITY.available === false` 同理：**只评建筑物**（剥离土地）也不是本技能
能给出的结论 —— 它需要土地价值作为减项，没有土地口径就得阻断，而不是"按建筑面积估一个"。

## 五、以后接入土地技能时要满足什么

新技能上线时，本技能这一侧需要的是：

| 需要 | 为什么 |
| --- | --- |
| 明确的 `routeId` → 土地方案的通用 / 方法 / 参数 / 模板知识 | 与本文第一、二节同一套分阶段读取口径 |
| 土地方案的 `valueScope = land-only` | 互斥规则据此判断能否与 `building-only` 相加 |
| 土地结论的**计价口径**（面积 / 单价 / 内涵） | 汇总时才能与建筑物结论相加而不重复 |
| 独立的模板与重算记录 | 两个方案的工作簿各自重算、各自留痕 |

在它齐备之前，唯一正确的行为是**阻断**。
