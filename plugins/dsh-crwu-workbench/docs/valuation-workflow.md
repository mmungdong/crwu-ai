# 估值工作流（当前实现）

> 本文描述**当前已接线**的估值工作流行为，是现行说明，不是计划、设计草案或验收报告。
> 历史计划与设计快照见 [`docs/superpowers/`](../../../docs/superpowers/) 下对应日期的文件；
> 它们只作历史证据，正文保持原样。开发与踩坑视角见 [`development-notes.md`](development-notes.md)，
> 界面与样式口径见 [`ui-design-guidelines.md`](ui-design-guidelines.md)。

**诚实边界（先读）**

- 当前来源预检每渠道只检查一页，首条满足数字与取证校验的挂牌用于预检；业务库原模板在随后取回并保留，
  还没有用其完整案例字段驱动采集。后续受控挂牌参考表和原始单价平均值不能证明原模板的市场法比较修正已完成。
- 取到页面但无法识别结构时登记解析缺口，不能据此断言社区没有房源；明确空结果与选择器失效分别登记。
  规划缺口保留实际取数回执中的能力说明、对应来源的恢复动作和页面任务身份。
- 首版只交付**挂牌参考**口径。它给出参考单价 / 总价、算法、来源与底稿，**不等于正式评估结论**，
  页面也不把挂牌参考显示成"正式成果已完成"。
- 明确不支持的正式方法（收益法 / 成本法等）在**执行之前**就被识别并如实登记为能力缺口，
  不靠"界面里有一个选项"暗示已经具备。
- 真实桌面端到端验收（真实产权证、真实知识库正文、真实来源、真实计算与模板、业务金额与底稿）
  **仍待进行**；当前证据来自受控夹具、Host 工作流测试与聚焦的 Client 测试，以及在 macOS 上
  **实际观察到的原生 PDF 8 页资料准备**。资料准备可被观察到，不等于业务链路已被验收。
- Windows 未实测；仅记录了 macOS 上的实际验证范围。

## 1. 业务路径

```text
业务总览 → 估值输入（资料 / 对象 / 方法 / 可选模板与基准日）
        → Host 按真实知识准备的方案
        → 员工按精确「修订号 + 摘要」明确确认
        → 实际采集 → 程序计算 → 复核 → 交付
```

- **业务总览**只列真实业务步骤；当前只有「估值」一项，其余步骤未定义就不画。
- 输入页是通用估值入口：递归选择资料，并**明确选择资产类别与评估方法**（当前资产类别只有房地产，
  方法只有市场法 / 收益法 / 成本法；没有 `auto`，也不替员工默认一个选择），可选填基准日与补充要求；
  模板是**可选角色**，通过原生选择器给出本机 `.xlsx`。
- 只有资料、资产类别与方法都通过校验，「核对资料」才可用；未选基准日照样能算，
  报告里写明「本次未指定评估基准日」。

**意图路由先于专业节点**

- 本批资料 / 文本进入后先跑**意图路由子会话**，此时还没有读取任何专业知识、也没有启动任何专业节点；
  路由只依据已提交的正文与资料原文，不依据文件名。
- 识别出**多个候选估值对象**时，本轮不替员工挑一个：运行停在一个**可回答的澄清**上，问题逐条列出
  真实的 `objectId`，并保留本次识别的完整对象与证据（以及真实意图子会话 id）。
- 员工选定唯一对象后，**问题与回答一起**交给一个**全新的意图子会话**重新识别；资料、正文与冻结快照
  沿用，不重新读取、也不新建案例。识别为单一对象并通过校验后，才进入已注册的专业阶段。
- 路由停在阻塞 / 失败时，具体原因（例如"识别到多个对象，需要先选定唯一对象"）会作为**缺口**显示在
  工作面与路由器节点上；页面不把未知停止状态说成已停止，也不用相关键顶替真实子会话 id。

**入口选择快照（initialInput）**

- 确认入口时把员工**第一次提交的完整选择**固化为不可变快照：原始 userInput、资产类别、评估方法、
  目的、基准日、价值类型、模板标识、补充要求、输入摘要，以及全部冻结资料的身份
  （`fileId` / 文件名 / 归档相对路径 / 摘要）。未知的可选项保持 `null`，不会自动补一个值。
- 全部 7 个专业节点与知识 / 规划选择器都会拿到该快照的**独立克隆**，与当前已确认事实、员工回答和
  修订记录（`revision.changes`）并列展示；当前更正永远不写回原始快照，节点也不能通过自己的请求改写它。
- 重启 / 冷恢复后原样保留快照；**旧版本导出的运行没有这个字段时如实恢复为 `null`**，
  不用后来更正的当前状态伪造历史选择。

**资料取值与确认恢复**

- 对已选定的唯一对象，先从 PDF 等已提交材料读取用途和建筑面积；相同用途重复出现不构成缺失。
  建筑面积支持数字后的平方米单位及字段表头的 `m²` / `平方米`，与套内、土地面积保持区分。
  引文必须能按材料身份、摘要和实际字符位置核对完整标签及取值；多个无标签数字不代选、单位不补默认值。
- 只有缺失、冲突或仍无法核对的事实才进入确认。有效回答完成原来等待的要素回执，并清除已解决的缺口；
  其他未核来源继续阻断。回答记录为用户确认，原模型候选保留作核查记录，不冒充已核实的材料事实。
- 回答及问题进入当前输入，原始 `initialInput` 不变。更正回答生成新的提交标识，相同回答重试仍去重。
  同一修订号下任务状态变化时，所选节点详情也重新读取，避免继续展示旧错误。

**知识导航引用**

- 来源选择的引文必须逐字包含指向所选路径的完整 Markdown 链接，只有链接后的说明文字不能授权读取。
  Host 从同一份已验真入口正文中提供实际导航原文，选择器按当前阶段、用户指定方法和对象选择。
- 如果入口版本、路径、角色和原文均有效，仅引文没有包含对应导航链接，允许一次带具体验证反馈的纠正。
  再次选择仍须通过全部校验，失败结果不缓存，未通过前不读取目标正文。错误入口版本、库外路径、
  伪造原文、读取失败或业务未决问题不触发这种纠正；不会静默替换模型引用或跳过失败条目。

**规划依据的来源身份**

规划选择器会收到与校验器一致的来源清单：`user-input` 对应本轮实际用户输入；材料标识对应正文，
`<材料标识>:file-name` 对应文件名且仅可证明社区线索；知识标识对应已验真知识正文。
城市不能由文件名证明，渠道与模板等业务决策须由知识或用户输入支撑。渠道能力清单和模型输出不是知识来源。
没有有据的周边社区时可保留空列表，不单为补齐该列表提问；模板适用性、计算能力和真实来源缺口仍按实际情况处理。

## 2. 真实图与节点

### 节点问题、答案与草稿（协议 47）

- 节点模型一次返回当前已知的全部员工可回答问题，包含稳定标识、字段、题型、必填标记、选项、语义版本和提问原因。
  单选、多选、判断、文本、数值、日期按题型展示；必答项全部有效后统一提交。“无法确认”必须说明原因，回答保存后仍须核验，不能自动通过。
- 当前任务的 SQLite JSON 同时保存问题定义、已提交答案、草稿、补充说明和历次提交。已回答的问题持续回显并可更正，
  下一轮携带所有仍适用的最新答案；每轮历史保留当时的题干和选项。草稿不进入模型的生效输入。
- 输入自动保存草稿，切出页面时立即尝试保存；保存失败保留本地输入并显示错误。刷新或关闭前尚未保存时提示确认。
  页面显示“草稿已保存”、提交排队和正式答案保存结果，模型故障不会撤销已经持久化的答案。
- 执行期间可以编辑、保存草稿，结束或确认停止后才能正式提交。不同页面发生版本冲突时保留本地更正，展示已提交答案，
  由员工核对最新问题后显式重新保存，不自动覆盖。
- 类型、选项或语义版本变化要求重新确认；明确不再适用的问题保留原问答与原因，但不进入当前有效答案。
  更正影响的下游结果失效并保留历史，材料值和用户值保留各自来源，冲突不会静默取值。
- 旧补充按原节点与修订保存；有确切字段契约的旧确认答案可回填，无法恢复题型的原文只展示为历史补充。
  系统、权限、网络和工具故障展示真实原因，不编造员工问题。已经回答却仍未解决的问题说明原因并停止自动重复推进。
- 节点详情优先展示问答与处理结果，“本次输入”和“本次输出”默认分别折叠，需要时展开。
  折叠时不创建内部结构化回执，展开后才渲染；关闭后卸载内容。切换节点或修订时恢复折叠。
  流程状态轮询不等待详情读取；同一节点的后台详情请求未完成时复用该请求，避免反复取消和重启。

### 节点受阻与失败（协议 48）

- 所有受阻或失败的专业节点及意图节点都展示具体原因、未满足要求和下一步处理。模型可返回完整 `failure`：
  `kind`（业务或系统）、`reason`、非空 `requirements` 和 `actions`；空原因、仅写“受阻 / 失败”、缺少要求或恢复动作均不能作为有效失败说明。
- 每次隔离推理的提示包含本次实际 JSON Schema。Host 仍独立校验；缺结构化对象、字段类型错误和子会话异常结束分别报告，
  不回显被拒绝的内容、未知字段名或原始基础设施诊断。失败保留真实子会话身份，已有问答不会被撤销。
- 原生结构化工具返回非选择题的 `options: []` 时，入口将其正规化为未提供选项；非选择题的非空选项、选择题缺失 / 空选项、
  非法题型和其他不合规字段仍被拒绝，避免两层校验把完整有效问题一并丢弃。
- 业务问题按题型集中回答；系统或输出契约故障优先展示恢复要求和显式重新执行入口，草稿仍可保存，不能冒充答题提交。
  没有问题、也没有新补充时不能提交空表单。旧回执缺少失败明细时明确说明历史未记录，不编造缺失字段或业务问题。
  本次没有引入自动循环重试；原任务的已保存输入、答案和上游结果继续用于显式重试。

### 图投影

图在 Host 侧编译，页面只是它的只读投影：

- 根图：`src/host/graph/graph.ts`；业务图与专业图注册表：`src/host/graph/valuation/`；
  房地产专业子图：`src/host/graph/valuation/realestate/`。
- 实际节点按原生 id 暴露，例如 `__start__`、`valuation:intent-router`、
  `valuation:realestate:elements`、`valuation:realestate:plan`、`valuation:realestate:calculation`、
  `valuation:realestate:delivery`、`__end__`，边由编译器给出（顺序边或条件边）。
- Client 渲染的就是这些 **实际 id 与实际边**：`data-workflow-node` 带原生 id，连接器带
  `data-workflow-edge-from/to`。页面**不**另画一套固定阶段，也不虚构业务节点。
- 只有待执行（`pending`）节点禁用，其余状态（包括受阻、等待处理、部分完成与已取消）都可以点击查看详情；准备资料期间整张图只读。
  任务仍运行、节点均为已通过或待执行且还有未开始的业务节点时，显示「下一个节点初始化中…」与 loading 图标。
  待执行节点不因此被标记为运行中，等待员工处理或任务停止时也不显示该初始化提示。
- 每个节点都可以查看本次输入 / 输出、采用的知识引用与原文摘录、本次已读资料、缺口、
  依赖影响与真实会话 id。路由器节点展示真实路由与证据；哨兵节点只表示流程起止。

**结构化输入输出与来源，而不是"思考过程"**

- 节点回执是结构化字段：字段值、来源种类（材料 / 已确认输入 / 模型判断 / 程序 / 用户）、
  来源说明与可核对的引用。页面不展示隐藏推理，也不编造推理链。
- `confirmed` 表示**已确认的上游输入**（例如已确认的方法或补充要求），不是知识库引用；
  采用的知识仍然是单独的、带原文引用的列表。
- 原始回执可以通过节点详情里的「完整记录」展开检查；页面不隐藏字段，也不补字段。

## 3. 方案与确认

- Host 按真实知识库准备方案，方案里给出：方法 / 模式、逐条来源（社区、详情 URL、
  实际数字字段与失败原因）、计算表文件与字段映射 / 公式试算、采用依据与限制。
- 来源按登记顺序探测，单一来源失败只影响该来源；**不**因为一个来源失败就声称"全网都没有"。
- 只有**经过校验**的模板按钮才可打开，并按**受控类型**打开（`template`），
  客户端不提交文件名或案例路径。
- 确认必须绑定**页面上显示的那一份方案**：`{expectedRevision, planDigest}` 原样提交；
  如果 Host 已经推进到更新的方案 / 修订，Host 侧拒绝这次陈旧确认，不会静默确认未显示的新方案。
- 计算表打开、来源 URL 打开等动作都走封闭取值；未知交付件名不转发，
  按 basename 映射到封闭类型（`workbook` / `report` / `trace` / `data`），未知项直接省略。

## 4. 修订与重新执行

- 员工只能修改 Host 标为可编辑的字段；程序金额字段不可直接改写。
- 提交修订必须带**修订理由、依据来源、本次基于的修订号与变更列表**；节点已过期时拒绝提交。
- 修订会创建一个**新的、有界的子会话尝试**，并让受影响的依赖节点失效；
  页面展示依赖影响，但不改写历史记录，也不把旧结果说成新结果。
- 澄清问题按 `question.field` 提供真实可编辑字段；已知的封闭取值（例如模式）用真实选项呈现，
  不是让员工猜一个英文 id。答案要带澄清身份与修订号提交。

## 5. 持久化与恢复

- 每个**工作空间 + 业务步骤**只保存一份当前任务，落在
  `<已选工作区>/.crwu/workflows.sqlite`（Host 派生路径；`.crwu` 或 `workflows.sqlite`
  若是解析到工作区之外的符号链接会被拒绝）。
- 数据库保存图状态、当前步骤、修订、检查点与**真实会话 / 文件索引**；
  它是执行状态，不是聊天镜像。原始资料、模板与成果仍在项目目录里，不进数据库。
- 入口选择快照随当前状态一起持久化，但**只读**：澄清回答、字段修订与重新计算只更新当前值，
  不回写快照；导入 / 导出与冷恢复都保留同一份快照。
- 重新进入页面时**被动展示**已保存状态并重新核对真实会话与已产出文件；
  只有明确的动作（确认方案、回答、提交修订）才推进执行，页面加载本身不重跑未知动作。
- 页面已移除「重新对接」及 JSON 导入 / 导出入口；保留刷新、取消任务、清空与打开估值会话。
  准备失败时通过估值会话查看实际错误和处理情况。
- Host 的显式恢复能力只对**停在意图路由、尚未进入任何专业阶段**的运行发起一次有界重试：
  状态为 `blocked` / `failed`、错误不是"停止状态未知"、路由为空、7 个专业阶段全部 `pending` 且
  `attempt = 0`、没有结果 / 交付 / 已确认方案。重试沿用**同一父会话、同一项目与已缓存的资料正文**，
  不重新读取 PDF、不新建案例，只启动一个新的意图子会话；单一对象路由通过后，已注册的专业阶段才会继续。
- 任何**未知停止状态**仍然保持阻塞：页面加载与 Host 的恢复操作都不会替它猜结论，也不会释放占用。
- Host 保留显式导出 / 加载契约：导出为 JSON 快照并校验格式、工作空间 / 步骤 / 图版本 / 运行标识 /
  修订号一致；它**不内嵌原始资料字节**（资料仍在项目目录里），输入上限 16Mi 字符。
  加载与导出必须来自同一工作空间与同一步骤。
- 清空需要页面二次确认，并明确提示会永久删除该任务在 SQLite 中的草稿、问题、答案和历史。
  Host 确认执行已停止并复核任务身份后，删除整条当前任务记录与检查点，不保留问答归档。
  其他任务与**已有成果文件独立保留**。

## 6. 会话与工作区

- 父会话与各节点子会话都建在【环境信息】选定的工作空间里；落地参数只有一个
  `workspaceId`，建完回读会话 cwd 与工作区归并。
- 没有无头业务分支：页面与父会话都不在别的目录里偷偷跑业务。
- 停止语义是保守的：运行中的任务可以取消；但"活动中的未知停止状态"目前**无法自动证明**，
  因此保持阻塞，由 Host 恢复能力重新核对，而不是猜一个结论。

| --- | --- |
| `src/host/graph/` | 根图、状态与定义；`valuation/` 是业务图、意图契约与专业图注册表；`valuation/realestate/` 是房地产专业编译子图。**不**导入 DSH、文件系统或 provider。 |
| `src/host/domains/report-evaluation/workflow/` | 纯领域：`ports.ts` 能力接口、`service.ts` 运行 / 版本 / 互斥 / 等待 / 修订、`plan.ts` 方案、`persistence.ts`、`views.ts`。不拥有图拓扑。 |
| `src/host/domains/report-evaluation/assets/realestate/` | 专业要素核对与挂牌参考口径（纯逻辑）。 |
| `src/host/domains/report-evaluation/knowledge/` | 知识定位、适用条件与引用绑定（纯决策 + 注入探针）。 |
| `src/host/integrations/valuation-workflow/host.ts` | 外层装配与操作入口：装载运行时、解析工作区存储、把操作 / 生命周期 / handoff 接起来；`production/` 里的辅助模块各自聚焦（会话、规划、计算、证据、模板、视图）。 |
| `src/host/operations/report-evaluation.ts` | 面板操作表装配：合并输入 / 交接 / 恢复操作，并在装配了工作流 Host 时并入 `valuation-workflow-*`（启动 / 状态 / 回答 / 修订 / 取消 / 导入导出 / 清空 / 重新对接）操作。 |
| `src/host/tools/report-evaluation/workflow.ts` | 已登记估值会话的命名业务接口；与面板复用同一实例。 |
| `src/host/core/workflow-store/` | SQLite 检查点存储、校验与导入导出。 |
| `src/client/modules/report-evaluation/ui/workflow/` | 图 / 方案 / 澄清 / 节点详情组件（纯展示）。 |
| `src/client/modules/report-evaluation/ui/AssetAssessmentWorkflow.tsx` | 挂载点：把工作流控制器接到图工作面、输入页与工具栏。 |
| `src/client/modules/report-evaluation/workflow-controller.ts` | 页面控制器：被动读取、过期响应防护、轮询与提交门禁。 |
| `src/shared/contracts/valuation-workflow.ts` | 跨进程可序列化合同（图、进度、方案、节点回执、澄清）。 |

边界：Graph / 领域 / Client **不**导入 provider；provider 能力由 `src/host/integrations/valuation-workflow/`
的外层适配器注入。样式留在所属模块的 `styles/`，共享 UI 控件不重画。

### 能力与 API 备注

- **原生 PDF 页面渲染**是可选注入能力：内置提取器读不出 PDF 页面时可渲染真实页面图再做视觉判读，
  只补齐图片与真实页数，**不**把渲染结果冒充成 PDF 原有文本层；能力缺失时按缺口如实登记，不伪造正文。
  该能力在 macOS 上实际观察到 8 页 PDF 的资料准备过程（业务端到端仍未验收，见"诚实边界"）。
- **意图重试**是 `service.retryIntent` 的显式、有界入口（页面不再提供该操作按钮）：只接受停在意图路由的
  停止运行，沿用缓存的已准备输入启动一次新的意图识别；单一对象路由通过后，已注册的专业阶段才会继续。
  它不重新读取资料、不新建案例，也不处理未知停止状态。

## 8. 当前限制

- 只支持挂牌参考首版；正式方法在识别后如实登记为未支持，不假装完成。
- 模板与来源的"预检保证"在**真实探测成功之前**不成立：没有真实探测证据时只显示未验证 / 缺口。
- 活动中的未知停止状态无法自动证明，保持阻塞（见第 6 节）。
- 原生 PDF 页面渲染只补齐图片与真实页数，不重建 PDF 原有文本层；业务金额 / 底稿的端到端验收仍未完成。
- Windows 未实测；真实桌面端到端验收待进行。本页不声称已经交付真实金额或通过实机验收。
