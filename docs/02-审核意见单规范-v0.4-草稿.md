## 2. 意见条目 schema（每条强制字段）

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| issue_id | `{模块}-{序号}` | 如 `RPT-企业价值-009`、`DC-001` |
| 模块 | M-法律法规合规 / M-数据校对 / M-收益法 / … | 归因到模块 |
| 位置 | {文件, 章节, 定位} | 可复核定位（段落/表/单元格） |
| 分区 | 报告正文 / 评估说明 / 测算明细表 / 审核意见流 | 按材料分区定位（校准 G5，与机构一/二/三级意见分区分组一致） |
| 严重程度 | 高 / 中 / 低 | 按影响使用程度 |
| 意见类型 | 规则性缺陷 / 合理性存疑 / 无依据待判 | 分级置信（防幻觉第三道） |
| 问题描述 | 客观陈述 | 不含推断补全 |
| 依据 | [{kb_id, 出处, 原文片段}] | **规则性缺陷必须有**；无依据则类型必须为后两者 |
| 修改建议 | 文本 | 可执行建议 |
| 置信度 | 高(基于原文) / 中 / 低 | |
| 答复/流转状态 | 待答复 / 已答复 / 已复核 | 人工三级审核"问题-答复"流转用（校准 G5，机构口径） |
| 自检记录 | {引用完备, 空库触发, 分级正确} | 调度器自检放行标记 |
| 复核对照 | {分类: A/B/C, 复核出处: {文件,定位,原文摘录}\|null, 说明}（阶段二必附） | **阶段二（AI 意见定稿后）**对照产出，不参与阶段一判断；复核材料缺失/不可读 → 全部为 C（未对照）；格式见 §5.3 |

## 4. 适用规则集快照（随每次输出必附）

```json
{
  "项目画像": {"对象类型": "...", "方法": ["..."], "场景": "...", "环节": "..."},
  "命中规则数": N,
  "规则kb_id列表": ["RULE-01-03-001", "..."],
  "已装载模块": ["M-画像与调度", "..."],
  "未装载原因": {"M-成本法": "画像未命中成本法"}

```

> 用途：人工复核发现漏报时先查快照归因（画像解析错 / 标签没命中 / 规则缺失），见方案 §4.7；
> 快照另含装配键与未装载/排除原因留痕（§6.4），复核独有（§5.5 L 条带）漏检归因也先查本块。

## 5. 复核对照与综合对比（意见单必附块；2026-09-07 增对照、2026-09-09 阶段化 + 综合对比）

> 目的：让"AI 审了什么、发现什么、与人工复核意见的关系"对使用者一目了然——已在人工复核意见中
> 提出过的问题必须能回溯到**复核意见的具体出处**；AI 发现而复核意见未提出的必须单列，不能混在一起；
> 最后给出 AI 与复核的**综合对比**（相互印证 / AI 新增 / 复核独有＝AI 未命中），支撑 AI 自检与防漏检。

### 5.1 输入、适用与时序门禁（阶段一 独立审核 / 阶段二 对照）

**时序门禁（先于一切，v0.4 定稿）**：AI 审核是"先独立审、后对照"的两阶段流程；复核对照/综合对比
**不得反过来指导 AI 审核**——复核记录是审核完成后的**对照材料**，不是审核输入。

| 阶段 | 内容 | 允许读取 | 禁止 |
| --- | --- | --- | --- |
| 阶段一 · 独立审核 | 路由→叶子按规则/清单独立审核，产出《意见列表》并**定稿** | 源材料（报告/评估说明/测算明细表）＋规则/清单（经 crwu-dws 实时下载） | 复核记录：**不下载、不读取、不参考**，不据其出意见/改口径/补结论；氚云字段/附件清单含复核记录 → 只登记存在（文件/份数/状态），不读正文 |
| 阶段二 · 对照与综合对比 | AI 意见定稿后：单独下载/读取复核记录 → 检索建立"复核事项全集" → 逐条对照分类（5.2）→ 输出《复核意见对照表》（5.3）与《复核综合对比表》（5.5） | 复核记录（附件/字段）＋阶段一已定稿意见 | 改写在先定稿的 AI 意见以匹配复核；把复核记录内容倒推补成 AI 意见（漏检应走补审：独立出意见后再对照，见 5.5） |

- **对照材料**：阶段二单独下载/读取的人工复核意见（一级/二级/三级审核意见、质控意见、G15-4 等表格、
  在线底稿意见、外审意见）及其答复文件（若有）；无对照材料不影响阶段一主流程，但必须输出"未对照"
  声明（见 5.3 小结 / 5.4 红线 2）。
- **对照对象**：阶段一定稿《意见列表》中每一条 issue（含规则性缺陷/合理性存疑/无依据待判）；
  反向比对对象：复核记录中真实读取到的每一条**复核事项**（复核事项全集，供 5.5 L 条带）。
- **为什么必须分阶段**：A（已在复核提出）只有对"独立检出"才有**相互印证**意义；B（AI 新增）只有
  在未参考复核记录时才是**真新增**；L（复核独有＝AI 未命中）是**漏检自检**输入——阶段一若参考了
  复核记录，三条带全部失真，统计与防漏检失去意义。

### 5.2 对照分类（每条 AI issue 取其一）

| 分类 | 判定 | 输出要求 |
| --- | --- | --- |
| A · 已在复核意见提出 | 复核记录中可定位到同位置/同主题/同数值的问题（AI 独立检出且复核亦提出＝相互印证） | 必须指出**出处**：复核意见文件名 + 条目编号/页码/段落号 + 原文摘录（一段即可） |
| B · 复核意见未提出（AI 新增发现） | 复核记录全文检索不到对应问题 | 单列并注明"建议提交人工复核补充" |
| C · 未对照 | 复核记录材料缺失 / 不可读 / 未提供 | 全部 issue 标"未对照"，禁止编造任何出处 |

> 边界：对照只回答"是否已提出、在哪提出"，**不评判人工复核意见本身对错/质量**；
> 复核记录中存在而本次 AI 意见未含的事项 → 属 5.5 L 条带（复核独有/漏检候选），**不得静默省略**。

### 5.3 输出格式

json 意见条目扩展（阶段二在定稿 json 上**追加**，不回溯改写）：

```jsonc
{
  "issue_id": "RPT-…-009",
  // …原 §2 字段不变…
  "复核对照": {
    "分类": "A | B | C",
    "复核出处": { "文件": "G15-4三级审核意见-…docx(第2页/条目1-2)", "定位": "…", "原文摘录": "…" },  // A 必填；B/C 为 null
    "说明": "已在复核意见提出 / 复核意见未提出，建议人工复核补充 / 未对照（原因）"
  }
}
```

md 意见单在"适用规则集快照"之后附《复核意见对照表》：

```markdown
## 复核意见对照（阶段二：AI 意见定稿后执行；审核范围：报告/评估说明/测算明细表 × <模块/调用链>；材料：<文件清单>）
| 问题ID | 分区/位置 | 问题摘要 | 分类 | 复核出处（文件+条目/页码+原文摘录） |
| --- | --- | --- | --- | --- |
| RPT-…-009 | 报告 §X | … | A · 已在复核意见提出 | G15-4（条目 1-2）："…" |
| DC-003 | 测算明细表 | … | B · 复核意见未提出（AI 新增） | —（建议人工复核补充） |
> 小结：本次 AI 发现 N 条，其中已在复核意见提出（相互印证）M 条（出处见上表），复核意见未提出
> （AI 新增）K 条，未对照 C 条；复核独有（AI 未命中）L 条见《复核综合对比表》（§5.5）。
> 复核材料缺失/不可读 → 本节仅保留："未对照：未提供可读复核意见材料，全部 issue 分类=C"。
```

### 5.4 红线（与文件级抽验红线一致）

1. 复核出处（文件/条目/页码/原文摘录）只能来自**真实读取**的复核记录文件（下载→转换→grep/定位），
   禁止凭印象、凭字段、凭经验拟造出处；
2. 复核记录材料缺失/不可读 → 整表标"未对照"，**不得以"复核意见未提出"替代**（B 类判定前提是已真实检索）；
3. 原文摘录须与复核记录文件逐字一致，转述须注明"转述"；存疑 → 明示待人工复核。
4. **独立审核门禁（v0.4 新增）**：AI《意见列表》必须在读取任何复核记录**之前**定稿（§5.1 阶段门禁）；
   任何环节不得把复核记录内容作为 AI 审核线索/先验/参考（含氚云字段、材料包附件、附件文件名）；
   违反 → 该批次意见失效，隔离后重审（先独立审，再重新对照）；
5. **禁止回改匹配（v0.4 新增）**：阶段二对照/综合对比只标注"是否已提出、在哪提出"，禁止为匹配复核
   而改写 AI 意见或增删 issue；确有漏检 → 走补审（独立出意见后再次对照），并在意见单记录"补审批次"；
6. **"复核独有（AI 未命中）"判定前提（v0.4 新增）**：已真实全文检索复核记录（同红线 2）；材料缺失/
   不可读 → 标"未对照"，**不得以"复核未提/无漏检"替代**。

### 5.5 综合对比（双向 · 意见单必附块；2026-09-09 新增）

- **目的**：把 AI 独立检出与人工复核记录放进一张表做**双向**对比，回答三个问题——
  ① 哪些两边都有（AI 独立检出且复核已提＝**相互印证**，对应 5.2 A）；
  ② 哪些只有 AI 有（复核未提＝**AI 新增**，对应 5.2 B，建议人工复核补充）；
  ③ 哪些只有复核有（复核已提而本次 AI 未命中＝**复核独有/漏检候选**，驱动 AI 自检与补审）。
- **输入**：阶段二已分类的《意见列表》（5.2）＋ 复核记录中真实读取建立的**复核事项全集**
  （每条含 文件 + 条目/页码 + 主题/摘要；含答复文件中未撤回的事项）。
- **对齐规则**：一条复核事项至多对应一条 AI issue、反之亦然（按位置/主题/数值对齐）；
  一对多/多对一 → 按主要对应计 1 条并在备注说明。

## 6. 清单逐条裁定表与校准点反查（族级强制产物 · 全叶子适用；2026-09-07 定稿）

### 6.1 逐条裁定表（强制产物）

## 7. 本次审核记录清单（检查痕迹 · 意见单必附块；2026-09-09 增）

> 目的：把"AI 到底查了什么、每项查到什么文件内证据、哪些没查/查不了"完整记录，作为**防编造与防漏查**
> 的审计轨迹。与《适用规则集快照》（§4）、逐条裁定表（§6）、复核对照与综合对比（§5）配套——
> 前几块回答"装配了什么规则、出了什么意见"，本块回答"**检查覆盖面与证据**"：AI 在清单里逐项说明
> 检查了哪些项目，每条都能回溯到文件中的具体依据，人工复核核漏查、核编造先查本块。

### 7.1 适用与汇总方式
- 由各执行模块（路由画像、叶子技能、datacheck、监管覆盖层、校准/回测反查）在检查时**逐项留痕上报**，
  crwu-audit 在汇总输出阶段（步骤 10）去重合并为《本次审核记录清单》；阶段二的复核对照/综合对比行
  （§5.3/§5.5）于步骤 11/12 并入本清单；
- 逐条裁定表（§6）、datacheck 差异清单（C1–C6）等既有产物**逐行引用进本清单**（记录ID 直引），
  不重复展开正文；
- 无对照/复核材料、无监管覆盖命中、无风险案例等"空"情形**必须显式写"未涉及/不适用+原因"**，
  禁止空手省略。

### 7.2 必含域与逐条字段

每条记录字段（强制）：`记录ID（{检查域}-{序号}）｜检查项｜检查对象（文件+定位）｜检查内容｜
证据（原文摘录一段/数值/坐标）｜结论（符合/差异/未检查/不适用）｜备注`。

| 域 | 含义 | 必含内容 |
| --- | --- | --- |
| AI 检查项 | 本次执行的检查点/模块（对应 §6 裁定表行、datacheck C1–C6、方法/参数/披露核对等） | 凡执行必留"对象+证据+结论"，未命中缺陷的也留痕（同 §6.1）；路由/画像判定链含 字段+文件证据 |
| 知识库业务/资产必检项 | 画像命中的业务主线/资产类型/校准点对应的**必检项** | 来源（库内 `01-业务路线/`、`02-资产类型/` 等层级路径或校准点 B_x）+ 映射 CHK + 执行结果（直引 §6 裁定行） |
| 评估数据核查 | 报告/评估说明/测算明细表中**实际核对过的数据** | 表名 + 坐标（单元格/行/页），核对类型（合计/口径/公式/单位/小数/跨表一致/参数取值与来源等），核对到的值与结果（直引 datacheck 差异清单行） |
| 监管覆盖核查 | 命中的监管覆盖层（国资/证券/司法/金融）**实际核对的披露要求/条款** | 覆盖层、核对了哪份文件的哪些要求/条款、结论；未命中覆盖层 → "不适用（画像未命中）" |
| 风险覆盖核查 | 是否涉及知识库风险案例 | 涉及 → 写清**涉及库内哪个风险案例**（库内层级路径 + 案例ID/名称 + 要点）及关联检查点与结论（附依据）；未涉及 → 显式"未涉及风险案例覆盖" |

### 7.3 依据纪律（红线，与 §5.4/抽验红线一致）

1. 每条"检查过"必须带**真实读取的文件证据**（本次下载 KB 文件:行号 + exportedAt；源材料
   文件:行号/坐标/条目/页码），禁止凭印象、凭字段、凭经验写"已检查/已核对"；
2. **所有对比/判定（报告↔测算表、AI 意见↔复核记录、校准点映射、风险案例关联、口径一致性等）必须
   两端各给出文件内具体依据**（出处 + 原文摘录/数值），只写结论而无出处 = 编造；
3. 未检查/不可读 → 显式列入"未检查项（原因）"；不适用（画像未命中/清单外）→ 写"不适用+原因"，
   禁止空手省略；
4. 出处原文须与文件逐字一致，转述注明"转述"；存疑 → 明示待人工复核。

> 仅作内部结构化/留档/复核用途。

### 8.1 生成与命名
- 由同批 `审核意见.<项目ID>.md` + `.json` 在**阶段二收口**（复核对照/综合对比/记录清单全部并入后）
  渲染生成；一次审核一个 html；
- 文件名 `审核意见.<项目ID>.html`（含报告版本时可加 `<报告版本>` 后缀）；
- 页面须含"导出时间 ＋ 导出方（审核引擎+版本）＋ 数据源文件清单（含 exportedAt）"页脚，保证可追溯；
- 渲染只做"呈现"：内容 = md/json 意见单的**全量**渲染，不得在渲染时新增/删减/改写任何意见、依据、
  对照结论或记录行（改数据走定稿/补审流程后重新渲染）。

### 8.2 内容范围（与意见单全量一致，禁止只给部分）
- **头部**：项目ID / 画像摘要 / 报告版本 / 审核时间 / 阶段声明（阶段一未参考复核记录）；
- **三区意见**：规则性缺陷／合理性存疑／无依据待判，逐条 issue 卡片，字段与 §2 一致——位置/分区/
  严重程度（高红·中橙·低黄）/意见类型/问题描述/依据（三段式引用逐条列出 kb_id＋出处＋原文摘录）/
  修改建议/置信度/答复·流转状态/复核对照（A/B/C ＋ 出处或"未对照"说明）；
- **附块**：《适用规则集快照》《复核意见对照表》《复核综合对比表》《本次审核记录清单》《未检查项》；
- 空库静默/"未对照/未涉及/不适用"提示必须显式可见，禁止空白省略；
- 所有依据与对比以可读引用呈现（文件:行号/坐标/条目 ＋ 原文摘录或数值）；纯静态版用尾注/脚注承载
  出处，**禁止只写结论、不出处**（同 §7.3）。

### 8.3 样式与工程规范（自包含 ＋ 可打印）
- **自包含单文件**：CSS 内嵌，不依赖外链资源/在线字体（避免内网或离线打开失效）；不内嵌任何凭据；
- **A4 可打印**：`@media print` 控制分页，issue 卡片不跨页截断；打印页眉含项目ID、页脚含生成信息；
- 严重度色标与"待答复/已答复/已复核"状态徽标随内容渲染；长表（对照/综合对比/记录清单）可用折叠区；
- HTML 内**不含**本地文件系统路径、nodeId、凭据、隐藏数据内容（同隐藏数据隔离红线）。

### 8.4 边界与纪律
- 送达前按机构口径执行必要脱敏（第三方客户/无关人员信息等，保留可追溯标识）；
- 页面注明性质与边界："AI 辅助审核结果，供人工三级复核与员工答复流转；‘合理性存疑/无依据待判’类
  须人工确认后方可作为结论依据"；
- 员工答复/流转以系统（氚云记录、答复文件）为准，html 内流转状态仅为呈现口径；状态回填后需重新
  渲染或随批次归档。
