# 节点展示与推进性能排查

历史快照：2026-10-20。范围为现有工作流的页面刷新、节点回执渲染与串行执行链路；未操作活动 profile，未调用真实员工材料或在线模型。本记录不能证明真实模型耗时或总体加速比例。

## 已复现并修复

1. **详情读取拖住流程刷新。** 原控制器在读取当前状态后等待所选节点详情，再启动下一次 4 秒轮询计时。慢详情会叠加到流程状态延迟上。用延迟详情、100ms 虚拟轮询的测试复现：到 200ms 时状态读取停在 2 次。修复后至少 3 次，未完成的详情请求仍只有一条。手动刷新仍等待详情完成；后台轮询不积压等待详情的调用。
2. **折叠仅隐藏内容，没有避免渲染。** 原详情在两个关闭的 `details` 内仍创建完整 `StructuredValue` 树。300 条合成输入、300 条合成输出的测试复现默认生成内容；修复后默认不创建字段，展开对应区域后才渲染，关闭后卸载，其他区域保持折叠。切换节点或修订重置展开状态。合成渲染替身中的一次测量约从 6ms 降到 0.28ms；这不是浏览器帧率或整个业务链路的加速测量。

回归入口：`plugins/dsh-crwu-workbench/tests/unit/client/client-workflow-performance.test.mjs`。真实浏览器另外验证深浅主题和三种宽度下的展开、关闭、重新展开与完整内容。

## 后续优化优先级

| 优先级 | 发现与证据 | 建议与约束 |
| --- | --- | --- |
| 高 | 生产知识端口 `stageAware=true`，知识选择缓存键包含节点；每个节点在业务推理前等待知识选择模型。七个专业节点完整执行时，这两部分可形成 14 次串行模型调用，另有意图路由、规划、读图等操作。 | 评估一次产生各节点知识计划、按输入与知识版本失效的方案，减少重复选择；必须保留每个节点不同的角色要求与来源核验，不能直接去掉缓存键中的节点。当前正文已有缓存，重复下载不是此处已证明的问题。 |
| 高 | `stageFacts` 同时提供 `questionnaire` 和完全克隆的 `currentQuestionnaire`；用户输入还含累计答案。适配器将全部事实直接序列化进模型提示词。 | 先量化真实任务各部分字符数和模型输入 token，再在模型边界只传一份生效问答；保留独立历史、初始输入与当前更正的含义。 |
| 中 | `current` 返回完整 snapshot 和 progress；两者含问卷、方案与修订历史。`node` 又返回 progress 和 graph。修订历史含旧节点回执，长任务会放大复制与传输。 | 引入轻量状态与版本标记，详情按需读取，未变化时不传完整历史；避免用过期缓存回答正式提交或跨任务读取。需要明确更新跨进程合同。 |
| 中 | 当前基础轮询间隔仍为 4 秒。即使上述阻塞已移除，服务器完成到页面发现仍有轮询等待。 | 先减少状态负载，再考虑事件通知或运行时缩短轮询；不直接把重型全量请求频率翻倍或翻四倍。 |
| 待实测 | 小型领域夹具的七节点路径产生 25 次持久化写入。此夹具未接生产 checkpointer；不能用其数量推断真实磁盘占比。 | 分别计时知识选择、模型、清理、工具和保存；仅在证明磁盘占比高时合并重复快照，不跳过节点开始、答案提交和结果采用前的持久化边界。 |
