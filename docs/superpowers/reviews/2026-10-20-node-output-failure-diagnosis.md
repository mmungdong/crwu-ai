# 节点输出被拒绝诊断与修复

历史快照：2026-10-20。本次修复继续执行已确认的持久问答设计，并补足“所有受阻或失败节点必须说明具体原因和要求”。当前操作说明见[估值工作流](../../../plugins/dsh-crwu-workbench/docs/valuation-workflow.md)。

## 实际根因

只读检查当前任务 SQLite 与相应的原生子会话后，确认失败的方案子代理正常完成，并成功调用 `structured_output`。
输入含基本要素、权属两个已通过节点的上游结果、已提交答案和补充、材料与知识引用；本次没有发现上下文传递中断的证据。

返回包含单选和文本两道完整业务问题。文本题的 `options: []` 符合原生 Schema，Host 的附加校验却禁止非选择题出现任何 `options`，
因此把整份结果拒绝。原代码又把未完成、缺失结果及校验失败压成同一句提示；失败时没有保留实际子会话到节点回执，页面无法直接核查。

## 修复

- 在模型入口只将非选择题的空选项正规化为缺省；不接受非空的多余选项，不放宽其他字段、题型、版本或选择题校验。
- 节点支持严格的失败说明结构，包含具体原因、未满足要求和恢复动作。程序故障与业务问题分别处理，所有失败详情都有解释。
- 每次提示附本次实际 Schema；缺少结构化对象、字段不合规和异常结束分别报告，拒绝内容和原始基础设施诊断不回显。
- 失败仍保存真实会话身份；系统故障页面提供显式重试，不能用空表单冒充回答。问题整理同时收到故障和问题时，系统故障优先且保留恢复要求。
- 协议升至 48，兼容读取项目记录 43–47；不清空当前任务，不改已保存答案，不自动重试或重启 profile。

## 验证边界

真实返回仅做离线只读重放：修复后两道问题均可采用并进入持久问卷。合成的原生返回经过实际 inference adapter、应用服务和 DTO 恢复后进入等待回答状态。
原始缺陷、空失败原因、系统故障被问题覆盖等回归均先观察失败再验证修复；专项覆盖推理、服务、投影、意图和客户端。

隔离浏览器检查验证具体失败原因与要求、问答记录保留、显式重试和无答题提交误导。没有对真实任务发起模型重跑；仅 macOS 验证。
完整门禁的既有五项模板需求能力失败仍属未完成能力，不能把本次修复描述成整个估值链路均已验收。
