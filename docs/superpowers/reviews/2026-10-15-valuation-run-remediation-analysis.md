# 再次估值运行的 P1–P18 解决方法分析

> 历史分析快照，日期：2026-10-15。对应用户提供的 `估值-20261014-212456-4888`、`plan-001-apartment` 问题清单。基于 HEAD `4c12b85` 和当前未提交源码。本轮分析解决方法，未修改业务源码、运行环境或知识库。

## 结论

这些问题有明确的处理路径。应先修工具回执、证据落盘和会话恢复，再接通现有知识与真实页面搜索，最后补齐业务条件。验证码需要支持人工完成后的可靠续跑，不必以实现自动解题作为解锁前提。

在案源为零、必需知识不可用的情况下不产金额是合理处理。当前产品的缺陷是：把文件命名或读取范围问题当成没有知识，取数失败后无法可靠恢复，并在重启后丢失项目归属。

原清单是本次运行的事实摘要。本轮没有原始产权 PDF、原始页面、代理配置和实际 DSH 运行回执，因此不会将所有环境归因都视为独立验证过。已通过源码和离线调用验证的新问题见后文。

## 原清单的四处关键修正

### P8 不是补一个字段就能修好

本轮调用当前 Tool，再使用仓库安装的 `@deepseek-ai/dsh-tools` 原生 `validateJsonSchemaValue` 验证，实际得到：

```text
value.dedupedAway：未声明字段
value.cases[0].evidence_missing：未声明字段
value.cases[0].screenshot：未声明字段
value.cases[0].screenshot_digest：未声明字段
value.cases[0].screenshot_captured_at：未声明字段
value.cases[0].screenshot_missing：未声明字段
```

另外，搜索结果本身没有 `retrievalTaskId`。因此修复应同时包含输出契约和恢复信息接线，不能仅加入 `dedupedAway`。恢复任务应以项目、方案、来源、页面任务绑定，避免相同关键词跨项目共用预算。

代码位置：[market-search.ts](../../../plugins/dsh-crwu-workbench/src/host/tools/report-evaluation/market-search.ts) 第 153～180、266～330、590～606 行。

### P2/P3 的 empty 不能等同于业务库没有规则

模拟指定路由下 `住宅/规则.md` 有非空正文，当前 `resolveRoute` 仍返回 `empty`。这是 [resolve.ts](../../../plugins/dsh-crwu-workbench/src/host/domains/report-evaluation/knowledge/resolve.ts) 第 115～128 行只收直接子文档的结果。

上一轮本地知识库对照也确认，`02 市场法.md` 已有案例渠道、选取标准、税费、日期修正和数值约束章节。应先解决发现、路由及章节引用，再判断哪些内容确实需要补。**不能把“补三个目录正文”当作唯一解法，也不能把方法文档未经业务确认自动当成通用规范。**

### P1 的文本解析库不能代替 OCR

扫描 PDF 只有页面图像时，安装 pypdf 等文本库仍无法读出图像中的文字。需要渲染加 OCR/视觉识别，并复核关键字段。pypdf 官方文档明确区分这两类能力。[pypdf 文本提取说明](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)

代码 [extract_files.py](../../../plugins/dsh-crwu-workbench/skills/biz/crwu-biz-valuation-realestate/scripts/extract_files.py) 当前只尝试文本库；[python.ts](../../../plugins/dsh-crwu-workbench/src/host/core/runtime/python.ts) 的必需包预检主要覆盖 openpyxl。这不能证明 DSH 的 PDF 渲染和 OCR 已经就绪。Codex 本机拥有某个库，也不能替代 DSH 托管运行时的能力验证。

### P13 的网络和登录结论需要拆开

Mihomo 官方文档说明 fake-IP 模式及其映射、过滤配置，因此 fake-IP 地址本身可以是代理正常工作方式，不能直接当作网站把员工判为异常的证据。[Mihomo DNS 配置](https://wiki.metacubex.one/config/dns/)

关代理仍出现验证页，能支持“切换网络没有消除挑战”；不能单独证明是哪一个 IP、账号或设备信号触发。当前旧预检工具的 `needsLogin` 又将所有非 authenticated 状态包括 unknown 纳入，故“四站 needsLogin”也不一定等于“四站都证实没登录”。需要用员工会话的权威 status 结论与页面验证结果分别说明。

代码位置：[login-probe.ts](../../../plugins/dsh-crwu-workbench/src/host/domains/report-evaluation/browser/login-probe.ts) 第 86 行、[browser-preflight.ts](../../../plugins/dsh-crwu-workbench/src/host/tools/report-evaluation/browser-preflight.ts) 第 181 行。

## 推荐解锁顺序

1. **先固定本轮业务前提**：基准日、目的、价值类型、公寓分类依据，及确实影响所选方法的缺失资料。保留已识别材料，不重新做一遍没有变化的读图。
2. **修工具基本链路**：P8 完整输出契约和任务回执，P9 受控目录创建；一起消除金额单位丢失、搜索提前完成、失败类别被抹掉等上一轮已复现问题。
3. **接通知识**：P4/P5 的真实路径和索引格式，P2/P3 的文档发现与章节引用，以及现有自然语言正文到结构化规则的受控转换。模板路径能命中不等于 JSON 索引和规则参数已经可用。
4. **实现可靠的链家流程**：按用户要求只校验链家。通过页面搜索发现 URL，城市由站点适配器确定；遇验证暂停并保存任务，员工完成后继续。先验收一条检索、详情、截图、恢复完整链路。
5. **补项目续跑能力**：P18 的持久化、校验、恢复。修复前实际启动的新一轮应避免运行中重启；修复后恢复相同项目不应再新建一套目录或重复派发任务。
6. **处理补充来源和正式交付**：再处理安居客、房天下及其网络问题；按知识选例、参数、计算、重算、勾稽、报告和 finalize 依赖顺序完成。

步骤 1～5 中，业务输入确认、代码修复和知识对照可以独立推进。完整出数依赖这些前提汇合，不能承诺仅登录一次或更换网络就一定可完成。

## 最小验收闭环

| 场景 | 通过标准 |
| --- | --- |
| 零案例/有案例/等待验证/业务失败 | 所有回执通过真实 DSH 输出 Schema 校验，失败也能返回可处理原因 |
| 新方案首次取页 | 无手工建目录步骤；页面、截图和诊断目录正确派生，写失败独立分类 |
| 实际知识树含空格名与子目录 | 正文唯一命中；有歧义如实返回；引用落到真实节点、章节和摘要 |
| 北京的链家搜索 | URL 来自页面搜索动作；结果上下文吻合；分页和详情沿实际链接 |

| 遇到不支持的验证 | 不套用 v3 自动解题，不循环抓取；任务保存并提供明确人工继续入口 |
| 人工完成验证 | 恢复原项目、原方案、原页面任务；核验房源身份，重新获取正式证据 |
| 插件重建/应用重启 | 经验证的项目可恢复归属和冻结输入；摘要不符或归属不符明确拒绝 |

| 计算与交付 | 总价、单价、面积勾稽；案例/知识/模板可追溯；实际重算与交付校验通过 |
