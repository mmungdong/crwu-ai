# 估值流程重构：通用入口、Skill 能力与 Wiki 业务导航

- 日期：2026-10-15
- 状态：待用户评审的设计快照，尚未实施；不作为现行操作指令。
- 范围：工作台估值模块、房地产 Skill、知识读取、案例获取、方法组合、计算及复算。
- 配套：[知识库补全与 Wiki 编写方案](2026-10-15-valuation-wiki-driven-knowledge-plan.md)。
- 设计依据：本轮访谈已确认的产品决策、当前工作树源码，以及用户提供的本地知识库内容。核查全过程忽略 `_manifest.json`。
- 本设计替代同日旧版“知识库侧固定 manifest 路由”的拟议方向；旧设计和计划保留为历史，不覆盖其正文。

## 1. 目标与成功条件

用户在一个通用估值页提交资料、资产类型、方法请求、评估条件及补充提示词。插件加载对应 Skill，Skill 声明可用能力与唯一 Wiki 入口。Agent 用 DWS 阅读 Wiki，按实际输入、资料事实和业务条件逐步决定后续阅读、数据获取、计算及结论形成。

已有执行能力覆盖的业务变化，例如补齐收益法正文及模板、调整案例条件、更换模板页签，维护知识库即可生效。新增网站适配器、文件格式解析器或计算引擎属于执行能力开发，仍需更新插件或 Skill 脚本。

成功条件：

1. 估值不再依赖房地产二级导航，也不因链家未登录阻止填写或启动。
2. 每个 Skill 对应一份业务入口 Wiki；没有第二份固定业务路由表或本地正文兜底副本。
3. 所有方法入口开放；自动模式能够采用单一方法或组合方法，实际可执行性依据读到的规则、资料和能力判断。
4. 每个平台每组样本最多翻 10 页、收集 20 条达标候选，合并去重后优选 3 条；上限不成为凑数目标。
5. 有依据但不足 3 条时仍形成结论并说明限制；无计算依据时与用户沟通。
6. 用户在会话中按候选编号追加案例，生成可追溯的新版本结果，旧版报告和底稿保留。
7. 报告数字、计算轨迹与真实重算结果一致；不能把模型写入的成功标记当作重算证据。

## 2. 责任边界

| 层 | 负责 | 唯一维护位置 |
| --- | --- | --- |
| 通用估值页 | 收集和确认用户输入、展示能力、交接会话 | Client 与共享输入合同 |
| Skill | 适用资产、Wiki 入口、可调用能力、技术说明及少量脚本 | 对应 Skill 自身目录 |
| Wiki | 业务步骤、条件分支、方法选择、样本规则、参数来源、模板和结论形成 | 知识库入口及所链接正文 |
| Agent | 读取、比对、解释判断、按能力执行、向用户提出明确待确认项 | 本轮估值会话 |
| Host 与工具 | 工具注册与权限、真实来源状态、读取和下载、预算、计算执行、来源及交付校验 | 独立的应用服务与外部适配器 |

CLI 与 MCP 继续作为传输层；知识与浏览器 provider 不互相依赖。DSH 是外层装配，业务服务不按 AI 宿主分支。

Skill 的“声明能力”说明已有工具如何服务本业务，不能凭文案注册一个不存在的工具。新增资产仍采用独立 Skill；沿用目录发现，不增设第二份全量 Skill 清单或全资产总 Skill。

## 3. 输入、页面与会话

### 3.1 通用页面

- “估值”直接打开通用页面，移除房地产二级导航。
- 资产类型放在共用输入区的下拉框，初始为空，由用户选择后才进入确认；当前可执行入口是房地产。
- 共用资料、评估目的、价值类型、基准日、补充提示词保留。切换资产类型不清空共用资料和输入；不兼容的专属条件需明确提示。
- 房地产方法选项为自动判断、市场法、收益法、成本法，全部开放。开放入口不代表缺正文、参数或模板时也能完成计算。
- 选择值使用稳定业务标识，显示文案不承担路由。房地产映射到 `crwu-biz-valuation-realestate`；房屋用途分类由资料与 Wiki 决定，不作为新的二级导航。

页面从上到下为资料区、共用条件与补充提示词、资产类型下拉及对应方法、能力区和确认操作。资产类型下拉保留“请选择”空态；房地产显示为选项，不继续占据顶部导航。

### 3.2 能力区与确认抽屉

- 页面下方提供能力区，包含链家登录状态、登录及适用时的验证操作。
- 进入估值页不自动探测网站。确认抽屉先显示用户输入和文件，能力状态独立更新，避免阻塞归档预览。
- 抽屉使用已有默认状态查询读取本机凭据事实；登录后的页面核验、验证码恢复仍走现有机制。
- 展示真实的已登录、未登录、状态未知及访问需验证事实；验证码不被重新判成未登录。
- 登录与来源不可用不阻止开始；把本轮可用、跳过、待确认的来源及原因传给 Agent。

### 3.3 冻结输入与最终判断

确认时冻结资产类型、用户方法请求、目的、价值类型、基准日、补充提示词及材料身份。能力状态附检查时刻，是运行初始事实，执行中可以更新；不把一次成功检查当作整轮始终可用。

- 自动判断允许单一或组合方法，Agent 解释采用、不采用及协调理由。
- 指定方法作为明确请求，不静默换法或追加方法。Agent 仍判断适用性；用户提示词与表单冲突时提出具体问题，不擅自改写冻结输入。
- 缺少目的、日期等值仍是未指定，不能把资料中的日期或模型假设冒充用户选择。
- 父会话交接复用归档、指纹和幂等创建机制；提示词只携带输入、能力、技术边界及 Wiki 引导，不复制业务筛选阈值与方法优先级。

## 4. Skill 与 Wiki 的读取协议

### 4.1 唯一入口

房地产入口为知识库中的 `01 估值与测算/01 房地产/wiki.md`。Skill 自身的 `references/wiki-entry.md` 声明逻辑入口及定位说明，`SKILL.md` 引用该说明。库身份沿用现有 Host 知识服务配置；不把员工本机绝对路径、凭据或持久化节点 ID 编入 Skill。

入口位置不再同时维护在配置 `manifestPath`、TS 静态路由和 Skill 多处。当前工作树的旧 manifest 读取、解析及槽位选择链路需迁移退出；这与用户要求忽略的本地 `_manifest.json` 是两个不同对象，二者都不作为新流程入口。

本地知识库目录用于本次设计盘点；运行期继续通过 DWS 读取已核对身份的知识库，不自动将本地导出目录当作可信在线来源或离线兜底。

### 4.2 正文导航

Wiki 使用可读正文、条件表及知识库原生链接。维护者写清“在何种输入或资料条件下，读哪一份文档或哪一节，调用什么能力，缺失时如何处理”。Agent 阅读和解释条件，Host 不解析业务决策树。

不要求固定 JSON、固定路由槽位或标题齐全；不因少一个建议章节就停止整轮。参数可用正文或表格表达，Agent 提取有来源的类型化值传给计算工具，工具检查类型、单位和实际引用依据；不再要求业务维护者先填写专用 JSON 参数段。

支持逐步列节点、读正文或章节、返回可继续读取的位置。当前本机 DWS 契约具备这些能力，但线上节点的真实类型、权限和正文仍需实际验收。脑图或图片只能作为辅助，执行条件和链接应保留可读文字。

### 4.3 下载、证据和版本

- 入口及方法正文按需在线读，不整库下载，不要求将整份 Wiki 导出到工作区。
- 留存本次实际采用的片段、节点身份、章节位置、读取时刻、来源更新时间或版本，以及实际读取内容的摘要。
- 分段读取的摘要只标识该片段，不能冒充全篇指纹；不以本地文件修改时间充当远端更新时间。
- 二进制计算模板按实际采用的方法和对象下载，复用同源模板；不预取全部模板，也不沿用旧文档的“一项目最多两个模板”硬限制。
- 同一次计算使用已记录的依据，不在运行中静默替换。案例复算默认沿用原规则和模板；用户要求采用新规则时，建立记录新来源的新版本。
- 入口缺失、歧义或无权限时说明无法取得业务引导并与用户沟通；某方法或模板缺失只影响相关对象与方法，其他有依据的工作继续。

## 5. 来源阶梯与案例预算

### 5.1 已确认的来源策略

| 情况 | 来源与处置 |
| --- | --- |
| 链家已登录且能取得足够合适案例 | 优先使用链家，不为达到上限继续抓取 |
| 链家地区不覆盖、无匹配或合适案例不足 | 补充安居客、58 同城，再跨来源优选 |
| 链家未登录 | 直接使用房天下、58 同城，仍提供登录入口 |
| 状态未知、页面挑战或访问失败 | 复用已有分类及有界恢复，仍不可用则记录缺口，继续对应替代来源 |

来源顺序与补充理由由 Wiki 的渠道说明维护；工具负责真实能力和来源事实，不能在 Wiki 中宣称未实现的适配器已经可用。当前没有 58 适配器，房天下和安居客也需要真实页面验收。

地区适配按各来源分别解析。链家不支持某地区不等于整个输入非法，不得阻止其他来源搜索。原始地区信息保留，禁止把来源不覆盖静默改成另一个城市。

### 5.2 样本组、计数和提前停止

样本组按估值对象及样本用途划分，出售价格与租金分开。业务条件允许时可引用同一候选事实，但采用判断与计算依据按各组分别记录。

每一来源在同组同一检索轮次：

- 最多 10 页列表，最多 20 条达标候选，任一触顶即停；原“每站 5 条”被本次确认的 20 条上限替换。
- 上限不是目标，已足以支持最终选组时可以提前停止。
- 换关键词、筛选条件、重复调用和验证码恢复都不重置预算。
- 同源重复候选不重复计为新达标样本；相近但未达标的候选另行标记，仍受页数预算约束。
- 复算默认复用已取得的候选，不自动重启整轮搜索；用户提出补搜需求时记录新的检索轮次。

预算由 Host 持有并持久化，Agent 不能靠更换查询绕过。实际来源能力仍可更早失败或没有数据，不承诺一定取得 20 条。

### 5.3 列表、详情与证据

先批量解析列表，根据当前方法正文筛选和排序。列表已足够判断的候选直接保留或剔除，不逐条打开详情。只为拟采用但缺关键字段的候选补读必要详情。

跨站去重后选择最接近的 3 条，保留来源和处置理由。相似性判据来自方法正文，不在 Host 写死万能评分、面积范围或修正阈值。

采用案例保留 URL、采集时刻、价格性质、关键事实及证据位置。列表能支持所需事实时可以作为证据，不强制每例必须有详情截图；同一列表截图可被多例引用，避免每条候选重复截同页。挑战页不作为房源证据。

## 6. 方法、模板与计算

取消代码中仅允许住宅市场法的覆盖门禁，也取消自动模式只选第一种方法、结果必须恰好一个 adopted、任务图只执行 primaryMethod 的旧约束。

一次对象估值可有多次方法运行，每次保留适用理由、输入、参数来源、案例、模板与结果。再按 Wiki 的协调规则形成对象结论，不默认平均或默认权重。

同一对象的多方法结果属于交叉判断，不能相加；土地、建筑物等价值组件仅在范围互斥时按相应规则汇总，继续保留重复计算检查。

模板随附填写说明，定义输入区、单位、公式区、结果读取位置及核对办法。通用工具不要求所有方法都采用七张固定工作表，不在通用校验器固定业务阈值。现有住宅模板可以保留原样作为一个具体模板，收益、成本页存在并不代表方法正文、参数和执行链已经完整。

继续保留：模板字节与来源核对、原模板只读、受控输入区写入、公式保护、空值与零区分、十进制计算、来源和产物一致性。缺关键参数不以默认值或模型记忆填补。

真实重算必须经受控的表格计算能力执行，并回读结果与报告数据核对。目前 `delivery/recalculation.ts` 只有可复用接口与校核逻辑，尚无生产装配调用点；完成判定不能仅信任 Agent 写出的 `verified` 文件。没有真实引擎时保留已完成工作，清楚标记尚未完成的重算。

## 7. 少案例结论、用户确认与复算

| 情况 | 行为 |
| --- | --- |
| 有 3 条达标可核案例 | 按 Wiki 方法与实际适用条件计算，数量够不等于其他条件自动满足 |
| 仅 1～2 条，但有足够依据形成参考测算 | 给出结论、实际案例和具体限制，不因数量直接清空所有金额 |
| 当前方法无可用案例或其他关键依据 | 有其他可执行方法时给出其结果；否则提出需要用户决定的具体问题，不编造金额 |
| 有接近但未达标案例 | 展示稳定编号、差异、可用信息和纳入影响，由用户选择是否加入重算 |

知识库需区分参考测算、受限结果与其所要求的正式成果，不能把用户同意纳入案例等同于符合全部业务规范。

用户可以在原估值会话回复“加入 A、C 重算”。系统验证编号及其所指事实，记录用户选择、差异接受说明和变更原因；无法核实或已失效的事实不因确认就变成已核实。

每次计算生成新修订：关联父版本、对象与方法、采用案例、规则与模板身份、输入、计算轨迹、报告和底稿。旧交付件不覆盖；新版本完成核对后更新当前版本指针。继续原会话，不要求重传材料。

## 9. 落地顺序

这是一份分阶段设计，不是已批准的实现计划。

1. **入口与能力切片**：通用估值页、空资产下拉、方法开放、可选登录、抽屉状态和冻结输入接线。
2. **Wiki 与住宅市场法切片**：新阅读工具和 Skill 引导上线，配套补入口、统一案例及模板说明，退出旧 manifest 业务路由。
3. **来源与预算切片**：新增 58、验收房天下与安居客、来源地区独立解析、持久预算及跨站筛选。
4. **组合与修订切片**：移除单方法与固定模板限制，接通真实计算及重算回读、用户候选选择、新版交付。

知识补全与执行能力分开验收。收益法和成本法入口先开放；只有相应正文、必要资料、模板和计算能力到位才可声明该方法已跑通，不能因用户补了一个空标题就称能力完整。

## 10. 验收与回归

实施时先写能因旧行为失败的聚焦测试，再完成相应边界。必要场景：

1. 进页资产为空、输入可用，没有链家检查；选房地产后确认抽屉正确展示登录与验证事实。
2. 未登录仍可启动，父会话收到房天下与 58 的策略及真实能力；旧 required 空列表不能退回全部必需。
3. 链家不支持地区、无结果、案例不足分别进入安居客与 58，不改错城市。
4. 达到第 10 页或第 20 条达标候选即停止；有足够案例可提前停；换词、重试和恢复不重置预算。
5. 列表批量筛选、跨站去重、最终 3 条与剔除记录可核对；不逐条重复截同一列表。
6. 自动模式多方法能真正分别执行与协调；指定方法不静默改写；缺一方法不误伤其他方法。
7. 1～2 条有依据时有结论与限制；无依据时提出明确待确认项，不伪造计算。
8. 按编号加入案例生成新版，旧版仍可读；重复提交、无效编号、正在执行的版本与中断恢复都有确定行为。
9. Wiki 正文修改能改变业务流程，不读 `_manifest.json`；入口不可读、歧义、空正文有真实说明。
10. 模板页签结构变化仍能按对应说明执行；错模板、覆盖公式、缺关键参数和重算不一致能被识别。
11. Agent 自写成功记录不能绕过真实重算与回读；没有计算 provider 时不误报完成。
12. 新旧输入及配置的迁移可观察；Host/Client 跨进程行为变化同步递增协议并验证不匹配处理。

相关仓库闸门为 `make plugin-check`；修改 Go 行为时增加 `make test`；修改现行 Markdown 入口时运行 `make docs-check`。交付前运行 `git diff --check` 并检查最终范围。不得自动提交、推送或发布。

## 11. 方案边界

本轮交付设计及知识建设方案，不改用户本地知识库、线上 Wiki、模板或插件运行行为。既有未提交改动保留。既有知识中的准则、税率和行业口径仅作为待整理来源，不在本次软件设计盘点中宣称已核实其现行有效性。
