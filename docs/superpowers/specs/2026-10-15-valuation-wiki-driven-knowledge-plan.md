## 2. 优先修复的知识冲突

| 位置 | 问题 | 修订方式 |

| 市场法多个流程或公式代码块 | 相似性圈层、筛选、税费、日期调整、归一化、计算链等存在空代码块 | 补可读条件、公式与有数值的验算例；无法补齐则明确缺口，不能把空块当作已定义规则 |

对于业务口径冲突，建设任务是补适用条件、来源及统一结论；不在软件中随便选一边。对明确的算术错误可直接列入校正清单。文档引用的准则、地区税费及市场变化表述还需按其来源核对版本与适用时点，不从旧示例推成当前统一数值。

### 3.1 通用知识

| 文档 | 最少补充内容 | 何时读取 |
| --- | --- | --- |
| 输入与资料解释 | 用户字段含义、原文与提取事实区分、未指定值、资料坐标、补充提示词冲突处理 | 读入口后，结合本次输入 |
| 对象分类与价值范围 | 原始登记用途与业务分类、房地合一/分别、对象和价值组件的界定、资料缺失时判断边界 | 形成对象、样本组及方法候选前 |
| 缺失冲突与用户确认 | 一般缺项、关键参数缺失、来源矛盾各如何处理；只问影响当前计算的具体问题 | 出现缺口时，不要求每次全量阅读 |

通用资料中只维护跨方法规则；收益率、修正系数等仍由相应方法及参数来源说明持有。

### 3.2 三种方法的正文

市场法已有的计算主体优先复用，不另写第二份市场法。首次先读导航和本次所需章节，例如判案例读第 2 章、修正读第 3～7 章、取值读第 8 章；模板操作转到当前模板填写说明。共用渠道、证据和参数整理完成后，原文改为引用权威位置，避免双份规则长期漂移。

收益法至少补齐：适用和不适用条件、租约与市场租金如何使用、租金口径及免租/递增/空置处理、费用及税费、净收益、收益期、报酬或资本化口径、终值处理、必要参数依据、分步公式、缺项处置、模板和带答案的验算例。这里列的是知识主题，不预设任何率值或统一采用的公式分支。

成本法至少补齐：估值范围、土地与建筑物分工、重置成本的组成及口径、费用和利润来源、各类贬值的识别与测算、年限与时点依据、税费、分步计算、重复价值检查、缺项处置、模板和带答案的验算例。若正文需要土地方法，链接到相应已维护知识；不存在时明确缺口，不让 Agent 自行补出一套土地算法。

每种方法都要写明：需要哪些输入、什么事实证明适用、计算依赖哪些参数、如何取值、成果到什么程度、什么时候需要问用户。只补“适用条件＋模板链接”不足以让方法投入执行。

### 3.3 案例与数据渠道

`渠道与降级策略` 统一维护：

- 链家可用时优先；地区不覆盖、无匹配、合适案例不足时补充安居客和 58。
- 链家未登录用房天下和 58；未知及挑战按已有有界恢复结果判断，不阻断其他来源。
- 按对象与出售/出租等样本用途分组，各平台 10 页、20 条达标候选的累计上限；合并去重后优选 3 条，允许提前结束。
- 平台数据是挂牌、成交、算法估算还是其他性质；来源切换不改变价格性质，也不自动证明数据达标。

`候选筛选与相近案例` 统一维护筛选流程和记录方式；具体业务阈值引用所选方法，不再复制市场法的所有阈值。区分达标采用、相近待确认、不可核或不适用；列出每个相近案例的具体差异及纳入影响。列表页可判断的直接筛，拟采用候选缺关键字段时再读详情。

`证据与跨站去重` 说明可用身份线索、重复判断、冲突价格处理、URL 与读取时刻、列表/详情证据何时足够，以及同页多例引用一份截图的方式。不得凭图片相同就认定一定同房源，也不得重复房源当成多条独立样本。

### 3.4 参数与税费

参数以易维护的表格表达，最少包含名称、值或取值方法、单位、适用对象/地区/方法、适用时点、来源与章节、缺失影响。数值没有依据时写明缺口，不用示例值顶替。

税费按地区、交易主体、价格与承担口径、政策有效期组织，附真实来源；不把住宅某城市旧案例中的税率当作商业、办公或其他地区默认值。

允许方法正文直接给出公式和参数解释；共享参数库保存跨文档会复用的权威口径。Agent 在运行时提取类型化参数及引用，业务维护者无需写专用 JSON。

### 3.5 模板与填写说明

唯一模板索引只列真实存在或明确待补的附件，至少区分方法、物业与价值范围、适用情形、工作簿链接、填写说明链接、版本和已验证范围。待补项不能被描述成可用模板。

每份实际模板配一份填写说明：

1. 输入字段、单位与真实填写区域；逐格核查后给坐标，不从旧底稿列号猜测。
2. 公式区、只读区、输出位置与结果含义。
3. 案例数变化及未采用方法时如何保持结果正确。
4. 中间过程、结果精度、取整阶段和核对办法。
5. 一组完整的示例输入、预期输出与逐步验算，标为演示，不作实际项目默认参数。
6. 实际验证的计算引擎及已知限制。

住宅工作簿可先作为一个完整模板保留，无需为了目录整齐强行拆表。收益、成本的现有页若经验证能承担对应方法，可由各方法索引引用同一附件的不同部分；不必先复制三份相同工作簿。方法相关结构由模板说明持有，通用插件不再固定七表。

### 3.6 结果协调与复算

现有方法选择 §6.3 已有协调原则，先引用；需要独立维护时再迁出并回链，避免两份权重规则。

补充内容包括：各方法同口径比较、差异分析、取舍或权重依据、同一对象多方法不可相加、价值组件不得重复，以及数据或方法不完整时如何披露结论范围。

复算文档说明少案例结论、相近候选差异展示、按编号选择、原版本保留、变更原因、同规则复算与采用新规则的区别。用户确认只改变已明确的选组或假设，不把未知来源变成已核实事实。

## 4. 入口 Wiki 草稿

下面是可转写到现有空 `wiki.md` 的内容结构。括号内的文档名是导航目标；上线时应插入真实知识库原生节点链接，不能照搬成本机路径。尚未补齐的目标保留清楚的待补说明，不写成可执行完成。

```markdown
# 房地产估值 Wiki

本页是房地产估值 Skill 的业务入口。结合本次用户输入、资料和可用能力逐步执行；
正文和模板按实际需要读取，不预先下载整库。

## 1. 理解本次输入

读取用户确认的资产类型、方法请求、评估目的、价值类型、基准日、补充提示词及材料。
按《输入与资料解释》区分用户选择、材料事实与未指定事项。
资料或要求互相冲突时提出具体问题；不替用户改写已确认条件。

## 2. 识别对象和价值范围

按《对象分类与价值范围》整理对象、原始用途及其依据。
区分房地合一、分别评估和不同价值组件，避免重复计算。
某对象缺关键依据时说明该对象的缺口，其他有依据的对象继续。

## 3. 判定采用的方法

- 用户选自动：读《房地产评估方法选择方案》，分析可采用的单一或组合方法。
- 用户指定方法：读该方法正文，核对适用条件和资料，不静默换法或加入其他方法。
- 方法与补充提示词冲突：说明冲突，请用户澄清。
- 记录采用和不采用的依据；缺正文、参数或模板不等于已经执行成功。

## 4. 按采用的方法逐步执行

- 市场法：读《市场法》的本次相关章节，按《候选筛选与相近案例》组织出售样本。
- 收益法：读《收益法》，按实际路线取得租金及其他必要参数。
- 成本法：读《成本法》，按明确的范围取得土地、建筑物及成本参数。
- 所需共享参数和地区税费读对应参数说明。
- 按《模板使用目录说明》定位实际模板及其填写说明，只下载所需附件。

使用 Skill 已声明的能力执行检索、计算和产物生成；调用能力不能取代业务依据。

## 5. 外部案例与来源

按《渠道与降级策略》选择来源：链家优先；地区不覆盖、搜不到或合适案例不足时，
补充安居客和 58；未登录时使用房天下和 58。
按对象及样本用途分组，各来源累计最多 10 页和 20 条达标候选，任一上限即停。
足够支持选组时提前结束，不为收满上限继续抓取。
列表先筛，只有缺关键字段的拟采用候选补读详情；跨站去重后选最接近的 3 条。

## 6. 形成结论及待确认项

按对应方法与《结果协调与结论说明》给出计算结果和最终判定。
只有 1～2 条但有依据时仍给参考测算，并说明实际数量与影响。
没有可用计算依据时与用户沟通，不生成无依据金额。
展示相近案例编号、差异及加入后的影响，供用户决定是否纳入复算。

## 7. 按用户选择复算

按《相近案例确认与复算》处理用户明确选择的编号。
保留原版本，记录采用案例与变更原因，再生成新版本结果、报告和底稿。
沿用原规则与模板；采用新规则时说明新的依据版本。
```

章节名与次序是写作建议，不是 Host 强制解析合同。入口只做条件与文档导航，不复制市场法全部正文、税率、修正系数或模板单元格表。

## 5. 链接、来源和维护纪律

1. 每个 Skill 声明一个入口；入口用真实链接指向叶子文档或章节。编号用于阅读排序，不从编号推断方法。
2. 优先使用稳定节点链接；方法的具体目标、模板和共享规则关系由 Wiki/正文链接维护，Host 只解析真实链接身份。
3. 每个规则明确是来源原文、机构执行口径还是示例；列适用范围和时点，不能把示例或搜索预算冒充标准条款。
4. 空文件、空章节与失效链接有明确缺口，不以本地 Skill 旧正文顶替；没有业务依据时问具体问题。
5. 迁出共享内容时同步修改原文引用，保留一个当前权威位置；历史示例标日期，不把旧表名继续作为现行操作说明。
6. 参数和模板更新附版本、适用说明及验算记录。既有估值引用保留，不能让新规则改写旧结果依据。
7. 新方法正文、所需参数、模板与验算例组成一套可执行知识；还依赖新能力时明确列出执行能力缺口。

## 6. 补全优先级与验收

| 优先级 | 工作包 | 可验收结果 |
| --- | --- | --- |
| P0 | 填入口 Wiki，补输入/范围/缺失处理，统一挂牌与少案例口径 | Agent 能从用户输入走到具体方法及明确待确认项，不猜下一步 |
| P0 | 补渠道、筛选及证据说明，接入真实来源能力 | 链家优先和两条降级路径、10 页/20 条、最终 3 条可演练；平台缺能力被如实呈现 |
| P0 | 修市场法错误/空块/旧表引用，补住宅模板填写说明与验算例 | 住宅市场法形成可重复的知识和模板闭环；不是仅存在一份 XLSX |
| P1 | 补收益法完整正文、参数说明、模板和演示验算 | 仅改已接通能力范围内的知识，即可执行收益法，并与市场法组合 |
| P1 | 补成本法完整正文、范围与参数、模板和演示验算 | 成本法能够独立执行，土地与建筑物范围及缺口清楚 |
| P1 | 补协调、相近案例确认与新版复算说明，接通真实计算能力 | 可按编号复算，新旧结果及差异均可追溯 |
| P2 | 商业办公等模板与示例、更多地区参数和扩展对象 | 按实际已具备的数据及能力逐项扩展，不将占位标题宣称为支持 |

每个方法的知识验收都检查：输入和单位明确、链接可读、必要参数有来源、模板可下载且填写说明匹配、示例能独立复算、缺口分支可沟通、实际结果与报告一致。不同方法独立通过，不因某一方法仍待补而让整个估值入口不可用。

收益法、成本法的 UI 入口开放与方法实质验收是两项不同结果。插件重构与知识补全需要配合推进；修改 Wiki 不能凭空产生尚不存在的 58 适配器或真实重算引擎。
