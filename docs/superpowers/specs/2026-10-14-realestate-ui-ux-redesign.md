# 房地产估值启动页 UI/UX 全面优化设计方案

> 文档性质：2026-10-14 的设计与实现交接快照，描述待实现方案，不是当前能力说明。
> 接收方：DeepSeek Harness 中负责 `crwu-ai` 的实现 Agent。
> 用户要求：全面检查「报告评估 → 估值 → 房地产」的页面、操作体验、动画和提示，提供可直接据此实现的详细方案。
> 基线：`4c12b85` 加当前未提交工作区；本稿核查的是当前工作区源码，不是只看 HEAD。相关模块正在修改，实现前必须重新核对差异，保留用户已有工作。
> 本次交付：设计文档与静态示意图。没有修改产品代码、安装插件、创建业务估值会话、提交或发布。

## 1. 设计结论与目标

推荐保留现有「资料输入 → 只读核对 → 进入一个 DSH 原生估值会话」结构，把房地产页做成稳定、清楚、紧凑的专业任务入口。

此次优化优先解决操作闭环，再提升视觉与动效：用户应始终知道现在在哪一步、哪些输入已经保存、为什么某个动作不可用、下一步可以做什么，以及重试是否会重复创建会话。

核心设计决策：

1. 保持工作台既有“办公 + Apple”视觉和一层工作面，保留两级目录。
2. 输入页一个明确主操作「确认」；核对抽屉一个明确主操作「开始估值」。两者使用现有中性实心主按钮 token。
3. 门禁只替换房地产正文；检查失败、未登录、等待验证和已登录四种语义分开处理。
4. 资料区必须区分“选中的入口”和“实际纳入的文件”。展开文件夹、逐文件排除、重新扫描后保持排除结果，形成完整闭环。
5. 核对抽屉保持只读，创建期间继续显示同一个抽屉和同一颗按钮；创建开始后禁止返回修改。
6. 请求等待、切页返回、超时和重试有明确状态，不允许留下永远加载或按钮无反馈的页面。
7. 必要说明使用可读的文字颜色；状态使用图标、文字、颜色共同表达。
8. 动效用于说明状态变化和空间关系；默认 120–160ms，抽屉进入 200ms、退出 150ms。支持减少动态效果。
9. 成功立即进入会话；房地产页不恢复运行进度、结果看板或后台估值轮询。
10. 所有新增交互必须补可观察行为测试；涉及 DOM、焦点、几何和动画的内容必须经过真实浏览器验收。

成功判据是：员工无需学习内部术语，能添加正确资料、排除错误文件、核对条件、创建一次会话，并能从每类错误中恢复。

## 3. 当前问题清单与优先级

优先级定义：P0 阻断恢复、丢失流程连续性或误导用户判断任务是否创建；P1 影响操作效率、信息理解和可访问性；P2 提升一致性与精致程度。

以下路径相对于 `plugins/dsh-crwu-workbench/`。行号是本次检查位置，后续改动后以函数名为准。

| ID | 级别 | 当前证据 | 用户影响 | 目标处理 |
| --- | --- | --- | --- | --- |
| UX-01 | P0 | `model/valuation-state.ts:232` 的 `showsConfirmationDrawer` 只接受 confirmation；创建阶段定向渲染得到 0 个抽屉 | 点击开始后原操作界面突然消失，创建按钮的 pending 反馈看不到 | confirmation 与 creating-session 保持同一抽屉实例 |
| UX-02 | P0 | `ValuationAuthGate.tsx:95` 对 challenge 只渲染文字；定向渲染唯一按钮为「重新检查」 | 用户看到需要验证，却缺少实际处理入口 | 按可信站点调用 Host 的打开验证操作 |
| UX-03 | P0 | `controller.ts:206` 将 waiting-user 归一成 running；shared wire 的登录状态数组也漏掉 waiting-user | 人工验证状态被误报为持续登录，等待提示路径无法正常到达 | 显式覆盖所有 LoginJobState，同步 wire 词表；未知值不伪装 running |

| UX-08 | P1 | 估值扫描 RPC 只返回 `scan.items`（选择入口），不返回 `scan.files`；移除仅过滤 selection | 文件夹展开数量可见，但具体文件与逐文件排除不可操作 | 返回受控文件明细，增加 exclusions，同步 scan 与 intake |
| UX-09 | P1 | FileRow 全部使用 FileIcon；目录大小未知；fileStatusText 只有 scanned/skipped 两个显式分支 | 文件夹像文件，unreadable/over-limit 会落入“待读取” | 图标按类型，状态采用完整映射 |
| UX-10 | P1 | 主按钮样式仅设置红色描边和文字，背景仍透明 | “唯一 primary”的视觉层级没有成立 | 复用 `--crwu-primary-bg/text` 实心主按钮 |
| UX-11 | P1 | 移除按钮 24×24，没有局部扩大命中区；方法和一般按钮的焦点状态不完整 | 难点击、键盘位置不够明确 | 实际可点击区至少 44×44，增加 focus-visible/focus-within |
| UX-12 | P1 | 必要元信息和路径使用 tertiary；浅色当前 #9A9A9F 对白底约 2.80:1，深色 #6F7075 对纸面约 3.45:1 | 核对来源和解释提示的阅读困难 | 必要正文、路径、帮助说明使用 secondary 或更深色 |
| UX-13 | P1 | 资料数量在文件区与底栏重复；准备中可见说明叫“返回修改”但页面没有对应动作 | 噪音与操作指引不匹配 | 文件区显示纳入/跳过明细，底栏显示当前行动摘要；准备中补真实返回动作 |
| UX-14 | P1 | 扫描失败有文字但未连接已有 `controller.rescan` | 用户只能重新选择或反复点添加 | 资料区给「重新读取清单」 |
| UX-15 | P1 | 确认抽屉将整组方法画成 disabled radio | 核对页看起来像无法使用的表单 | 改为只读键值摘要，保留禁用方法范围说明 |
| UX-16 | P1 | 抽屉退出依赖父层延迟卸载，估值调用没有 closing 管理；输入表单在确认时卸载 | 退出动画缺失、背景上下文弱、滚动与展开状态可能丢失 | 独立管理抽屉呈现生命周期和表单展示记忆 |
| UX-17 | P1 | 创建失败的顶部 phase 文案一律“会话还没有创建成功”，即使 parentSessionId 已存在 | 同一屏对创建事实给出矛盾信息 | 失败标题来自结构化结果，删除重复泛化阶段句 |
| UX-18 | P2 | 补充要求展示用普通 p，缺少 pre-wrap；方法说明重复“当前选项”前缀 | 原输入换行丢失，辅助信息阅读冗长 | 保留换行；只展示当前方法的一句解释 |

上述对比度为当前 token 的数学计算，不代替运行中元素的计算样式检测。品牌红 #D84A4A 对白底约 4.20:1，不适合直接作为 12–14px 的必要链接或按钮文字。品牌色继续用于强调线、描边和非文字标记。

## 4. 方案取舍

| 方案 | 收益 | 代价 | 结论 |
| --- | --- | --- | --- |
| A：单层纵向工作面 + 只读抽屉 + 原生会话 | 符合现有习惯与架构；切页少；可分阶段实施；宽窄面板一致 | 需要把状态和反馈做完整 | 采用 |
| B：独立三步向导 | 步骤明显；可单页承载较复杂输入 | 只有少量条件也要额外切页；增加前进/返回状态；与抽屉核对重复 | 暂不采用 |
| C：左资料、右设置的双栏 Dashboard | 大屏可同时看两块内容 | 小资料量时空白大；窄面板变形；重建已有视觉；容易扩展出运行看板 | 不采用 |

借助 ui-ux-pro-max 搜索得到微交互、清晰层级、可恢复错误、可见焦点等建议。其通用输出也出现营销网站布局、豪宅字体、默认 OLED 深色等内容，这些与桌面专业工具不符，不能照搬。设计系统以本仓当前 token、字体、组件和用户已有规则为主。

## 5. 信息架构与完整用户旅程

### 5.1 页面层级

```text
DSH 宿主
  工作台头部：既有品牌、版本与问候
  一级目录：估值
  二级目录：房地产 / 土地（开发中）/ 机器设备（开发中）
  房地产工作面
    范围与下一步说明
    门禁工作区 或 资料输入工作区
      资料范围与文件清单
      评估方法
      评估基准日
      补充要求
      面板内操作栏
  核对抽屉：只读输入 + 开始估值
  DSH 原生估值会话：后续识别、取数、计算与交付
```

两级目录归 shell；门禁归房地产域；输入、核对、交接归估值页面状态机。不要在页面重复生成另一套环境状态或导航树。

### 5.2 正常旅程

1. 员工进入房地产，正文先显示来源检查；有记录也不先假报“未登录”。
2. 必需来源未登录时，显示每个来源的状态和可用动作。
3. 员工在受控浏览器完成登录，回来点「重新检查」；Host 判定放行后进入输入工作面。
4. 添加文件或文件夹，读取元信息清单；列表显示纳入数量、跳过项和文件范围。
5. 必要时展开文件夹，移除错误文件；方法默认自动判定，日期与补充要求可选。
6. 点击「确认」，立即呈现准备状态，保留原输入，生成归档预览。
7. 只读抽屉核对文件与条件；发现问题可以「返回修改」。
8. 点击「开始估值」，抽屉保持打开，主按钮变为「正在创建会话…」。
9. Host 返回交接成功，提示“估值会话已创建，正在打开…”，立即打开原生父会话。
10. 后续处理在会话内进行；再次进入房地产是新草稿，可显示一次最近会话链接。

### 5.3 过程提示

输入顶部只保留一条低权重说明：

> 当前支持住宅市场法。确认资料后，将创建并打开估值会话。

阶段从当前按钮、局部状态区和抽屉标题表达。不要再叠一条“还没有开始”或“会话还没有创建成功”的泛化句。

仅在准备、创建或失败时，出现必要阶段反馈。不增加大型步骤条、百分比或 AI 运行看板。

## 6. 视觉系统与组件规格

### 6.1 整体布局

| 项目 | 规格 |
| --- | --- |
| 最外层 | 沿用工作台 app 背景与 shell，不新增独立网站外壳 |

### 6.3 颜色与 token

| 用途 | token | 应用 |
| --- | --- | --- |
| 背景 | `--crwu-app-bg`、`--crwu-surface`、`--crwu-surface-subtle` | 宿主底、纸面、轻状态区域 |

| 装饰性弱信息 | `--crwu-text-tertiary` | 非必要编号、装饰；不能承载操作所需的信息 |
| 主按钮 | `--crwu-primary-bg`、`--crwu-primary-text` | 浅色黑底白字，深色浅底深字 |
| 主按钮 hover | `--crwu-primary-bg-hover` | 与主题一致 |
| 次按钮 | `--crwu-control`、`--crwu-control-text` | 添加、重读、返回 |
| 选中提示 | `--crwu-selected` + `--crwu-brand` 描边 | 方法选中与局部强调 |
| 普通分隔线 | `--crwu-border` | 不承载必要的控件识别 |

| 成功 | `--crwu-risk-pass` 图标 + 正文 token | 不把整行染绿 |
| 焦点 | 品牌或经验证的交互 token，2px outline | 背景对比至少 3:1，outline-offset 2px |

当前控件浅描边可能不足以独立识别输入框。建议在唯一 token 定义块增加两个估值语义槽，限制在估值模块使用：

| 新 token | 浅色候选 | 深色候选 | 用途 |
| --- | --- | --- | --- |
| `--crwu-valuation-field-border` | #85858B | #6F717A | 必要输入框边界，当前纸面对比约 3.67:1 / 3.50:1 |
| `--crwu-valuation-hint-text` | 引用 text-secondary | 引用 text-secondary | 必要帮助文案，不影响其他模块三级字色 |

候选值需要计算样式复核；不要为了估值页更改全部模块的 tertiary、品牌红或全局边框。新增色值只放 `styles/tokens.ts` 允许字面量的区域。

主题严格跟随 `body[data-ds-dark-theme]`；减少动画使用 `prefers-reduced-motion`，二者职责不同。

| 文件夹展开 | 图标 16px + 文件夹名称 | 至少 44px 高的标题区域 | 展开或收起 |
| 方法选项 | 常规高 36px | 独立 44px 高区域 | 整块 label 可点 |

若使用伪元素外扩命中区，父行必须预留足够槽位，外扩区域不能覆盖文件详情、邻近按钮或另一行；必须用真实点击坐标验证。窄面板直接采用 44px 控件高度。

主按钮固定最小宽度 96px。pending 文案更长时预留其宽度或允许按钮自身稳定变宽但不做 width 动画、不把其他控件推来推去。

所有按钮的 disabled、hover、active、focus-visible 都须明确；禁用态不保留看似可用的 hover 高亮。不能只用 title 告诉用户为什么禁用。

## 7. 页面 A：案例来源门禁

### 7.1 布局

门禁区域复用一层工作面，不另套厚边框卡片。结构为标题、说明、站点行、任务提示、动作区。

```text
案例来源检查
开始前需要确认必需来源已登录。

链家   必需       [状态图标] 未登录        [登录链家]
说明：在打开的浏览器窗口完成登录。
──────────────────────────────────────────────────
贝壳   可选       [状态图标] 无法检查      （不显示登录按钮）
说明：暂时无法确认访问状态，可重新检查。

                                           [重新检查]
```

站点名称由 Host 提供。必需/可选排序与分组来自可信配置，不在页面硬编码“链家与贝壳必定都要登录”。如果全部必需来源通过，即刻转输入，不为成功动画延迟放行。

### 7.2 检查中

- 第一帧显示“正在检查案例来源登录状态…”和轻量静态骨架。
- 不展示假的来源清单、假的未登录状态或“0 个来源”。
- 若已有上次站点事实，重查时保留原行并标注“正在重新检查”；旧状态不得作为新放行结论。
- 最小反馈区高度稳定；没有已知行时预留两行骨架只是视觉占位，不代表确有两个站点。
- 同一个检查请求在途时按钮 disabled，文案“正在检查…”，`aria-busy=true`。
- 超过 15 秒增加“检查用时较长，可以稍后重新检查”；检查仍在进行，不能假报失败。
- 建议单次 Client 检查等待上限 60 秒；到期回到可重试的 blocked 状态，并作废旧响应。此超时只描述页面等待结束，不假称 Host 操作已被取消。

### 7.3 站点状态与动作矩阵

| 权威事实 | 展示 | 行动作 | 是否阻塞 |
| --- | --- | --- | --- |
| authenticated，无挑战 | 已登录 | 无需登录；可在详情看有效期 | 按 gate 放行 |
| unauthenticated，无挑战 | 未登录 | 登录来源 | 必需项阻塞，可选项不阻塞 |
| unknown，无挑战 | 暂时无法确认 | 使用全局重新检查 | 必需项阻塞 |
| challenge 已检测、未完成 | 需要完成验证 | 打开验证窗口 | 按 gate；不能把验证等同未登录 |
| 已登录且 challenge waiting-user，gate 已放行 | 来源可能需要验证 | 输入页一条非阻塞提示，按需打开窗口 | 不新增 Client 阻塞 |
| challenge recovered，但其他必需项未好 | 访问已恢复 | 无重复验证入口 | 按其他项判定 |
| provider unavailable / 系统失败 | 当前无法检查 | 重新检查；必要时去环境信息 | 不要求员工重装包内工具 |

打开验证窗口只能通过 Host 的受控站点操作；Client 不直接把 verifyUrl 当作任意 window.open URL。Host 必须绑定现有 profile、校验站点与 URL，并把错误安全回显。

### 7.4 登录任务生命周期

| 状态 | 文案 | 动作 |
| --- | --- | --- |
| running | 已打开来源登录窗口，请在浏览器中完成登录。 | 取消本次登录；重新检查仍可用，但重查请求在途禁用 |
| waiting-user | 登录状态已确认，还需要完成页面验证。 | 打开验证窗口；完成后重新检查 |
| succeeded | 来源已登录。 | 执行一次权威 preflight，再决定是否放行 |
| failed | 登录操作未完成：安全原因。 | 重试登录或重新检查，依 errorKind 判断 |
| cancelled | 本次登录已取消。 | 重新登录；不撤销其他有效来源 |

首次点击后立刻给受理反馈。重复点击复用 Host 现有 jobId；展示“登录窗口已打开，请继续完成登录”，不产生多个窗口。

首版采用明确的「重新检查」闭环，不为 UI 优化引入常驻轮询。每次检查都按 jobId 更新本页任务：有对应 Host 任务时用新状态，没有时不把旧 running 无限保留。离开页面只停止页面请求，不擅自取消员工打开的浏览器任务。

### 7.5 错误位置

- 单站点登录失败：贴在该站点动作下。
- 全站检查失败：贴在站点列表上方，保留先前事实但注明未重新确认。
- 取消失败：贴在当前任务下，保留原任务。
- 普通错误用一行原因和一行动作；技术细节不默认展开。
- 不同时在顶部、站点行和底部重复播报同一错误。

## 8. 页面 B：估值资料与条件输入

### 8.1 资料区空态

```text
估值资料                               [添加文件] [添加文件夹]

           添加待评估资料
       权属资料、对象清单、现场照片等
     支持 PDF、Word、Excel 和图片，单次最多 30 份

（通过上方按钮选择本机资料；不宣称支持拖拽）
```

空态高约 104–120px。使用小文件线性图标即可，不增加插画或按钮副本。样式不使用强烈“上传投放区”暗示，文字叫“添加资料”，不是“上传到云端”。实际支持扩展名必须由 Host 能力对齐；不能把所有普通文件都标成“内容可分析”。

### 8.2 有资料时的结构

资料区分两层：

1. 已选入口：直接文件或文件夹，显示名称、种类、纳入文件数，文件夹可以展开。
2. 实际文件明细：归属入口、文件名、相对路径、大小、纳入状态和移除。

默认已选入口展开到首批最多 8 个文件行，超过提供「查看全部 N 份」；计数始终使用 Host 的递归去重事实，不能把入口数当文件数。

示例：

```text
v  项目资料                          文件夹 · 纳入 3 份       [移除文件夹]
   权属资料.pdf                      PDF · 2.4 MB   已纳入       [移除]
   对象清单.xlsx                     Excel · 84 KB  已纳入       [移除]
   现场照片.jpg                      图片 · 1.2 MB  已纳入       [移除]

已纳入 3 / 30 份；跳过 1 项                                    [查看跳过项]
```

“已纳入”只表示通过本次文件范围与读取元信息检查，不表示已经解析业务内容、估值完成或证据有效。

### 8.3 文件状态

| 原始事实 | 行状态 | 附加说明 |
| --- | --- | --- |
| 扫描中 | 读取清单中 | 未知大小显示「大小待确认」，不编 0 B |
| scanned，普通文件 | 已纳入 | 业务内容将在会话内读取 |
| directory | 文件夹 · 纳入 N 份 | 使用 FolderIcon，可展开 |
| unreadable | 无法读取 | 路径不存在、权限或占用等安全原因 |
| skipped | 已跳过 | 不支持项、符号链接或特殊文件；按 Host 原因 |
| over-limit | 超过单次上限 | 区域级提示真实份数，整批不可确认 |
| removed / excluded | 已从本次范围移除 | 不再计入；可通过撤销恢复 |
| 未认识的状态 | 状态待确认 | 重新读取；不能落入“已纳入”或“待读取”的正常语义 |

无效行不整行降低 opacity，以免原因更加难读。状态图标与原因使用适合的语义，文件名仍可读。

### 8.4 目录展开与逐文件移除

这是本次必须完成的能力闭环，不能只画一个展开箭头。

- 文件夹行点标题区展开/收起；移除文件夹按钮独立，不触发展开。
- 展开状态使用 `aria-expanded`，关联实际存在的文件组。
- 子文件移除写入 `excluded` 范围，不修改磁盘文件；同真实路径经多个入口出现时仍被统一排除。
- 移除整个文件夹删选择入口，并清理只属于该入口的排除项；重复纳入关系由 Host 去重重算。
- 重新扫描、添加新入口、确认预览，都使用同一组 exclusions。移除后不能又在预览里重新出现。
- 本期采用“排除优先”：被移除文件不会因重新添加另一个含它的文件夹而自动恢复；提示“此文件已从本次范围移除”，可「重新纳入」。
- 提供最近一次移除的「撤销」，反馈在资料区下方，保留 8 秒。连续移除以最近一次操作为单位；移除文件夹的撤销恢复整个入口及相应排除状态。
- 开始准备确认时隐藏撤销入口并冻结当前范围；不把可编辑操作带进只读抽屉。
- 如果目录遍历触及安全上限、清单不完整，显示“资料清单未完整读取，请选择更小的文件夹”，禁用确认。不能把截断数量当全部数量。

DSH 可复用 `local-audit/scan.ts` 已有 excluded 参数和候选文件结构，但不能直接修改本地审核的业务口径。估值的参数与回显仍由自己的 operation 校验。

### 8.5 数量与问题处理

- 0 份：底栏“先添加至少一份资料”，主按钮 disabled。
- 1–30 份且至少一份可读：允许确认；跳过项可见，不能悄悄丢掉。
- 超过 30：显示“本次共 N 份，超过 30 份。请移除部分资料或分批估值。”不截取。
- 全不可读或全空：展示具体原因及「重新读取清单」/「重新选择资料」。
- 部分空文件：由 Host 明确纳入或跳过规则，UI 不臆造。仍需在确认时指出，不称内容已读取。
- 取消原生文件选择器：无错误、原输入不变。
- 同一个真实路径重复选择：保留第一次；提示“已忽略重复选择”，不将它记为一份失败文件。
- 同名不同路径：均保留；显示短目录上下文，在详情和核对抽屉给完整路径。
- 相同内容不同路径：扫描阶段不假装已知；归档阶段指纹确认后展示重复内容关系。

### 8.6 重新扫描的视觉稳定性

添加或移除后，旧文件行保持可见，以“正在重新读取清单”标记为旧事实；主按钮临时禁用。新结果在同一次状态更新落地。

不要每次扫描先清空列表再出现新行。controller 必须区分旧显示事实和当前可确认事实，旧清单不能被用于生成确认。

扫描失败保留入口与条件，在资料区给“资料清单读取失败”和「重新读取清单」。失败时不能只剩“请添加至少一份”这种错误原因。

### 8.7 评估方法

保留四项单选：自动判定、市场法、收益法、成本法。

- 自动判定标注“推荐”，默认选中。
- 自动判定说明：“由估值会话根据资料与规范判断适用方法；当前可完成住宅市场法。”
- 市场法说明：“按市场法处理；案例条件与适用性仍需在会话内核实。”
- 收益法、成本法可见灰态，标注“暂未开放”；下面一句“收益法、成本法尚未提供完整知识与模板”。
- 禁用选项不响应点击、键盘或 controller 修改；Host 同样拒绝。
- 不增加收益法成本法的“预约开放”等按钮，也不假称自动判定可以执行它们。
- 整个选项可点击；选中态为轻底、描边、字重和单选标记，不只变色。
- `fieldset/legend` 或等价单选组语义；方向键沿用原生 radio 行为。

宽度 ≥560px 时四项一行，必要时自然换行；更窄时两列；≤400px 时单列。禁用原因在选项附近常驻，不依赖 hover tooltip。

### 8.8 评估基准日

- label：“评估基准日”，旁边“可选”。
- 宽面板控件宽 240px；窄面板全宽，最小 44px 高。
- 沿用原生日期输入，不引入新的日历库。
- 不自动填今天、不从文件日期代入；空值原样提交。
- 空值帮助：“未指定时，按会话采集时点组织测算，并在结果中说明未指定基准日。”
- 已填写时帮助：“将按该基准日核实案例与时间口径。”
- 有值时允许「清除日期」，与输入同组；禁止在 blur 后悄悄补一个值。
- 校验合法日历日期，不只校验 YYYY-MM-DD 字符串形状；如 2026-02-30 必须拒绝。
- 不自行设置“未来日期禁止”这类未获业务确认的规则；UI 校验格式与合法日期，业务适用性留给会话。
- 日期值视为日历日期，不用 UTC Date 转换把日期前后移动一天。

### 8.9 补充要求

- label：“补充要求”，旁边“可选”；默认 3 行、约 88–96px 高。
- placeholder：“例如：请按清单逐套测算；权属资料中面积与现场记录不一致，请在报告中说明。”
- 持续提示：“可填写资料说明与项目要求，具体口径仍按资料和适用规范核实。”
- 保留换行，输入不要自动 trim、删空行或改写措辞。
- 计数与错误单独一行，右侧显示 N / 4000；接近上限（≥3600）提示剩余数量；达到上限给明确说明。
- 字符计数统一沿用现有 Client/Host 字符串长度口径，不一端按字素、一端按 UTF-16。若以后改按用户感知字符计数，需要两端一并迁移。
- 中文输入法 composition 期间不频繁打断、不把半个合成串报错；合成结束再应用上限。
- 粘贴超限不得静默截断而不提示；说明“输入超过 4000 字符，请精简后重试”，原有有效内容保留。
- 允许纵向调整，但不让 textarea 挤出底部操作栏；最大建议 240px，此后内部滚动。
- 不把示例 chip 自动写入已存在文本；本期不增加可能污染用户要求的快捷提示模板。

## 9. 页面内操作栏与准备确认

### 9.1 操作栏布局

左侧只显示当前可行动摘要；右侧唯一 primary「确认」。

| 状态 | 左侧摘要 | 主按钮 | 次操作 |
| --- | --- | --- | --- |
| 空输入 | 先添加至少一份资料 | 确认，禁用 | 无 |
| 扫描中 | 正在读取资料清单… | 确认，禁用 | 无重复扫描 |
| 正常 | 已纳入 N 份 · 下一步核对输入 | 确认 | 无 |
| 超限 | 共 N 份，请减少到 30 份以内 | 确认，禁用 | 回资料区处理 |
| 扫描失败 | 资料清单未能读取 | 确认，禁用 | 资料区重新读取 |
| preparing-confirmation | 正在复制资料并准备核对信息… | 正在准备确认信息…，禁用 | 返回修改 |

数量详细分解只在资料区显示；底栏不重复一整段列表说明。禁止原因关联 `aria-describedby`；当多项阻塞同时存在，按“清单完整性 → 资料有效性 → 数量 → 方法 → 文本/日期校验”优先显示，并在各字段附近给具体原因。

### 9.2 滚动结构

操作栏属于估值工作面，不 fixed 到宿主整个窗口。

建议让工作面成为确定高度的 flex column：中间内容 `flex:1; min-height:0; overflow:auto`，底部操作栏 `flex:none`。如果既有 shell 已承担这一级滚动，则在 shell 允许的面板容器中实现 sticky 底栏，但必须实测初始首屏、长清单和短高度都可见。

不能仅在很长的表单最后加 `position:sticky; bottom:0` 就宣称主操作永远可见。验收必须覆盖操作栏的初始可见性和最近滚动祖先。

避免同时让 root、tabpanel、工作面正文都滚动；最终仅一个主正文滚动容器。桌面资料清单可使用最多 320px 的内部滚动，窄面板取消这一层，用主正文滚动。

### 9.3 点击确认后的即时反馈

- 点击同步进入 preparing-confirmation，然后发送请求；不等服务器响应才改按钮。
- 保留资料、方法、日期和要求的显示，编辑操作禁用，增加 `aria-busy`。
- 不清空清单，不跳入空白页，不先显示“内容解析中”。本步骤仅归档与元信息核对。
- 按钮中给 14px spinner 和状态文字；文案不反复改变宽度。
- 超过 15 秒提示“资料较多，仍在准备；你可以返回修改，原输入会保留”。
- 沿用现有 120 秒准备等待上限。到期回可编辑草稿，显示“准备核对信息超时，资料选择和条件已保留”。
- 「返回修改」立即恢复草稿并作废旧响应；只说明停止等待本次预览，不承诺磁盘复制已立即停止。
- 成功后核对抽屉打开；只有 Host 返回的有效 preview 才能展示为可开始状态。

```text
──────────────────────────────────────────────────────
[返回修改]                               [开始估值]
```

把只有三项的条件摘要放在清单前面，避免 30 份文件把方法和日期推到底部。仍只展示“文件元信息 + 用户输入”，未纳入项属于资料范围说明，不展示业务分析。

### 10.2 只读条件呈现

- 方法不再用四个 disabled radio，使用 `<dl>` 键值摘要。
- 自动判定显示“自动判定 · 当前支持住宅市场法”；市场法显示“市场法”。
- 在方法值下保留“收益法、成本法尚未提供完整知识与模板”的范围说明；不暗示可以在抽屉切换。
- 日期未填显示“未指定”，并用一行必要说明解释采集时点测算。
- 补充要求未填显示“未填写”；已填内容 `white-space:pre-wrap`、`overflow-wrap:anywhere`。
- 补充要求很长时只在正文自然滚动，不创建又一层高 80px 小滚动框。
- 不展示 digest、requestId、scope、模型 Prompt、内部目录和工作流阶段。

### 10.3 文件元信息

每份最少包含文件名、类型、大小、创建时间、原始绝对路径；必要时附重名和重复内容信息。

- 文件名 13–14px medium；元信息 12px secondary；路径 12px secondary。
- 路径允许选中，不只存在于 title；可选「复制路径」按钮，仅复制到本机剪贴板，不写日志、不传模型。
- 复制失败时路径依旧可选中，说明“请选中路径手动复制”。
- 同名不同文件：短目录或短 fileId 区分；完整 ID不作为每行主要视觉。
- 相同内容副本：“与〈可识别文件名及目录摘要〉内容相同”，比“与 material-002 重复”更容易核对；稳定 ID保留辅助标记。
- 创建时间未知明确显示“创建时间未知”，不拿修改时间代替。
- 已有格式化函数保留 ISO 字面量时，UI 必须标注 UTC，避免误认本地时间。若以后改成本地显示，需统一 helper、明确时区并更新测试，不只替换文案。
- 对文件夹选择，抽屉展示实际归档文件，不再只显示入口文件夹名称。
- skipped 列表存在时在资料末尾显示“以下 N 项未纳入”及原因；不把 skipped 混入已归档份数。

### 10.4 打开、关闭和焦点

- 打开时将焦点放在抽屉标题（`tabindex=-1`），使员工先核对内容，不默认把焦点放到开始按钮。
- 标题 `aria-labelledby`，简短说明 `aria-describedby`；正文长清单不整段作为 describedby。
- Tab/Shift+Tab 限于抽屉实际可操作元素；禁用元素不纳入循环。
- Escape、遮罩、关闭按钮、返回修改在 confirmation 阶段等效：返回草稿，保留输入、展开状态与原滚动位置。
- 退出动画完成后再卸载；恢复焦点到原「确认」按钮。减少动态效果时立即卸载并还原焦点。
- SideDrawer 不能只把当前 aside 的兄弟 inert 就宣称整个宿主已隔离；需要真机确认目录、侧栏和会话内容都无法从 Tab 或读屏访问。
- 背景 inert 范围不能包含当前抽屉自身；卸载、切页、异常时必须恢复原先属性。
- 背景可保留只读输入摘要以展示来源上下文，但不保留可点击的确认按钮。一个可见工作面仍只有一个 primary。

### 10.5 创建期间

点击开始后继续显示同一个抽屉实例，保留位置和清单，footer 主按钮变成「正在创建会话…」。

- 主按钮 disabled，保留 spinner；返回修改、关闭、Escape 和遮罩关闭均不可用。
- footer 增加一句“正在创建会话，请稍候”；阻止关闭时以状态文字解释，不弹二次确认。
- 创建期不能修改 preview、输入或 exclusions。
- 不使用覆盖整个抽屉的大 spinner 遮住待核对内容。
- 原操作元素被禁用时，把焦点稳定移到状态区或抽屉标题；焦点陷阱每次按键获取当前可聚焦项，不缓存启用时列表。
- 超过 15 秒提示“创建用时较长，正在确认交接结果，请勿重复开始”；不伪造目录/指令发送的细分步骤。
- 沿用 180 秒等待上限；超时不是“创建失败”的权威事实，进入第 11 节可恢复状态。

## 11. 页面 D：交接失败、打开失败与再次进入

### 11.1 按实际事实分三类

| 类别 | 标题 | 解释 | 主动作 | 次动作 |
| --- | --- | --- | --- | --- |
| Host 确认没有创建会话，且本次处理已终止 | 未能创建估值会话 | 资料与条件已保留 | 重试创建 | 返回修改 |
| 已有 parentSessionId，指令未接受 | 会话已创建，交接尚未完成 | 重试向同一个会话发送，不新建 | 重试交接 | 打开估值会话 |
| 交接成功，导航失败 | 估值会话已创建，未能自动打开 | 估值交接已完成 | 打开估值会话 | 无需创建重试 |

结果未知单独处理：

> 尚未确认会话是否创建。恢复交接会复用本次请求，不会另建一轮。

主动作「恢复交接」，复用当前 previewId、handoff requestId。不能仅因为 Client 没收到 sessionId 就给“尚未创建”或“返回修改”。

### 11.2 失败界面

采用短结论、具体原因、下一步动作的一层局部状态区域。正常失败不铺满红色背景；左侧轻错误线和图标即可。

错误字段来自 Host 安全映射，不直出原始 Error.message、私有路径、网络响应、命令或 URL。员工可处理的原因给动作；系统原因说明“请重新尝试；持续失败请联系管理员”，不要让员工安装插件包内程序。

### 11.3 返回修改的边界

只有 Host 明确告知会话没有创建且不会再继续创建时，handoff-failed 才可返回草稿。未知结果和已有会话的失败必须保持冻结输入，先完成同一轮恢复。

当前 `backToEdit` 拒绝失败态，因此不能只添加新文案。必须修改状态机与 Host 结构化回执，写测试证明“可返回”和“不可返回”两类边界。

### 11.4 成功与导航

- 成功提示用 `role=status`：“估值会话已创建，正在打开…”。
- 即刻调用原生 openSession，不增加固定停留 1–3 秒、不做庆祝动画、不自动滚到成功卡片。
- openSession 失败只重试导航，不再次调用 start。
- 当页面已经被员工切走，后台完成交接只能记录一次恢复入口；不强行把员工从另一个正在操作的页面拉走。是否自动导航由“当前页面仍在前台 + 当前交接 generation”判断。
- 返回房地产时可显示“最近创建的估值会话”中性链接，不读取执行进度或交付件；一次链接来自本次 Client 内存记录即可。
- 新草稿不继承上一轮文件与条件；失败恢复入口仍指向原有轮次，不能被新建覆盖。

## 12. 状态机与跨页恢复规格

### 12.1 可观察状态矩阵

| phase | 正文 | 编辑 | 唯一主动作 | 允许离开 | 返回本页 |
| --- | --- | --- | --- | --- | --- |
| checking-auth | 来源检查 | 否 | 检查中 disabled | 是 | 旧请求作废后重新检查 |
| auth-blocked | 来源状态与动作 | 否 | 重新检查 | 是 | 恢复站点事实，按需重新检查 |
| draft | 输入工作面 | 是 | 确认 | 是 | 保留本次草稿 |
| preparing-confirmation | 原输入 + 准备反馈 | 否 | 准备中 disabled | 是 | 旧准备作废，回草稿，不永远 pending |
| confirmation | 只读抽屉 | 否 | 开始估值 | 关闭抽屉后可离开 | 保留同次有效预览或返回草稿 |
| creating-session | 同一个抽屉 | 否 | 创建中 disabled | 抽屉内不允许关闭；宿主离开不取消交接 | 获取同一次权威回执 |
| handoff-failed | 结构化失败区 | 按创建结果 | 重试创建/重试交接/恢复交接 | 是 | 保留同次 requestId 与结果 |
| handed-off/openFailed | 导航失败区 | 否 | 打开估值会话 | 是 | 保留会话入口 |
| handed-off/成功离开 | 原生会话 | 不适用 | 不适用 | 是 | 新草稿 + 最近会话入口 |
| stale-host | 版本不匹配说明 | 否 | 有实际服务才提供重启入口 | 是 | 未重启前仍禁止发新业务请求 |

stale-host 不能被迟到的 scan、preflight 或 start 回调改回正常态。未收到有效兼容握手时不继续启动。

### 12.2 生命周期原则

为请求分别管理生命周期，而不是用一个 generation 管全部异步行为：

- 来源检查：页面可取消，晚到响应不改变当前页面。
- 文件选择器：受选择 epoch 控制；离开后选取结果不得追加到新页面。
- 扫描：受输入版本控制；旧清单不能覆写新范围。
- 预览准备：受输入版本与 prepare requestId 控制；返回修改后预览失效。
- 登录任务：Host 管理；页面离开不擅自终止；回来可按 jobId 读取现状。
- 会话交接：Host 事务管理，不能因页面卸载中断；Client 去掉显示定时器不丢失恢复句柄。
- 导航：仅当前可见页面自动打开；过期回调只记录恢复入口。

至少将页面可取消请求和持久交接事务分开。不要为这些任务引入通用工作流框架；使用 focused controller 与现有 operation 即可。

### 12.3 草稿与展示记忆

本期在 controller 与页面专属 UI memory 中保存：选择入口、排除项、方法、日期、补充要求、文件夹展开状态、查看全部状态、返回焦点和草稿滚动位置。

不把原始绝对路径、补充要求或文件内容写入 localStorage、通用日志或模型消息。重启后的草稿持久化属于独立产品能力，本期不自动增加；文案“已保留”限定当前页面会话，不宣称重启也能恢复。

### 12.4 预览过期与文件变化

- 核对使用归档副本的事实；源文件后来变化，不自动更换本次归档输入。
- preview 过期或归档校验失败，显示“核对信息已失效，请返回修改并重新确认”。
- 尚未创建会话时允许回草稿，保留原选择与条件。
- 已开始交接后先按同一请求恢复权威结果，不能直接回草稿生成第二个项目。
- 不在核对页每秒显示倒计时；检查有效性由 Host 开始操作时完成。

## 13. 提示文案与反馈系统

### 13.1 文案原则

用“发生了什么 + 影响 + 可以做什么”。不使用“digest 校验失败”“protocol 35 不一致”“provider gate unavailable”等内部词作为主说明。

“读取清单”与“解析资料内容”区分；“登录已确认”与“页面验证完成”区分；“会话已创建”与“交接已接受”区分；“页面等待超时”与“Host 创建失败”区分。

| 渠道 | 使用场景 | 持续时间 |

必要错误不只用 3 秒 toast；不要为同一件事同时弹 toast、写 alert 和改变页面标题。

### 13.4 Tooltip

只用于补充图标按钮的名称、完整文件名和额外解释，不承载“为什么不能启动”等必要信息。

鼠标 hover 约 400ms 后出现；键盘 focus 同样可见；Escape 关闭。关键说明可在正文阅读，触屏没有 hover 也不丢失。不要混用 title 与自定义 tooltip 导致双层浮窗。

## 14. 动效与微交互详细规格

### 14.1 动效表

| 元素 / 触发 | 动画 | 时长 | 曲线 | 减少动画模式 |
| --- | --- | --- | --- | --- |
| 按钮 hover | background-color/color/border-color | 120ms | ease-out | 即时 |
| 按钮 active | 控件底色加深 | 80–120ms | ease-out | 即时 |
| 方法选中 | 底色与描边变化；勾选同步 | 160ms | ease-out | 即时 |
| 资料新增 | 新行 opacity 0→1，translateY(4px)→0 | 160ms | `--crwu-ease` | 无位移，直接出现 |
| 单项移除 | 行 opacity 1→0；结束后删除结构 | 120ms | ease-out | 直接删除并宣布结果 |
| 文件夹展开 | 内容立即占位，子内容轻淡入；箭头 rotate | 120–160ms | ease-out | 即时展开 |
| 状态区替换 | 新文字轻淡入；容器最小高度预留 | 120ms | ease-out | 即时 |
| 抽屉进入 | translateX(20px)→0，opacity .85→1 | 200ms | `--crwu-ease` | 即时 |

默认不使用按钮 scale，以免办公界面频繁晃动。连续旋转只用于真实等待，不能用在已登录图标或装饰背景。

### 14.2 结构变化与布局

- 不动画 width、height、max-height、top、left 或 grid 行高；避免重排型折叠动画。
- 展开结构允许立即改变布局，视觉上用子内容 opacity 和箭头旋转表达，不宣称“高度动画不会重排”。
- 新增/移除行后的布局变化只发生一次，不做整个列表的弹簧重排。
- 超过 8 个新增文件，不逐行延迟入场；整组一次淡入，避免用户等几秒。
- 扫描刷新不让整个工作面反复淡入；只改变受影响区域。
- 抽屉背景上不添加 transform/filter，因为这可能改变 fixed 浮层的 containing block。
- 动画结束按 transitionend/animationend 管理，并保留短兜底定时器；卸载时所有监听与定时器释放。
- reduced-motion 下不得仍等待 150ms 才关闭；状态、焦点与视觉呈现同步完成。

### 14.3 等待时间设计

| 时间 | 反馈 |
| --- | --- |
| 点击当帧 | 状态与按钮同步变化，禁止重复提交 |
| <300ms | 保留原内容，轻量局部 loading；不强制闪大骨架 |
| ≥300ms | 来源检查显示骨架/状态；扫描与准备显示明确说明 |
| ≥15s | 增加长等待说明与此阶段真正可用的动作 |
| 到阶段超时 | 可恢复界面；错误不得宣称未证实的创建事实 |

不显示假的完成百分比、倒计时或“预计 10 秒完成”。仅 Host 有真实分阶段事实时，才能展示那一阶段；本期默认不扩展进度 API。

## 15. 实现边界、组件分工与必要契约扩展

### 15.1 组件分工

沿用现有模块结构，优先在现有组件内提炼明确小组件，不新增通用框架。

| 所有者 | 负责 | 不负责 |
| --- | --- | --- |
| ReportEvaluationPane | 根据 phase 装配、显示区域、连接 controller | Host 业务判断、重复导航树 |
| ValuationAuthGate | 来源事实、登录/验证任务、错误与动作 | 自己推算 authenticated 或 gate |
| ValuationIntakePane | 资料范围、输入、底栏 | 文件系统访问、目录遍历、业务分析 |
| MaterialSelectionList（可提炼） | 入口/子文件层级、状态、移除与恢复 | 自己算最终 fileCount |
| ValuationConfirmationDrawer | 只读条件与文件元信息、创建反馈 | 规则预检、运行进度、结果 |
| ValuationHandoffFeedback（可提炼） | 结构化失败类型与安全恢复动作 | 从“没有 sessionId”猜测未创建 |
| controller / model | 页面状态、请求版本、输入锁、恢复 | 直接读本地文件或执行 shell |
| SideDrawer | 浮层框架、可配置关闭、焦点、隔离、动画 | 估值领域 phase 判断 |
| Host operations | 扫描/排除/归档/验证窗口/交接回执 | Client 展示记忆 |

### 15.2 SideDrawer 扩展

建议新增或等价实现：

- `closeDisabled?: boolean`：创建期间统一禁止 X/Escape/遮罩关闭。
- `initialFocus?: 'heading' | ref`：估值以标题为默认；其他抽屉保持既有行为。
- `onAfterClose?: () => void` 或由父层管理 presented/closing：关闭完成后卸载和焦点返回。
- 焦点查询按实际可聚焦状态更新，不缓存打开瞬间列表。

所有新增参数默认保持旧调用兼容。报告审核抽屉、授权弹框和其他模块不能因为估值设计变成无法关闭或焦点反复跳动。

### 15.3 文件扫描与排除

当前 wire 不返回实际文件候选，必须明确扩展；建议契约形状如下，字段名可与现有共享类型对齐，语义不可省略：

```ts
type MaterialScopeInput = {
  paths: string[]
  excludedPaths: string[]
}

type MaterialScanView = {
  ok: boolean
  items: SelectionRootView[]
  files: MaterialCandidateView[]
  skipped: SkippedMaterialView[]
  fileCount: number
  readableCount: number
  skippedCount: number
  overLimit: boolean
  truncated: boolean
  limit: number
}
```

要求：

1. scan 与 intake 都接受同一受控排除范围。
2. Host 校验排除项属于当前入口范围，不能让 Client 借此读任意路径。
3. 排除按 canonical/realpath 去重，符号链接和特殊文件策略不放松。
4. 候选完整路径仅在本机 Host/Client 回显，归档后模型只接收项目内相对路径。
5. 明细、份数、跳过、完整性和预览必须一致；不能只过滤 UI list。
6. 字节归档依旧按确认契约与摘要验证，不从新的 UI 范围绕过已有完整性检查。

### 15.4 验证窗口操作

建议增加受控 operation，例如 `valuation-browser-open-verification({ siteId })`。此名称是待实现提案，当前不存在，不应在文档或代码中宣称可调用。

Host 根据 siteId 和当前挑战事实取可信页面、复用同一浏览器 profile；Client 不接受任意 URL、profile 路径或命令。返回 opened、任务状态和安全错误；开启窗口本身不表示验证已经完成。

### 15.5 交接结果语义

已有 `ok / errorKind / parentSessionId / dispatchAccepted / reused` 应继续复用；为了安全提供“返回修改”，需补一个权威创建判据：

```ts
type CreationDisposition = 'not-created' | 'created' | 'unknown'

type HandoffRecoveryView = {
  creationDisposition: CreationDisposition
  retryable: boolean
  // Existing session and dispatch receipt fields remain authoritative.
}
```

Host 只有确认本次处理已终止且没有已建/在途会话时才返回 not-created。网络超时、返回丢失和未知异常一律 unknown，Client 无权自行改成 not-created。

恢复优先通过现有 `valuation-start` 同一请求幂等重试读取/完成原事务，不新增估值运行期 status 轮询。若必须增加查询操作，限定为单次交接回执恢复，不能扩展成执行进度监控。

请求 ID需要跨 controller 重建避免碰撞。当前 Client 的简单计数在新 controller 可能重置，Host 幂等键必须同时绑定 preview/project/scope；DSH 实施时核对已有持久记录的实际键，不盲目更换事务规则。

### 15.6 协议、文档与版本

- 纯 CSS、文案或内部组件拆分不因自己引入新 phase 名而改 wire。
- files/exclusions、验证操作、交接结构字段等跨 Host/Client 行为变更必须升级 `WORKBENCH_PROTOCOL`，同步 shared contracts、wire validators、operations 注册和 frozen inventory。
- 新动作需要 Host broker 校验；不能只靠按钮 disabled 作授权边界。
- 活跃 UI 文档与 PRD更新到实际完成行为；功能改变追加插件 changelog。
- 不手写 lib/client.js、package tarball 或运行 profile 文件；源码 gate 通过后由正常构建生成。
- 不自动发布或提交。本稿不分配版本号，不把新版本写成已发布事实。

## 16. 响应式、短高度与主题

响应式以面板 container 宽度为主；抽屉宽度以宿主视口为主。不能拿整窗 1440px 推断正文也有 1440px。

| 可用宽度 | 主布局 | 方法 | 清单 | 操作栏 |
| --- | --- | --- | --- | --- |
| ≥900px | 单工作面，最大 1120px | 四项一行 | 紧凑行，完整元信息；最多 320px 内滚动 | 摘要左、按钮右 |
| 560–899px | 单列，padding 20–24px | 四项一行或换行 | 名称 + 次行元信息 | 保持同一行，原因可另行 |
| 400–559px | 单列，padding 16px | 两列 | 路径换行；不嵌套列表滚动 | 摘要上一行、主按钮右侧 |
| <400px | 单列，padding 12px | 单列 | 名称与状态上下排，动作独立 44px 槽 | 主按钮全宽，辅助原因在前 |

补充规则：

- 375px 宽：添加文件和文件夹允许换行，不能挤成两枚小字按钮。
- 768px/1024px/1440px 宿主窗口都需要测试实际正文宽度。
- 500px 窄正文即使宿主 1920px 也使用窄面板布局。
- 视口高度 600px 时标题与操作栏仍可见，正文滚动；输入聚焦不被底栏完全遮挡。
- 长文件名、Windows 路径、UNC 路径、长无空格文本必须不撑宽整个页面。
- 正文不出现水平滚动条；导航胶囊超宽时可在自身横滚，这与正文溢出分开。
- 深色与浅色所有页面都使用同一组件与 token；不复制两套组件树。
- 高对比度/forced-colors 时保留原生 outline、边框、文字与状态标记，不只用 box-shadow 表示焦点。

## 17. 可访问性与性能

### 17.1 可访问性约束

- 所有输入有持久 label；aria-label 可补充，不能拿 placeholder 代替可见标签。
- 关键文字对比至少 4.5:1；可识别的控件边界与状态图形按用途检验至少 3:1。
- 图标按钮可读名称包含对象，如“移除：权属资料.pdf”，而不是只叫“关闭”。
- 44×44px 是本项目体验标准；WCAG 2.2 AA 的最小目标条目通常为 24×24px并有例外，不能把项目标准误说成全部 AA 法定要求。
- 键盘顺序跟随视觉顺序；方法使用原生单选组；Tab 遍历、箭头选择、Escape 均可完成任务。
- 文件移除后焦点落在下一文件移除按钮；最后一行移除则回上一个，清空则回添加文件。不能掉到 body。
- 资料区一个轻 live region 宣布“已纳入 N 份，跳过 M 项”；不要每个文件同时 role=status。
- 错误区域 role=alert 仅在新错误出现时播报一次；一般说明无 live 属性。
- pending 使用 aria-busy 和持久状态文字；spinner 装饰 aria-hidden。
- 弹窗背景不可访问、焦点有入口与返回、退出后无遗留 inert。
- 底栏、sticky 标题和浮层不能完全遮挡键盘焦点；滚动目标设置相应 scroll-margin。
- 200%缩放及窄宽 reflow 时仍可操作；不能强制单行把按钮文字截掉。

上述标准与行为以 [W3C 文字对比说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)、[模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) 和 [焦点不被遮挡说明](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html) 为外部核对依据。

### 17.2 性能边界

- 最多 30 份纳入文件，无需新增虚拟列表库。
- 大量 skipped 项展示摘要与按需展开，避免误选巨型目录产生数千 DOM行。
- 预览只读取元信息与归档，不调用模型、不下载整套知识、不抓案例。
- 所有请求只由实际操作触发，不因 hover、动画或重渲染重复请求。
- 不为了本稿增加图标包、动效库、react-dom 或外链字体；client 保持已有注入式单 bundle。
- 动画尽量 transform/opacity；色彩过渡只作用于少量控件。
- 单次动作无明显主线程冻结；若性能分析显示长任务，再针对实际慢点调整，不先做全模块 memo 化。
- 成功交接后清理页面定时器与请求；不运行 valuation-status/result 周期请求。

## 19. DSH 实施顺序与交付清单

### 19.1 第一阶段：流程恢复与状态正确性

对应 UX-01–07、17。

1. 复查当前工作区，确认改动来源与最近 UI 规范。
2. 加入创建期间抽屉持续显示、waiting-user、登录错误可见、切页恢复和失败返回边界的失败测试。
3. 修显示判据、job 收窄、任务刷新、错误呈现、请求生命周期。
4. 增加 Host 权威 creationDisposition 与受控验证窗口操作，同步协议。
5. 创建期间阻止关闭，失败提供真正可用的恢复动作。

阶段交付：所有 P0 用例通过；一个父会话、范围冻结和重试身份保持正确。

### 19.2 第二阶段：资料范围闭环

对应 UX-08、09、14。

1. 扩展估值 scan/intake 范围与回显，复用扫描服务已存在的 exclusions。
2. 入口与实际文件层级、文件夹图标、完整状态映射、跳过项和截断提示。
3. 逐文件排除、文件夹移除、撤销、重新纳入和重扫。
4. 验证 scan / preview / 实际归档字节一致，不让 UI 假排除。

阶段交付：文件夹内文件能看见、能移除，预览和归档范围一致。

### 19.3 第三阶段：视觉与微交互

对应 UX-10–13、15、16、18。

1. 主次按钮统一，必要文字颜色与输入边界对比度。
2. 单层工作面、分区间距、紧凑日期、补充要求、底部操作栏。
3. 核对键值摘要、文件元信息、路径复制、UTC标记、换行呈现。
