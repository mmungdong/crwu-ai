# CRWU 审核报告可读性与定位体验优化设计

## 背景

当前未提交改动已开始收紧 `problemDescription`：问题描述改为“首句结论 + 多行明细”，并在页面中分层显示。方向正确，但现状仍有四个影响员工处理效率的问题：

1. `summary.narrative` 仍以长段文字直接占据首屏，审核人员难以快速抓住处理顺序。
2. 问题卡片中的 `locationSummary` 仍是一行弱化文本；文件、工作表、单元格或页码没有形成明显的定位入口。
3. “需要人工确认事项”位于外部数据核验、人工复核对照和评分卡之后，审核人员无法连续看完待处理事项。
4. 当前校验常量声明明细至少两行，但实现只拦截零行明细，单行明细会错误通过。

## 目标

- 员工进入报告后，先看结构化结论，不必先读长段总结。
- 每个问题卡片清楚回答“到哪个文件、哪个位置核对”。
- “AI 检出的问题项”和“需要人工确认事项”连续呈现。
- 保留当前 AuditResult JSON 的兼容性，不新增业务结论或重复维护字段。
- 修正现有问题描述校验与规范不一致的问题。

## 不在本次范围

- 不改变审核判断、问题排序和严重程度算法。
- 不新增或迁移 AuditResult 字段。
- 不改造人工复核对照、评分卡或外部数据核验的业务规则。
- 不由 renderer 生成新的业务判断句子。

## 方案

采用“方案 A 的兼容性与强定位 + 方案 B 的结构化总结”。所有新增展示都从现有结构化字段确定性推导，完整原文仍可追溯。

### 1. AI 审核总结

首屏保留现有结论状态和指标卡，并新增三条式“处理摘要”：

1. 高风险问题：显示数量，并列出按现有问题排序后的前若干个问题标题；超出部分显示“另 N 项”。
2. 中低风险问题：显示数量，并列出前若干个问题标题；超出部分显示“另 N 项”。
3. 人工确认事项：显示数量，并列出前若干个人工确认标题；超出部分显示“另 N 项”。

摘要只组合受控标签、计数和输入中已有的标题，不编写新的业务句子。`summary.narrative` 完整保留，但移动到“查看完整 AI 审核说明”的折叠区，打印时仍展开，避免信息丢失。

没有对应内容的摘要组显示明确空态或省略，不制造“0 项”的视觉噪声。若三组均为空，仍保留现有总体结论和指标卡。

### 2. 问题位置

每张问题卡片在标题和元信息之后显示独立的“问题位置”定位面板：

- `locationSummary` 作为主要定位说明，使用高对比标题和正文，不再作为弱化的一行灰字。
- 从 `materialEvidence[]` 读取 `displayName` 与 `locator`，去重后逐行展示为“文件 → 具体位置”。
- 不使用 `recommendedEdits[]` 充当问题证据位置，避免把“去哪里修改”混成“问题在哪里”。
- 动态内容继续统一转义；缺少材料定位时仍显示 `locationSummary`，不生成虚假位置。
- 桌面、窄屏和 A4 打印均保持完整可读，不依赖颜色表达含义。

### 3. 章节顺序

正文和侧栏目录统一调整为：

1. AI 审核总结 / 本次 AI 审核结论
2. AI 检出的问题项
3. 需要人工确认事项
4. AI 外部数据核验结果
5. 人工复核对照
6. AI 审核表现评分卡
7. 本次审核依据
8. 审核范围与未检查项
9. 专业审核轨迹
10. 文件追溯信息

这样审核人员可以一次看完全部需要处理或确认的事项，再阅读核验、评分和追溯内容。

### 4. 员工话问题描述

保留当前未提交改动中的“两段式”设计，并补齐以下一致性要求：

- 首句一句话说明问题是什么，技术坐标放入明细。
- 明细必须为 2–4 行；实现按常量实际校验下限和上限。
- 每行保持短句，并至少包含可核对的文件或位置线索。
- 规则编号、知识库路径、内部代号和绝对路径继续禁止出现在员工交付内容中。
- 页面继续以“突出首句 + 逐行明细”呈现，不把内容重新拼成长段。

## 组件边界

- 校验层：只负责问题描述格式、长度、敏感内容和定位线索门禁。
- 渲染层：新增处理摘要、问题位置面板和章节换序；只组织已有事实，不改写业务内容。
- 模板层：提供摘要列表、位置面板、响应式和打印样式。
- 文档层：同步送达规范、脚本说明、Skill 入口、样例和变更记录。

## 测试设计

按测试先行实施：

1. 新增失败测试，证明单行明细必须被拒绝。
2. 新增失败测试，证明长 `summary.narrative` 默认不再直接显示，而是位于折叠区。
3. 新增失败测试，证明结构化摘要来自现有问题标题、严重程度和人工确认标题，并正确处理截断与空态。
4. 新增失败测试，证明问题位置面板展示 `locationSummary` 及去重后的材料文件和 locator，且动态文本被转义。
5. 新增失败测试，证明正文与侧栏中“需要人工确认事项”紧跟“AI 检出的问题项”。
6. 新增打印和窄屏断言，确保摘要、定位面板和章节顺序可读。
7. 运行交付脚本测试、相关技能族契约测试、样例 validate/render、`git diff --check` 与技能自洽性门禁。

## 版本与兼容性

- AuditResult 不新增字段，`schemaVersion` 保持 1.x。
- renderer 行为变化，`RENDERER_VERSION` 从当前未提交改动的 `renderer/1.2.3` 提升到 `renderer/1.2.4`。
- HTML 送达规范从当前未提交改动的 v1.3 提升到 v1.4。
- 旧 JSON 若已满足本轮问题描述写法约束，可直接渲染；不需要数据迁移。

## 验收标准

- 首屏不再默认展示长段 `summary.narrative`。
- 三条式摘要能让审核人员看出高风险、其余问题和人工确认的处理顺序。
- 每个问题卡片都有明显的问题位置面板，至少保留 `locationSummary`，有材料证据时显示文件和 locator。
- “需要人工确认事项”在正文和目录中都紧跟“AI 检出的问题项”。
- 单行明细不能通过 `problemDescription` 校验。
- 所有相关自动化测试和仓库门禁通过，且不修改或删除用户现有的无关改动。
