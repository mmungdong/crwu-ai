# 给 DSH：黑白底色、蓝色操作与公共表单组件重构

> 交接快照：2026-10-15。本文件整合用户最新修正，取代此前红色氛围、冰蓝铺底及原生表单控件的视觉候选。已有估值业务行为继续有效。

请重做中瑞工作台的公共控件与页面视觉。用户明确要求：按钮统一蓝色，输入框、下拉框及其选项、日期选择器都要美化，并抽成公共组件，保持整个工作台风格一致。浅色与暗色主题都采用清晰的黑白灰层次，蓝色负责操作与交互。

这轮要交付的是一套可复用的公共 UI 组件及其页面接入。前两版仅调整主色和背景仍未解决控件造型与系统弹层割裂的问题，本轮必须把控件的展开态、交互态和主题配对一起完成。

## 1. 最新视觉目标

- 浅色：浅灰应用底、白色工作纸与输入表面、接近黑色的主文字、蓝色操作。
- 暗色：近黑应用底、深灰工作纸、更亮一层的输入表面、浅色文字、蓝色操作。
- 中瑞红保留在真实品牌标识；普通操作与 AI 入口使用同一蓝色系。DeepSeek 小鲸鱼保持现有原始图形与颜色。
- 页面层次来自留白、字重、边界和少量阴影。移除前两版大范围冰蓝/粉灰背景、发光边框、渐变按钮和与阅读无关的装饰光感。
- 控件造型推荐“轮廓输入”：完整细边框、适量内距、约 10px 圆角、清楚的焦点。柔底输入可用于少量紧凑场景，但同一表单选择一种造型。
- 一张工作纸、一条纵向任务流。文件区后立即是资产类型与评估方法两个必填项；可选条件与信息获取辅助依次在下。

## 3. 所有普通按钮统一蓝色，但保留层次

| 组件变体 | 视觉与用途 |
| --- | --- |
| `primary` | 实心蓝底、配对白字；核对资料、开始估值等当前主操作。一处任务区只保留一个主操作。 |
| `secondary` | 蓝字、细蓝边、表面底；选择文件、返回修改等明确的次级操作。 |
| `soft` | 蓝字、低浓度蓝底；检查状态、登录及轻量辅助动作。 |
| `text` | 蓝字、透明底，hover 低浓度蓝底；清空、复制、轻导航。 |
| `icon` | 对应 secondary/soft/text 的图标按钮；命中区、焦点和可访问名称统一。 |
| `danger` | 只用于真正的破坏性语义，沿用明确的错误色。普通移除当前选择项无需冒充高危操作。 |

`loading` 保留原按钮宽度和文字语义并阻止重复触发；`disabled` 使用清晰中性禁用态与可读原因。统一默认、hover、active、focus-visible、loading、disabled，避免页面自己再加灰色按钮覆盖。

默认表单控件约 42px 高；主按钮约 40–42px，高度与相邻输入对齐；紧凑工具按钮可约 32–34px。触控时有效命中区至少约 44px，相邻命中区互不覆盖。字号以 13–14px 为主，窄面板编辑控件使用 16px。

## 4. 公共组件包如何组织

本轮先做**插件包内的公共 UI 组件库**，供估值、审核和环境页面共同引用。统一导出、统一样式、统一 token。沿用现有构建和依赖，不增加独立 npm 发布链或另一份 UI 运行时。

建议结构如下，可按仓库现有约定调整命名：

```text
src/client/ui/
  components/
    Button.tsx
    IconButton.tsx
    FormField.tsx
    TextInput.tsx
    TextArea.tsx
    Select.tsx
    DatePicker.tsx
    Popover.tsx
    date-value.ts
    index.ts
  styles/
    button.ts
    field.ts
    select.ts
    date-picker.ts
    popover.ts
    drawer.ts
src/client/styles/tokens.ts
src/client/styles/bundle.ts
```

- 复用 `ui/primitives.tsx` 中已有 `Button` 的行为与 busy/禁用说明；需要迁移时提供薄重导出或兼容适配，最终实现只有一份，删除或收敛页面私有按钮样式。
- 现有 `modules/report-evaluation/ui/SingleSelect.tsx` 已实现定位、键盘、关闭动画与单弹层协调，先提取可复用部分。它目前导入估值 `V` 样式、生成 `crwu-valuation-*` ID、使用估值测试属性，必须解除业务绑定后才能算公共组件。
- 业务页面不直接维护浮层坐标、选择器焦点、日历月份或重复的样式类。页面提供值、选项和业务回调，公共组件负责通用交互。
- 公共组件不包含“房地产”“收益法”“链家”等业务文案或门禁。显示哪些选项、是否必填、选项是否合法仍由业务合同与状态机决定。
- 样式仍由唯一 `styles/bundle.ts` 装配、现有 installer 注入，限定 `data-crwu-scope="workbench"`。复用 `ui/styles/button.ts` 等所有者文件，避免两份同名规则竞争。
- Client 的依赖与 Host/Client 边界保持仓库约定，只使用现有允许的 React 运行时。视觉参考 Ant Design 不代表本轮接入 Ant Design、ReactDOM 或新的 CSS-in-JS 运行时。

## 5. 公共组件最小合同

| 组件 | 必要能力 |
| --- | --- |
| `Button` / `IconButton` | variant、size、disabled、loading、图标、可访问名称、禁用原因关联、焦点与按钮 type。普通 form button 不意外提交。 |
| `FormField` | label、required、hint、error、控件 ID 与描述 ID；统一标签间距、错误位置、`aria-invalid`/`aria-describedby`。 |
| `TextInput` | 受控值、placeholder、前后缀图标/动作、可选清空、disabled、readonly、error、blur/change；兼容中文输入组合态。 |
| `TextArea` | 与 TextInput 同源；受控值、字数限制/计数、适量自适应高度，长内容不顶破工作面。 |
| `Select` | 受控值、placeholder、options、disabled、required、error；每项可带短说明和 badge；空值与已选值明确区分。 |
| `DatePicker` | 日历选日、手动输入、清空、显式“今天”、年月定位、disabled/readonly/error、可选日期范围；输出纯日期字符串。 |
| `Popover` | 锚点、开关、宽度策略、安全边距、翻转/位移、层级、外部点击、Escape、焦点恢复、关闭动画与资源清理。 |

值变化统一由 `onChange` 回调返回；公共组件不擅自选择第一项或默认今天。失焦和错误显示时机由 FormField 与业务表单协作，不在初次空表单显示满屏红字。

每个组件实例有独立稳定 ID。多页面、多个工作台挂载点或两个同名 Select 同时存在时，`label`、listbox、option、dialog ID 不冲突。通用协调状态归属正确的 UI 挂载边界，不让一个页面卸载破坏另一处弹层。

## 6. 输入框、下拉框和选项的细节

- 输入框与 Select/DatePicker 同高、同圆角、同内距、同边界。白底模式保持完整轮廓；hover 边界略增强，focus 明确蓝边与约 3px 柔和 ring。placeholder 比值弱，但保持可读。
- 文本、选中值、图标共用一条基线。左侧图标只用于真正帮助识别的字段；图标/清空按钮不能挤压输入或覆盖文字。
- Select 的触发器由“当前值/占位 + 统一 chevron”构成。展开时箭头轻转，浮层与触发器匹配宽度，约 6–8px 间距，约 12px 圆角与轻阴影。
- 选项主标题约 13–14px，说明约 11–12px；行内留白充足。当前项浅蓝底加勾；活动项 hover/focus 是独立状态；推荐 badge 轻量。禁止四周厚蓝框、每项单独卡片、超长解释挤满菜单。
- 所有方法保持可选；少量选项无需搜索框。选择后收起并正确回焦点，取消保留原值。
- 使用 combobox/listbox/option 语义；方向键、Home/End、Enter/Space、Escape、Tab 与字符定位行为完整。参考 [WAI-ARIA Combobox Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)，以浏览器和读屏验证实际效果。
- 统一的 Popover 处理滚动、resize、容器 transform/contain、视口边缘翻转。复用现有实测定位经验，切抽屉或切模块时关闭残留弹层，抽屉内弹层不越过当前对话框的层级与焦点边界。

## 7. 日期选择器需要真正替换系统外观

当前 `ValuationIntakePane.tsx` 仍有 `type="date"`，其内部格式、日历图标和弹层由系统绘制，与自定义 Select 无法一致。本轮替换成统一 DatePicker：文本输入与日历按钮组成一个完整控件，弹层也由公共组件负责。

### 外观与操作

- 默认显示“年-月-日”占位，选中后显示明确的 `YYYY-MM-DD`。右侧为统一日历图标，图标按钮与 Select 箭头区域对齐。
- 日历约 280–300px 宽，使用与 Select 相同的背景、圆角、边界和阴影。窄面板按可用宽度收缩，贴底时翻到上方。
- 顶部是清晰的年月标题及蓝色前后导航；支持直接定位年月，避免用户选择数年前日期只能连续点几十次。
- 周一到周日排列，星期标题弱化；日期等宽网格，hover 浅蓝、选中实心蓝配对文字。“今天”只用边界/小标识区分，不自动成为已选日期。
- 底部“清空”和“今天”均为蓝色文字操作。点击日期立即提交并关闭；不额外加一层无必要的“确定”。输入与清空均不自动开始估值。
- 既能点选，也能键入/粘贴日期。非法日期保留原文本并提示，不静默滚动成下个月，不擅自改成今天。

### 日期值与焦点

- 对外保持当前业务约定：`YYYY-MM-DD` 或空串。内部按年/月/日校验，纯日期不做 UTC/本地时间转换。不要用 `new Date('YYYY-MM-DD')` 再转本地展示造成偏一天。
- 验证闰年、每月天数与跨年；年份、月份定位只影响日历视图，真正选日才改变值。可选范围由调用者传入，公共组件不硬编码业务日期边界。
- 打开时焦点落在已选日；没有值则定位今天，只移动焦点，不写入表单。Escape 关闭并还原触发焦点，取消保留输入。
- 日历键盘支持左右移动一天、上下移动一周、月/年导航与选择。日期网格采用正确的焦点管理，不能让 Tab 依次走过 42 天。
- 使用相符的 dialog/grid 语义与明确标签；只有实际采用模态交互时才声明 `aria-modal` 并约束焦点。日期选择器在确认抽屉等场景中的嵌套焦点规则需验证。
- 可参考 [WAI 日期选择器示例](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/datepicker-dialog/)的键盘和焦点规则，按本产品中文格式及即时选择交互实现，不直接复制示例代码当生产组件。

旧注释中“不做自定义日历”的限制按本次用户明确要求更新；不因此改变“日期可选、不默认今天”的业务规则。

## 8. 页面接入与保留的业务要求

- 估值页的选择文件、文件夹、移除/撤销、检查/登录、核对/开始、返回/恢复/重试等动作接入公共 Button；正常按钮均使用蓝色系变体。
- 目的、价值类型、补充要求、资产类型、方法和日期全部接入公共 FormField 与控件，不再存在“某个原生 select/date 没有样式”的例外。
- 资产类型与方法均主动选择必填，新草稿为空；四方法开放，`auto` 不冒充用户选择。保持 Client/Host 枚举校验、成功预览完整性与冻结输入保障。
- 抽屉包含资产、方法、资料与辅助能力；输入条件只读，登录/验证按已有能力执行。未检查、未登录、未知和检查失败继续不阻塞估值。
- 保留文件数量上限、扫描与错误恢复、目录真实折叠、路径详情与短复制反馈、单会话幂等交接、退出内容保留、创建期间关闭锁定及结果未知恢复。
- 审核页、环境页与共有抽屉/菜单同步采用公共组件及语义样式。按区域迁移并回归，删除已替代的页面私有实现与样式，避免新旧两套长期并存。

## 9. 验证与交付

先补行为测试，再提取与迁移。使用现有 Node test、TS/TSX loader 与浏览器检查设施。公共组件至少覆盖默认、hover、focus、disabled、readonly、loading、error，以及以下有实际风险的场景：

1. 多个组件实例的 ID/标签与弹层互不冲突；卸载后监听、timer、观察器清理。
2. Select 键盘选择、Tab 退出、外部关闭、贴底翻转、不同包含块、长选项及 disabled 项。
3. DatePicker 空值、手输/点选/清空/今天、非法文本、闰年、月末、跨年、年月定位、键盘、取消与焦点；不同系统时区不改变纯日期值。
4. 页面原有必填、准备、确认、交接、登录辅助非阻塞与恢复测试继续通过。

建立隔离的组件展示/测试 fixture，把 Button、Input、Textarea、Select、DatePicker、FormField、Popover 的全部状态放在一起检查，不依赖真实账号或用户业务资料。

真实浏览器验证浅/深两种宿主主题，375 / 500 / 768 / 1024 / 1440px 实际面板宽度、约 600px 短高度及减少动画模式。检查无横向溢出、浮层不裁切、日期可操作、底部按钮可达、焦点清楚、对比度合格。尤其检查暗色弹层没有突然变白、次级按钮没有残留灰色版本。

动效以 120–160ms 控件过渡、约 150ms 下拉、约 200/150ms 抽屉为起点；退出结束后再卸载。减少动画立即完成过渡，不额外等待 timer。
