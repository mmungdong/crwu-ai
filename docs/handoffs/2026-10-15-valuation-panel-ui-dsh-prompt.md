## 2. 页面结构与必填行为

采用一条从上到下的任务流。宽度受实际面板容器约束，内容最大宽度沿用 1120px，不把资料和表单拆成左右两个大栏。

┌──────────────────────────────────────────────────────┐
│ 估值资料                         选择文件  选择文件夹 │
│ 紧凑的选择区域、扫描反馈、文件/目录清单、数量摘要     │
│                                                      │
│ 资产类型 *                  评估方法 *               │
│ [请选择资产类型        ▾]   [请选择评估方法        ▾] │
│                                                      │
│ 补充条件 · 可选                                      │
│ 评估目的       价值类型       评估基准日              │
│ [          ]   [          ]   [                  ]    │
│ 补充要求                                             │
│ [填写其他估值要求……                              ]   │
│                                                      │

│ 就绪摘要 / 下一步提示                    [核对资料]  │

- 文件选择区域包含清单。两个必填项紧接其后，位于所有可选条件和辅助能力之前。长文件清单采用紧凑行、目录折叠和摘要，避免把必填项推到大量重复元信息后面。
- 面板内容宽度约 560px 及以上，资产类型与评估方法并排等宽；更窄时纵向排列。补充条件空间足够时三列，中间宽度两列，窄面板一列。以容器宽度判断。
- 可见标签使用“资产类型”“评估方法”并有统一的必填标记；控件和标签建立真实关联，声明必填及错误信息关联。其余条件继续可选。
- 新建草稿和开始新一轮时，两项都未选择；占位分别为“请选择资产类型”“请选择评估方法”。资产目前只有“房地产”，仍由用户主动选，沿用现有值 `real-estate`。
- 方法四项均可选：自动判定、市场法、收益法、成本法。自动判定是一个明确的用户选项，可显示轻量“推荐”，不能因此默认选中。说明可用“由 Agent 根据资料与知识库判断，可采用单一方法或组合方法”。
- 保留历史有效草稿中明确的 `auto` 值；新草稿空态与历史已选值分别处理。
- 初次进入不展示满屏红字。失焦、用户清空已填写值或触发下一步时，才在对应字段下面显示短错误。“核对资料”不可用时，附近显示当前最先需要完成的一项，例如“请选择评估方法”，并用 `aria-describedby` 关联原因。
- “核对资料”只准备预览、打开确认抽屉；抽屉主操作为“开始估值”。准备中原按钮显示“正在准备…”，创建中原按钮显示“正在创建会话…”。整条链路用词一致，不混用多个含义相同的“确认/提交”。

## 4. 下拉框需要完成的全部细节

资产和方法使用同一种单选下拉视觉与交互。当前仓库没有通用 Select；审核页是动作菜单，可以借鉴浮层位置、样式和关闭机制，表单选项仍用正确的选择器语义。

### 外观与状态

- 触发器：左侧当前值或占位，右侧统一向下 chevron；文字区域 `min-width:0`，长值截断但可获完整内容。placeholder、已选值、禁用状态能区分。
- 完整实现默认、hover、键盘 focus、展开、未选、错误、禁用；错误态文字解释原因，不能只把边框变红。推荐标记不抢当前选择的视觉。
- 选项：主标题清晰；方法可带一行短说明；当前选中用勾表示，键盘活动项有独立高亮。hover 和键盘活动态一致可辨，不让鼠标移出清除键盘选择位置。
- 浮层与触发器等宽，约 8px 间距、10px 圆角，使用现有 menu 背景/边界/阴影。选项单行至少约 40px，有说明时自然增高；最大高度约 240–280px，超出在选项区滚动。当前少量选项无需搜索框。
- 按视口可用空间向上/向下展开，四周留至少 8px 安全距离。靠右、靠底、正文已滚动、浏览器缩放后均不裁切。
- 避免浮层被表单 `overflow` 裁掉。复用现有允许的浮层挂载/定位模式，处理 scroll、resize、容器位置变化；抽屉打开前收起下拉。不得把浮层抬到抽屉上面或留在 inert 背景中。

### 键盘与焦点

- 用适合单选的 select-only combobox + listbox/option 语义，包含可访问名称、`aria-expanded`、`aria-controls`、`aria-selected` 和活动项管理；不要复制 `menu/menuitem`。
- Tab/Shift+Tab 在表单正常移动；Enter/Space 打开，方向键移动活动项，Home/End 到首尾，Enter/Space 确定，Escape 关闭并保留原值，Tab 关闭并继续正常焦点顺序。支持适合现有实现的字符快速定位。
- 外部点击关闭，点击当前选项正常关闭；取消不会把原值清空。关闭后按交互原因合理恢复焦点：Escape/选中回触发器，Tab 和外部点击尊重目标焦点。
- 同时只开一个下拉；卸载后事件监听、定位观察、动画定时器全部释放。
- 额外说明通过 `aria-describedby` 与控件关联；选项说明不重复播报成按钮名称的长段文本。

## 6. “信息获取辅助”应当轻、准、可操作

对外标题统一为 **“信息获取辅助”**，旁边轻标“可选”。说明：“用于辅助获取公开信息；未登录可继续估值。”它表达补充信息能力，不叫“案例来源”“来源门禁”或“必需能力”。真实估值证据里的“案例”概念及内部业务 Tool 名称按原语义保留。

区域始终有可见的紧凑摘要行；默认无需展开一张很高的卡片。链家名称、状态和当前可用操作直接可见，详细原因、检查时间及登录任务说明按需展开。避免把唯一的登录入口藏在难以发现的折叠层内。

| 真实状态 | 展示与操作 |
| --- | --- |
| 尚未检查 | “尚未检查”＋“检查状态”；页面初次挂载不自动探测。 |
| 检查中 | 局部轻量 loading＋“正在检查…”；不锁表单，不显示整页遮罩。 |
| 已登录 | “已登录”；显示最近检查时间，可“重新检查”。不把已登录说成所有页面都可访问。 |
| 未登录 | “未登录”＋“登录链家”；提示“未登录时将使用房天下、58 同城补充信息”。 |
| 未知 / 检查失败 | “暂无法确认”或准确的短原因＋“重新检查”；不能推断成未登录。 |
| 页面待验证 | 保留登录事实，显示“需要页面验证”＋“去验证”；完成后可重新检查。 |
| 登录进行中 / 成功 / 失败 / 取消 / 待验证 | 沿用现有真实状态与可取消/恢复行为，分别提供短反馈和下一步动作。 |

- 主工作面和抽屉复用同一 controller 状态与动作，展示可拆小型摘要组件；两个 UI 实例不能各自产生重复探测、轮询或登录任务。
- 进入房地产确认抽屉时，沿用现有独立检查一次的行为，立即展示抽屉内容及局部检查状态。检查结果必须能在抽屉里看到，未登录可就地登录。
- 未检查、未登录、未知、检查失败、登录进行中均不是估值启动门禁。业务已具备启动条件时，用户可以继续。
- 链家无覆盖或无足够匹配资料时，运行阶段保留安居客和 58 同城降级。UI 只说明已知事实，不在启动前伪造平台覆盖结论。
- 登录/验证在现有浏览器能力中完成，继续复用已有幂等与恢复机制。UI 不采集账号、密码或 Cookie，不展示命令、profile 路径、内部端点。
- `ValuationCapabilityArea.tsx` 当前可能把通用 `state.error` 当成能力错误再次渲染；按错误归属整理，避免文件校验错误也出现在链家区。

## 8. 动效要有具体实现和退出行为

统一使用现有 `--crwu-ease`；只对必要属性做 transition。下列时间允许小范围协调，以实际观感和减少动画设置为准。

| 交互 | 目标 |
| --- | --- |
| 控件 hover/active | 约 100–120ms 的颜色/边界变化；无整体缩放或布局跳动。 |
| focus | 约 120ms 的 ring/边界变化，键盘焦点清晰可见。 |
| 下拉展开 | 140–160ms 淡入，位移不超过 4px；chevron 约 120ms 旋转。 |
| 下拉关闭 | 100–120ms 淡出后卸载；关闭期间不能继续选择或保留隐藏焦点。 |
| 文件新增/移除 | 如需反馈，使用轻淡入/淡出；扫描结果批量出现时整体更新，避免 30 条依次飞入。 |
| 文件夹/详情折叠 | 箭头轻转，内容明确出现/消失；优先稳定布局，不对未知高度长列表做复杂高度动画。 |
| 抽屉 | 保留约 200ms 进入、150ms 退出及遮罩淡变。退出期间保留最后一份预览内容，结束后再卸载。 |
| 复制路径 | 成功文字就地出现，约 1.5 秒后恢复，不改变按钮/行宽，不抢焦点；失败给真实可执行提示。 |
| loading | 局部 spinner 与持久状态文字；任务耗时未知时不伪造百分比、进度条或成功阶段。 |

`prefers-reduced-motion: reduce` 下去掉位移、缩放和旋转，展开/关闭即时完成，卸载不额外等待动画定时器；loading 以静态图标和文字保持可理解。监听与 timer 在关闭、切模块、卸载时清理。不要只写 CSS 而让 React 在退出动画前卸载内容。

## 9. 状态、测试与浏览器验收

先为行为变化补有意义的失败用例，再实现。复用已有 Node test、TS/TSX loader 和 `install/browser-check.mjs` 的真实浏览器能力。视觉重构必须有真实 DOM、几何和截图验证，不能只断言源码包含类名。

必须覆盖：

1. 空资料、扫描中、扫描失败、部分排除、30 份资料、长文件名/长路径、同名不同目录、文件夹实际展开收起、移除及撤销。
2. 两个必填全空、只选资产、只选方法、四种有效方法、未知枚举、清空、返回保留、全新草稿重置、残缺/不一致的预览回包拒绝。
3. 每个下拉的鼠标与键盘流程、焦点恢复、窗口边缘翻转、滚动后位置、浮层层级、退出动画和监听清理。
4. 辅助区未检查/检查中/已登录/未登录/未知/失败/待验证/登录任务各状态；抽屉内可见结果和登录操作；辅助失败仍可进入准备与创建。
5. 抽屉长内容、全部未指定的可选条件、路径详情与复制反馈、关闭动画、创建中关闭锁定、慢等待、创建失败和会话打开失败。
6. 审核页及审核抽屉、现有操作菜单的回归，尤其共享按钮、浮层层级、抽屉及 shell 纸面变更。

浏览器验收以**实际可用面板宽度**为准：375 / 500 / 768 / 1024 / 1440px，浅色和深色主题；另测约 600px 短高度、浏览器缩放、宽窗口内的窄工作台。用几何断言确认：

- 页面无意外横向滚动，长文件名和说明不顶破布局。
- 两个必填项顺序正确、同高对齐，窄面板正常堆叠。
- 下拉选项完全可见，正文滚动、贴底打开、切换抽屉均无残留浮层。
- 鼠标点击与键盘走完“选资料 → 选两个必填项 → 核对 → 返回修改 → 再核对 → 开始估值”。
- 按钮/图标实际命中区至少约 44px；辅助命中区不覆盖临近文字或按钮。
- focus 可见、字段错误可关联、动态反馈能被读屏获知；减少动画时无额外卸载延迟。
- 抽屉底部操作可达、正文不被 footer 覆盖，背景不可聚焦，创建中四条关闭路径都锁定。

测试使用隔离 fixture 与模拟回包，不操作用户真实员工 profile、凭据或业务文件。涉及用户活跃 profile 的手工验收，按仓库约定由用户重启并确认，不将其用作自动化测试环境。

更新现有断言以体现本轮新要求：原生 select/radio 的结构断言、方法默认 auto、抽屉禁止能力信息、旧字段顺序等都需核对。尤其 `tests/unit/client/client-valuation-handoff.test.mjs:345–358` 和 `install/browser-check.mjs` 的相关断言不能继续固定旧交互。保留原本保障的边界行为。

按仓库门禁完成相关 Client/Host 测试、类型检查、构建和浏览器检查，最终运行 `make plugin-check`、`make docs-check`、`git diff --check`。先读取实际脚本参数，使用现有浏览器运行入口。失败需修复或准确说明原因与未验证范围。

## 10. 完成交付标准

完成后交付实现和简洁说明，至少包括：

- 改动文件及关键行为：必填与空态、文件下方布局、统一下拉、信息获取辅助、确认抽屉、动效与响应式。
- 同一 fixture 的改前/改后对照截图；至少包含浅色宽面板、深色宽面板、375px 窄面板、下拉展开、确认抽屉，以及 600px 短高度抽屉。截图使用测试资料，不含真实用户文件路径或员工信息。
- 实际运行的验证命令与结果，浏览器测试的面板尺寸/主题/减少动画模式，仍需用户手工确认的项目。
- 同步当前 UI 设计规范及产品行为文档中与本轮冲突的段落、注释和测试；日期化历史方案保持原文，按仓库规则标识其历史属性。

这轮验收重点是：估值面板从进入、填写、选择、查看辅助状态到确认交接，都与审核页具有统一且精致的观感，信息主次清晰，交互完整。只调整局部 margin、替换几段文案或提供静态示意图，不能视为完成。

保持当前工作区已有改动。交付源码和验证证据；提交、推送、发布及用户活跃 profile 的重启遵守仓库与用户授权约定。
