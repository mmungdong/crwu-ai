# 给 DSH：中瑞品牌科技感工作台视觉升级

> 交接快照：2026-10-15。用户已选择“品牌科技感：保留中瑞红，用层次和动效增强 AI 感”。本文件更新本轮视觉目标；旧交接文档保留为历史快照。

请把插件工作台升级成具有中瑞品牌辨识度的 AI 业务工作台。采用**中瑞红 + 深石墨文字 + 带暖色层次的底面 + 局部品牌光感**，覆盖工作台外壳、导航、通用控件、估值工作面、确认抽屉及其反馈状态。用户明确认为目前灰黑办公风过于素，需要可见的整体视觉变化。

继续完成此前估值面板功能要求。前一份[估值面板完整优化提示词](2026-10-15-valuation-panel-ui-dsh-prompt.md)中的必填、交接、键盘、响应式及辅助能力规则仍适用；它的“沿用灰黑主按钮”“只参考审核现有配色”等视觉方向由本文件更新。

## 1. 当前灰色来自哪里

以下源码路径相对 `plugins/dsh-crwu-workbench/`，执行前读取当前内容：

- `src/client/styles/tokens.ts` 主动定义了浅灰底、灰色选中态、灰色控件；主按钮浅色模式是 `#1D1D1F`，深色模式是 `#F2F2F3`。中瑞红 `--crwu-brand: #D84A4A` 已存在，但主要用于少量细节。
- `docs/ui-design-guidelines.md` 第一节沿用“办公 + Apple”的旧目标；后续条目仍限制渐变、玻璃效果和大面积色彩，并规定灰黑主操作。此前提示词进一步强化了中性风格。
- `src/client/styles/bundle.ts` 统一合成插件样式；`install.ts` 注入插件自己的 style 节点。这说明插件有自己的视觉实现边界，源码中的灰色有直接设计来源。

据此先更新设计目标和语义色板。单凭源码不能判定用户当前运行产物是否最新；如修改后仍显示旧色，需要核对实际加载产物、样式节点及 computed style，再定位加载问题。

## 2. 本轮视觉定位

推荐方向为**任务聚焦**：保留现有业务导航，在正文顶部用紧凑的任务阶段提示、品牌红的 AI 操作标识与局部柔和光感建立识别；核心表单是一张清晰的工作纸。另一个较克制的方向为“品牌工作纸”，可作为密集列表页面的表现方式，两者属于同一套色板与控件系统。

“AI 感”需要在以下位置有具体表现：

1. **身份**：原有中瑞品牌图形与名称保持，配一个轻量 AI 标识；品牌图形继续用现有 `BrandMark`，无需重绘或用通用星星替换。
2. **层次**：暖色背景、清晰纸面、悬浮菜单和确认抽屉拉开空间关系。页面上方可有低浓度红色径向光感，正文始终易读。
3. **操作**：可用的 AI 主操作使用品牌红交互色，拥有轻微高光与阴影；选中导航、focus、下拉选中项采用同一品牌色系。
4. **任务**：用真实阶段解释“资料整理 → 输入核对 → 会话执行”。阶段来自现有状态，不能伪造估值完成、知识已读或数据已连接。
5. **反馈**：只在用户操作、准备中或创建中使用局部短动效。静止阅读时安静，内容滚动时稳定。

建议大部分页面面积继续承担资料阅读，品牌色集中在关键区域；低浓度品牌底面提供氛围。整体应当明显区别于当前灰色版本，同时仍适合长时间办公。

## 3. 色板与语义 token

保留现有 `--crwu-brand: #D84A4A` 的品牌身份。为按钮、AI 氛围和状态新增或调整独立语义 token，不通过品牌色同时驱动错误提示和所有装饰。

以下为实施起点，需要在真实字体尺寸与实际背景上核对对比度：

| 语义 | 浅色起点 | 深色起点 | 应用 |
| --- | --- | --- | --- |
| 品牌原色 | `#D84A4A` | `#D84A4A` | 标志、品牌身份 |
| AI 操作强调色 | `#C83E45` | `#F0787C` | 主操作、关键选中与 focus |
| 操作强调 hover | `#B12D36` | `#F59194` | 按钮与交互反馈 |
| 强调色上的文字 | `#FFFFFF` | `#221215` | 与操作强调色配对 |
| 工作台底面 | `#F6F3F5` | `#171419` | 轻暖灰 / 深石墨底 |
| 主表面 | `#FFFFFF` | `#211C23` | 工作纸、菜单、抽屉 |
| 输入/次级表面 | `#FBF9FB` | `#2A232C` | 输入区、弱次级操作 |
| 主文字 | `#262129` | `#F2EDF1` | 正文与重要条件 |
| 次文字 | `#756C76` | `#B2A6B2` | 提示与元信息 |
| 装饰分界线 | `#E9E1E7` | `#443844` | 纸面及区块分隔 |
| AI 浅底 / 光感 | 强调色约 4%–12% 混合表面 | 强调色约 6%–14% 混合表面 | 核心条件底、页头局部氛围 |

- 建议语义名：`--crwu-ai-accent`、`--crwu-ai-accent-hover`、`--crwu-ai-on-accent`、`--crwu-ai-soft-bg`、`--crwu-ai-focus-ring`、`--crwu-ai-glow`。按实际用途裁剪，保持单一色板来源。
- 原有 `primary` token 如果承担主要业务操作，可以统一映射到新操作色；先审阅全部使用点，避免只改估值按钮导致审核主操作仍然黑白。
- 表中分界线是装饰边界；必要输入框、focus 和错误提示另用足够清晰的语义槽，不能因柔和配色而变得不可识别。
- 风险、警告、成功、禁用仍沿用各自业务语义。AI 装饰红与错误态通过位置、图标、标签和样式区别；错误有明确错误文案。
- 颜色字面量集中在 `tokens.ts`，组件只引用语义变量。深色按 `body[data-ds-dark-theme]` 切换，跟随现有 DSH 主题。无需给产品增加一套主题开关。
- 浅深主题都检查正文及按钮文字对比度。深色按钮不能直接套浅色白字方案；不要把半透明背景叠在未知内容上承载正文。

## 4. 逐区域视觉要求

### 工作台外壳与导航

- 顶部保持紧凑，原有品牌、版本/更新及真实用户信息按现有行为展示。可加入小型 AI 标识，描述功能身份；不要捏造“模型在线”“知识已连接”等实时事实。
- 页面外壳使用带暖色层次的底面。内容上方可以有局部径向品牌光感，随正文向下迅速淡出；避免整页红色铺底。
- 一级导航当前项采用品牌色文字、明确的底部标记或轻量选中底。二级导航/选项使用低浓度品牌底与可识别形状。当前一级、二级导航结构以实际配置为准，视觉改造不自行恢复已取消的目录。
- 当前区域之外保持中性，让已选状态明确。hover、focus、pressed、disabled 各有表现。不要把所有导航做成同样的红色胶囊。
- 作用域限定于插件自己的挂载点。DSH 宿主聊天、其他插件、全局侧栏底色继续由宿主管理。

### 估值工作面

- 保持一张工作纸、单列任务流，使用适量留白与分隔。纸面顶部可以有紧凑的真实阶段条，当前“整理资料”用品牌色强调；点击“核对资料”后才进入核对阶段。此阶段条是状态说明，不强制增加串行向导或重复点击步骤。
- 资产类型与评估方法均必填，紧接文件选择区。方法保持四项开放，`auto` 为显式选项；新草稿空态、有效枚举校验、预览回显校验延续前一份要求。
- 两个核心字段可共享一个约 4% 品牌浅底区域，增强“本轮重要条件”的识别；表单的全部字段不逐项套卡片。
- 下拉控件统一高度、图标、圆角与焦点。展开选项的选中项使用浅品牌底与勾，键盘活动项有独立清晰高亮。保留完整键盘、定位翻转、滚动和焦点恢复行为。
- 文件区使用清晰行布局，文件名优先，元信息次级。空资料时可以用低浓度品牌背景与轻量文件图标；已有文件时恢复紧凑列表。
- 补充要求可以用小型 AI 说明识别其作用；用户输入的正文保持正常颜色。不要对用户尚未提交的资料自动生成虚假分析、适用方法或结论预览。
- “信息获取辅助”继续位于下方，保留可选属性，链家状态与当前动作清晰可见。辅助能力使用中性次级操作，不能与“核对资料”竞争。
- 底部使用通栏轻分隔和清晰主操作。“核对资料”“开始估值”采用品牌 AI 操作色，其余使用中性按钮。

### 确认抽屉

- 使用共享 `SideDrawer`，主体保持不透明且可阅读。允许页头局部品牌柔光或细品牌线；正文不整块套玻璃、红底或发光描边。
- 顶部标题和说明明确，开头的资产、方法、纳入数量与基准日可置于一块轻品牌底摘要面。文件清单、补充要求、辅助能力依次建立层级。
- 资料行保留完整路径/时间等可展开详情与复制；初始主要呈现文件名与必要元信息，避免全量技术细节平铺。
- 链家登录状态与适用动作必须在抽屉可见，检查中为局部反馈。未登录、未知、失败均不阻塞创建，已登录不代表所有页面都可访问。
- 保留宽度 token、窄屏全宽、唯一正文滚动、固定 head/footer、焦点约束、背景 inert、返回恢复焦点、创建期间四条关闭路径锁定与退出动画生命周期。

### 审核、环境与共享控件

- 审核页借用同一新色板、导航、按钮、focus、浮层和抽屉语言；保留列表信息密度和风险语义。它是新工作台的一部分，不能保留成另一套灰黑主题。
- 环境页和加载/错误/空态复用新表面、字号与按钮体系。真实错误和依赖问题继续准确表达。
- 同步共享按钮、选择器、菜单、Notice、抽屉与 shell 的视觉。不要在各个业务组件里分别硬编码略有差异的红色。

## 5. 品牌科技感的动效

| 场景 | 实现要求 |
| --- | --- |
| hover/focus | 120–160ms 颜色、阴影和边界变化；focus 使用柔和红色 ring，清晰可见。 |
| AI 主按钮 | hover 阴影略增强，最多约 1px 上移；pressed 迅速反馈。高光固定或随一次交互短暂变化，闲置时不循环扫光。 |
| 下拉 | 约 150ms 淡入与不超过 4px 位移，chevron 旋转；约 100–120ms 退出后卸载。 |
| 输入准备中 | 原按钮 loading，加局部状态文字；可使用短线段或小范围品牌光感反馈真实 pending。耗时未知时无百分比和假进度。 |
| 阶段变化 | 从真实状态切换当前步骤，150–200ms 强调变化；完成的只有已发生的步骤。 |
| 抽屉 | 沿用约 200ms 入场、150ms 退场，内容保留到退出结束，遮罩同步淡变。 |
| 信息反馈 | 复制约 1.5 秒短确认，状态变化就地更新；不让表单、文件行或整个页面反复闪入。 |

`prefers-reduced-motion` 下关闭位移、缩放、扫光与旋转，立即结束展示/卸载过渡，仍有文字状态。处理 timer、监听和观察器清理。光感不是全屏 blur，也不要求 WebGL、粒子背景或新动画依赖。

## 6. 样式未生效时的定位方式

如果实际运行仍然灰色，请直接用浏览器证据定位：

1. 核对当前加载包的版本/构建身份与目标开发产物，区分 Host 与 Client 的加载时机。
2. 确认 `crwu-audit-package-styles` 节点存在且内容来自本次构建，排查多个旧样式节点或错误安装路径。
3. 在工作台、浮层与抽屉根节点确认 `data-crwu-scope="workbench"`；检查新 token 的 computed value，确认明暗主题选择器与实际宿主属性匹配。
4. 读取主按钮、导航选中项、工作纸和下拉的 computed style，查明最后生效规则。验证背景及文字落到新的主题配对上，而非旧局部规则覆盖或无定义变量导致声明失效。
5. 按项目正规构建/加载流程修复，源文件为修改入口。用户活跃 profile 的重启按仓库约定执行，不直接修改安装产物解决表面问题。

不要把“DSH 都是灰色”作为未经验证的结论。样式问题应给出命中的变量、规则和实际加载身份。
