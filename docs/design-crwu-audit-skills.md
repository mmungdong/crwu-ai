## 1. 目标与定位

`crwu-audit-*` 是**可执行的报告审核能力族**，按技能分目录放在本仓库 `skills/`（与 `h3yun-*` 同层，均为"提示型 Skill"）。每个叶子技能 = 一组端到端审核能力：**画像子集 → 适用规则集（读 crwu-knowledge L1）→ 预装配清单 → 分区执行 → 意见输出 → 防幻觉自检**，且"只读、不下最终价值裁量以外的判断、引用必须带依据"。

**总路由 `crwu-audit`（后续实现）**：对原始材料做画像首判后**调用对应叶子技能**，本身不执行具体审核判断（职责单一，呼应 crwu-ai AGENTS"单一职责"）。

## 2. 为什么按"审核能力逻辑"划分：五个判据

一片叶子技能应当"换一套就要整体换逻辑"。可观测判据（自上而下判定优先级）：

| 判据 | 说明 | 影响 |
| --- | --- | --- |
| ① report_type 报告形态 | 评估报告（法定，全准则适用）vs 咨询报告/估值报告（参照口径、无有效期条款等） | 决定条款强制力与清单性质；边界引用 RULE-01-02-435（不得以咨询/估值替代法定评估） |
| ② object_type 对象大类 | 不动产（房建）/企业价值/无形资产/机器设备/矿业权… | 决定对象层准则、披露重点与主要特别事项 |
| ③ method 主要方法组合 | 市场法（租金比较/可比交易）、收益法（租约）、成本法（重置/指数修正）、假设开发、基准地价… | 决定方法层清单与模块装配 |
| ④ scenario 场景 | 经营性物业出租/一般商业/国资/证券/成果转化… | 决定租约、军产、核准备案、披露等附加关注与监管子集 |
| ⑤ 能力就绪度 | 该叶子依赖的 L1 规则/清单是否已精编（A 待发布即可试点）、有无校准样本 | 决定"现在能不能建、能不能正式跑"（本期排期用） |

> 叶子不是"按文件名组织"，而是 ①②③④ 组合稳定后仍需要**同一套清单与关注点**的那一类报告。

## 3. 命名与目录规范

- 目录：`skills/crwu-audit-<key>/`，内含 `SKILL.md`（frontmatter：name/description，触发语按报告类描述）。
- 命名：`crwu-audit` 开头 + 英文小写连字符细分（key 取"对象/形态 + 能力子类"），例如 `crwu-audit-realestate-rent`。
- 总路由技能目录保留 `crwu-audit/`（key 不含后缀）。
- 每个新叶子必须：① 在 `skills/README.md` 注册；② 在本文档路由表登记画像判据；③ 正文标注其只读引用的知识库清单/规则文件路径（**禁止复制规则正文**，保持单一事实源）；④ 经质控确认命名与边界。

## 5. 总路由 `crwu-audit` 契约（下阶段实现，先定契约）

1. **输入**：待审材料包（目录约定见 audit-skill/01 调度总纲）或氚云项目定位（报告审核流水号等）。
2. **画像**：report_type → object_type → method 集合 → scenario → stage → purpose/base_date（无基准日留空）。
3. **路由查表**：按 §4 表命中叶子 → 调用该 `SKILL.md` 的完整流程；未命中 → **如实返回"该画像暂无对应审核能力"，禁止硬套**（空库静默协议）。
4. **汇总**：合并叶子输出（意见按分区去重），附《适用规则集快照》与依据三段式引用，交人工复核（答复/流转字段见知识库 audit-skill/06）。
5. **门禁透传**：叶子涉及的 RULE/清单若未人工发布 → 明示"试点模式（依据待发布）"，正式意见须发布后运行。

## 6. 落地优先级与数据依据（结合氚云报告审核占比）

| 排名 | 能力 | 依据 |

| P0（本期） | realestate-rent | 报告审核流占比最大对象子流（房建/不动产，风险 C 级单格最大）+ 规则/清单/校准样本全就绪 |

## 7. 演进规则

- 新增叶子：本文档 §4 加一行 + `skills/README.md` 注册 + 新建 `skills/crwu-audit-<key>/SKILL.md`；
- 叶子只读引 crwu-knowledge（不同仓库），知识库内容更新不复制进 crwu-ai；
- 变更/新增后按 crwu-ai `AGENTS.md` 在 `docs/CHANGELOG.md` 追加纪要。
