# M-外部数据核验 —— 模块规程

| 模块 | M-外部数据核验 | 版本 | v0.1 | 状态 | 设计 |
|------|----------------|------|------|------|------|

## 0. 接口契约

```yaml
module_id: M-外部数据核验
scope: 报告引用的外部公开数据的核验：事实型数据取值比对、取数口径与来源的披露检查、
       关键参数的副源复核；只出"符合 / 不符合 / 请说明 / 未检查"，不做价值判断
not_scope: 参数取值合理性与方法适用性（归 M-收益法 / M-市场法）；报告内部与跨表数字勾稽
           （归 M-数据校对）；披露完整性的通用检查（归 M-报告披露）；
           数据源的技术调用与配额（系统层）
inputs: 报告、评估说明中被引用的外部数据及其原文位置；系统按本次清单取回的外部数据快照
        （含数据来源、取数时点、口径参数、单位）
outputs: 外部数据核验意见（数据项 / 报告值 / 外部值 / 来源 / 时点 / 口径 / 判定 / 证据位置）
         → 移交相关方法模块与终审人
kb_scope: 本模块规程（本文件）表 A–表 D；modules 含 [M-外部数据核验] 的条目
protocol: 继承 5.4 防幻觉三道协议；取数口径不一致时禁止作数值判定，只出"请说明"
maintainer: 待定
```

## 1. 职责边界

- **只负责"报告引用的外部公开数字对不对得上、取数口径与来源有没有说清"**；结论影响判断归 M-方法类模块与终审人；
- **事实型数据可判"不符合"**：有唯一正确答案的客观数值（上市公司财报科目、股票收盘价、市值、债券余额、公司属性事实）；
- **模型型数据只出"请说明"**：由机构加工、口径不同结果不同的数值（β、行业平均市盈率、一致预期利润、行业增长率），不得判"数据错误"；
- **专业判断一律不管**：折现率整体取值、特定风险、永续增长率、流动性折扣、控制权溢价、修正系数，转 M-收益法 / M-市场法 与人工；
- **不得用外部数据反推审核要求或生成准则依据**。

| 对方模块 | 移交内容 | 说明 |
| --- | --- | --- |
| M-数据校对 | 报告内部与跨表数字勾稽 | 本模块不重复，避免同一事实双出意见 |
| M-收益法 | 无风险利率、β、ERP、资本结构的外部取值与口径披露 | 本模块出证据，判定归其 |
| M-市场法 | 可比公司股价、市值、财报、价值比率的外部取值与口径披露 | 本模块出证据，判定归其 |
| M-报告披露 | 参数未披露取数口径与来源的条目 | 本模块出事实，披露完整性归其 |
| M-画像与调度 | 数据源未配置、取不到 → 未检查项与能力缺口 | 由其汇总登记 |

## 2. 表 A · 触发范围（三条同时成立才启动本模块）

| 判定线 | 成立条件 |
| --- | --- |
| 业务线 | 业务以公允价值计量、交易定价或财务报告为目的 |
| 资产线 | 对象存在公开市场锚点：上市可比公司、公开市价、公开商品价 |
| 方法线 | 报告实际采用或参考收益法、市场法 |

**用途**：保证"该组合下应当核的没漏"（覆盖检查与回归）。**实际核验以报告实际引用的外部数据为驱动**，不逐条遍历本表。

## 5. 表 D · 万得启用条件与降级

| 条件 | 触发 | 动作 |
| --- | --- | --- |
| W1 差异触发 | 同花顺取回值与报告值不一致：事实型数据相对差异 > 1% 且超过该指标最小有效位 | 万得复验；两源一致 → 报告值疑似异常；两源不一致 → 只出"请说明" |
| W2 关键参数 | 命中关键参数清单 | 直接双源，先按统一口径标准化再比对 |
| W3 兜底 | 同花顺无覆盖或取数失败 | 万得替代；仍无 → 未检查项 + 能力缺口 |
| W4 高风险项目 | 审核风险等级最高档且影响最终估值结论 | 双源复核 |
| 其余 | 事实型、非关键、低风险 | 只用同花顺 |

**关键参数清单（W2）**：无风险利率、β、市场风险溢价、资本结构、报告引述的价值比率、债券估值与收益率曲线。

**万得未配置或不可用**：W2 / W4 降级为"单源 + 请说明"，并在报告中显式声明；W1 / W3 记未检查项。

**统一口径**：双源比对前必须先按同一口径标准化（期限、窗口、频率、基准指数、时点、复权与异常值处理）；口径无法统一的，不作数值比对。

## 6. 数据留痕要求

每条核验记录必须具备：**数据项、数值、数据来源、取数时点、取数口径、单位、取数参数**。缺任一项，不得作为判定依据，只能登记为未检查项。

## 7. 结论档位与禁止事项

| 情形 | 结论 |
| --- | --- |
| 事实型数据与外部一致 | 符合 |
| 事实型数据与外部不一致 | 不符合（两源相互支持时证据更强） |
| 模型型数据与外部有差异 | 请说明（须同时注明"差异因取数口径不同，不构成数据错误"） |
| 报告未披露取数口径与来源 | 请说明（不需外部数据即可判定） |
| 口径不可比 | 不作数值判定，只记录口径差异 |

禁止：① 两源口径不一致时判"数据错误"；② 以供应商之间数值差异否定报告参数；③ 未留痕取数口径即出数值判定；④ 以外部数据反推审核要求或生成准则依据。

## 8. 未检查项与缺口记录

| 情形 | 记录方式 | 是否影响其他检查 |
| --- | --- | --- |
| 副数据源未配置或不可用 | 报告中显式声明：本次未配置副数据源，相关条目未经双源复核 | 不影响 |
| 主源无该数据覆盖 | 未检查项（原因码待分配）+ 能力缺口 | 不影响 |
| 两源口径不一致 | 记录口径差异，不作为数据差异 | 不影响 |
| 两源口径一致但与报告不符 | 不符合事项，附报告位置与两源数值 | 仅挂起相关检查项 |

意见条目编号格式：

```yaml
- ext_id: EXT-001
  数据项: 【指标名称】
  报告值: 【实际值】 位置: {文件: 评估报告, 章节/表: …, 定位: 段/页/单元格}
  外部值: 【实际值】 来源: 【同花顺 / 万得】 时点: 【取数日期】
  口径: 【期限/窗口/频率/基准/算法】
  判定: 符合 | 不符合 | 请说明 | 未检查
  移交: [M-收益法 | M-市场法 | M-报告披露 | 终审人]
```

## 9. 员工补录机制（表 A–D 的追加通道）

**触发**：审核中发现报告引用了某项外部数据，而表 B / 表 C 未覆盖。

**当场怎么做**（不得因为表里没有就跳过或口头带过）：

1. 仍按本模块规则核验：默认走同花顺，是否上万得按表 D 判断；
2. 在下方「待补数据项」区登记一条，**不直接改表 A–D**；
3. 核验结论照常进入本次意见。

**登记格式**：

```yaml
- 提出人: 【姓名】  日期: 【YYYY-MM-DD】  来源单: 【SeqNo / 项目编号】
  数据项: 【名称】  建议键: EXT_【…】
  归属: 业务【…】/ 子业务【…】 × 资产【…】 × 方法【…】
  主题: 【…】  检查点: 【…】
  建议源: 同花顺 | 万得 | 双源    依据: 【为什么需要 / 出现在报告哪里】
  证据: 【报告位置 / 取数快照】
```

**归口**：由知识质量控制员复核后并入表 B / 表 C，并在《审核模块注册表》§6 变更登记留痕；未采纳的条目保留在待补区并注明原因。

**为什么不当场改表**：知识库变更即生效、无试点期——未经复核的行一旦入表会立刻成为全公司有效要求，故先进缓冲区。

## 10. 依赖的 KB 首批条目（Phase 1 精编优先级）

报告准则（外部数据引用与披露相关条款）、评估方法准则（参数披露要求）、程序准则（核实程序与底稿留痕）、易错点库首批（口径不同误判为数据错误、以供应商差异否定参数等）、校准案例记录（含基准日错配与非权威来源案例）。
