## 1. 协作边界

- 钉钉知识库是规则、检查点、契约、案例等知识正文的唯一来源。
- crwu-audit 负责画像、路由、汇总命中技能的装配路径，产出本次审核下载清单。
- crwu-dws 负责解析清单、从钉钉下载正文、记录 manifest，不做审核判断。
- audit 叶子技能只读取本次审核下载物并执行 RULE/CHK。
- 本地目录缓存只保存目录结构、nodeId 与路径索引，不保存正文，也不能作为正文兜底。
- 当前审核的 `knowledge/` 是工作集，不是可复用知识库；跨审核和重跑必须重新下载。

## 2. 不变量

- **R1 正文唯一来源**：审核引用的知识正文只能来自该次审核期间的钉钉导出。
- **R2 文件零缓存**：本次下载物仅属于本次审核；上次审核文件不得作为本次依据。
- **R3 清单驱动**：只下载本次清单的单文件命中项和目录展开项；清单外零下载。
- **R4 目录元数据可缓存**：目录缓存只回答节点是否存在、路径和 nodeId；未命中时在线刷新。
- **R5 稳定寻址**：技能保存 RULE/CHK 编号与库内层级路径，不保存知识库名称、个人绝对路径或 nodeId 常量。
- **R6 可追溯引用**：出处包含本次下载文件、实际行号、库内路径、nodeId 与 `exportedAt`。

## 3. 清单项协议

同一清单允许混合两种条目：

1. **单文件路径**：不以 `/` 结尾。精确解析到一个文档后只下载该文件。
2. **目录路径**：以 `/` 结尾。精确解析目录后递归下载目录下全部支持的正文文件。

一个明确文件足以完成检查时应使用单文件路径；只有需要目录内全部正文时才使用目录路径。清单展开后按 nodeId 去重，同一文档在本次审核只下载一次。

## 4. 审核期数据流

```text
crwu-audit 画像与路由
  → 汇总 L1/L2 装配表和执行契约路径
  → 生成本次审核清单（文件项 + 目录项）
  → crwu-dws 用目录索引定位；未命中则刷新目录
  → 从钉钉逐文档导出到本次审核 knowledge/
  → 写 .crwu-manifest.jsonl 与 .crwu-directory.json
  → 叶子技能按本次文件执行 RULE/CHK
  → 输出引用：文件:实际行号 + 库内路径 + nodeId + exportedAt
```

新审核或重跑从“生成清单”重新开始，不读取上一轮正文。

## 5. 下载失败与降级

- 单文件路径零命中、多命中或命中目录：记录 failure，不猜测目标。
- 目录路径零命中或命中非目录：记录 failure，不改成相近目录。
- 文件类型不支持：记录 skipped；需要该正文的检查点标记无法执行。
- 钉钉导出失败：记录路径、nodeId（如有）和错误；对应检查点不引用、不编造。
- 目录刷新失败：可用旧目录元数据辅助定位时必须标注可能过期，但仍不得由缓存提供正文。

## 6. manifest 证据

每个成功或失败条目至少记录：

| 字段 | 含义 |
| --- | --- |
| requestPath | 装配表中的原始路径 |
| requestKind | file / directory |
| nodeId | 钉钉真实返回；未解析时为空 |
| localPath | 本次审核工作文件相对路径 |
| exportedAt | 本次正文导出完成时刻 |
| evidence | dws 导出回执 |
| status/error | entry、skipped、failure 及原因 |

目录条目展开出的每个文档保留同一个 `requestPath`，便于追溯下载范围。

## 7. Skill 维护纪律

- 装配表头必须声明文件与目录两种语义。
- 明确引用一份文档时写完整文件路径，不得为了省事扩大为整个目录。
- 执行契约按所需文件逐项列入清单。
- 路径变更时同步修改装配表、Skill 指针和活动设计文档。
- 运行时部署由用户的 Skills 管理机制负责；源仓维护者不直接改运行时目录。

## 8. 验收

| 场景 | 通过标准 |
| --- | --- |
| 单文件清单 | 只产生该文件的 entry |
| 目录清单 | 递归展开该目录的支持文档 |
| 混合清单 | 文件项和目录项均执行，nodeId 去重 |
| 清单外文档 | manifest 中不存在其 entry |
| 跨审核 | 每个正文重新导出，`exportedAt` 属于本次 |
| 缓存检查 | 目录缓存只有快照、树、索引和元数据 |
| 下载失败 | 对应检查点不引用、不编造，并保留 failure |
