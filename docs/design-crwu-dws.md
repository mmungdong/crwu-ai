## 0. 一句话定位

**提示型 skill**：运行于 agent，通过宿主注入的 `dws` CLI（wiki/doc 产品域）以**对钉钉纯只读**方式，围绕「中瑞世联 AI 测试知识库」提供三个模式 + 一个缓存层：

- **M1 目录查询**：解析用户可见范围内全部同名知识库 → 逐库递归导出完整层级目录 → **写目录缓存**（`~/.crwu/knowledge/dws-dir-cache/`）+ 聊天摘要/目录树展示。
- **M2 知识文档批量下载（案例镜像）**：把 crwu-audit 及子 skill 推理时依赖的参考知识文档，按库结构批量导出到与源审核数据文件同级的案例目录 `knowledge/`，供该案例审核时参考。
- **M3 缓存兜底查找**：skill/用户按 **文件名或 nodeId** 查找——先查本地目录缓存；未命中 → **刷新目录缓存**后再查；仍未命中 → 如实报告"没找到"。命中但要正文 → **实时拉取**（临时取用、不保存），保证内容永远是最新版。
- **缓存层原则（用户定稿）**：**目录可缓存、正文不缓存**。`~/.crwu/knowledge` 缓存只存目录结构与 nodeId 索引，永不存正文内容；正文每次由钉钉现场导出取用即弃（唯一例外=M2 案例镜像，属用户显式要求的案例期材料快照，非缓存复用）。
- **缓存名一致（v0.3.1/D12）**：目录缓存按 `<库名>` 分目录、只对与 skill 目标库名一致的库有效；缓存库名不一致（改名/换库/历史残留）→ **清理该缓存目录并在线重下目标库结构**，禁止把别的库的缓存当目标库索引（防跨库误命中）。

对钉钉零写操作。员工在钉钉更新文档 → AI 查目录可能旧（自动刷新兜底）、取正文永远最新。

## 1. 背景与动机

- crwu 生态知识库唯一事实源路线（skills/README §V2.1 + tools/kb/README「迁移/演进」）：本地 `~/.crwu/knowledge/knowledge-base`（CRWU_KB_ROOT）为静态根（仅维护/离线归档，不冒充实时）；钉钉知识库打通后目录内容向本地迁移、可换根。
- crwu-audit 及子 skill 推理时有两类输入：① **源审核数据文件**（材料包）；② **参考知识文档**（规则/清单/案例——员工在钉钉持续更新）。
- v0.1/v0.2 解决了"看目录"与"案例期镜像"；**缺一层"查找兜底"**：skill 推理时按 RULE 编号/文档名/nodeId 找参考文档，不能每次全量在线遍历（慢、脆），也不能信任一份可能过期的静态副本——于是：**目录层用本地缓存 + 未命中自动刷新；正文层永远实时取用**。

## 4. 明确不做（硬边界）

- **对钉钉零写操作**（同 v0.2，白名单不变）。
- **缓存层永不存正文**：`~/.crwu/knowledge/dws-dir-cache` 只存 目录结构/索引/元数据；任何正文导出结果**禁止**写入 `~/.crwu/knowledge`（含 knowledge-base 子树）与任何"缓存"语义目录。
- **M2 只收 adoc 为文本文件**（axls/able 等跳过如实报告，D7）；M2 案例镜像**不是缓存**：仅对"该案例启动时点"有效，跨案/长时复用须重跑 M2 或 M3 现场拉取。
- 不自动删除本地旧文件（远端已删 → 本地保留+清单）；不操作 CRWU_KB_ROOT/kb_tool；不做审计判断；泛化 wiki/doc 管理走 dingtalk-wiki/doc。
- **禁止推断**：缺字段如实标注；查找失败/刷新失败不吞错、不用旧缓存假装新鲜、不编造"已找到"。

## 5. 架构与依赖

- **形态**：提示型 Skill：`skills/crwu-dws/SKILL.md` + `references/`（00 快照 schema / 01 镜像 manifest / **02 缓存与兜底查找规范**）；无新依赖、不进 crwu Go 构建；源仓提交即交付，运行时部署由用户 skills 管理机制负责。
- **依赖**：`dws` CLI（≥0.2.14，宿主注入）；命令语义权威 = `dingtalk-wiki`（目录/节点）+ `dingtalk-doc`（正文导出 `+export --export-format markdown`，回执 `localPath`+`sizeBytes>0` 即终态）；错误走 `dingtalk-shared`。
- **缓存位置**：`~/.crwu/knowledge/dws-dir-cache/<库名>/`——**与 CRWU_KB_ROOT（=knowledge-base 子树）同级隔离**，kb_tool 不扫描、技能引用不指向此处（它是缓存不是事实源；事实源=钉钉）。
- **上下游**：上游=钉钉知识库（员工维护）；下游=①案例目录（M2）②目录缓存（M1/M3）③消费缓存的各类 skill（crwu-audit 族等，联动见 §8）。

## 6. 缓存与实时性模型（核心语义，用户定稿）

1. **目录可缓存**：目录结构变化低频，可本地缓存；缓存内容 = 目录快照 + 目录树 + nodeId↔名称/路径索引 + 元数据（fetched_at/evidence/版本）。
2. **缓存永不等于事实源**：事实源 = 钉钉实时。任何"有没有这个文件/nodeId"的**权威结论**必须来自一次成功刷新后的目录（在线遍历）或"刷新失败"的如实降级；缓存只用于减少在线遍历次数。
3. **正文不缓存、永远实时**：正文一律现场 `doc +export`（下载时点=钉钉当前版）；取用后即弃（临时区），或经用户明确指令走 M2 案例镜像。**禁止**把任何历史正文副本当作"最新"提供给推理（包括本技能缓存、CRWU_KB_ROOT 静态副本以外的任何副本）。
4. **未命中兜底**：缓存查不到 → 自动刷新（在线全量遍历、原子替换缓存）→ 重查 → 仍未命中 → 报告"库内不存在：<文件名/nodeId>（已刷新目录后仍无）"并附相似候选（若可枚举），不编造、不猜测。
5. **刷新失败降级**：在线刷新失败（网络/权限/分页未完成）→ 若旧缓存可用：用旧缓存作答并**显式标注"缓存可能过期 + 刷新失败原因"**；无缓存 → 报告"无法确认（缓存缺失且在线刷新失败）"。
6. **缓存名一致**（v0.3.1/D12）：缓存库名与目标库名不一致的缓存目录一律**先清理、在线重下后再用**；缓存永不跨库复用（防误命中），清理动作必报告。

## 7. 工作流设计（SKILL.md 已固化）

### P0 前置断言（同 v0.2：dws 可用、profile 明确且全程一致）

### P1 库解析 / P2 目录遍历（M1/M2/M3 共用底座，同 v0.2：双范围精确名匹配 → DFS 递归 + 分页证据 + 防环 + 体量上限 10,000×20）

### P3-M0 缓存清理层（v0.3.1：缓存名一致性；M1/M3 用缓存前置，M2 不涉及）
1. **目的**：缓存目录按 `<库名>` 分目录且只对目标库有效；别的库名的残留缓存被当目标缓存查找 = 跨库误命中 → 禁止，**先清理、再在线重下**。
2. **判据/动作**：缓存目录身份 = `.cache-meta.space`（name+workspaceId）。与本次目标（默认「中瑞世联 AI 测试知识库」或指定库名；M1/刷新路径按 P1 name+workspaceId 双匹配，M3 命中路径按请求库名名级对账、不发起在线遍历）不一致，或 meta 不可证实且目录名 ≠ 目标 → **整体删除该缓存目录**，随后在线全量遍历重下（P3-M1 原子写缓存；M3 走其刷新路径后重查）；meta 不可证实但目录名 == 目标 → 按缓存损坏刷新覆盖，不删除。
3. 清理只动 `dws-dir-cache`（不碰案例 knowledge/、CRWU_KB_ROOT、远端）；清理动作必在摘要/结论报告。

### P3-M1 目录查询 → **写缓存（原子替换）**
0. **前置（v0.3.1）**：P3-M0 清理层对账——与本次目标库名不一致的残留缓存目录先清理并报告（不参与任何查找/复用）；
1. 遍历完成 → 组目录树/快照/索引（references/00+02 schema）；
2. 写入 `~/.crwu/knowledge/dws-dir-cache/<库名>/.tmp-*` → 校验完整 → 原子 rename 覆盖正式文件（防半截缓存）；
3. 更新 `.cache-meta.json`：`{last_successful_at, source:"dingtalk-live", profile, evidence 摘要}`；
4. 摘要展示同 v0.2；**任何一次成功遍历都刷新缓存**（M2 的 `.crwu-directory.json` 视为该案例副本，不影响缓存）。

### P3-M2 批量下载（同 v0.2，补充 3 条）
1. 案例目录决议不变（§3/D6）；
2. 执行/记账/收尾不变（adoc→md、manifest、幂等、残留清单）；
3. **补充**：① 镜像文件 manifest 均带 `exportedAt`；② 摘要提示"本镜像 = <时点> 快照，仅供本案参考；需要再次最新 → 重跑 M2 或对单篇走 M3"；③ 镜像与正文**不得**进入 `~/.crwu/knowledge/dws-dir-cache`。

### P3-M3 缓存兜底查找
输入 文件名（精确）或 nodeId（精确）：
0. **P3-M0 清理层前置（v0.3.1）**：目标名级对账（命中路径不发起在线遍历）→ 库名不一致的缓存目录先清理（结论注明）；目标无一致缓存（含刚清理）→ 直接走步骤 2 刷新；
1. **查缓存**：读 `node-index.json`（nodeId → 条目；名称 → 条目列表，可能多命中）：
   - nodeId 命中 → 给 条目元数据 + 树路径上下文（folders 链）；
   - 名称命中唯一 → 同上；名称命中多个 → 全部列出路径上下文请调用方/用户消歧（不猜）；
2. **未命中 → 刷新**：重跑 P1+P2 在线全量遍历 → 原子更新缓存（同 P3-M1）→ **重查索引**；
3. **仍未命中 → 报告**："未找到：<名称/nodeId>（目录已刷新至 <时间> 后仍不存在）"+ 相似候选（名称相近节点，≤5）；
4. **命中且调用方要正文** → 现场 `dws doc +export`（临时文件）→ 交付内容/读取后即弃，**不保存**（若用户明确要留档 → 走 M2 单篇镜像语义：文件进案例 knowledge/ 并登记 manifest，不进缓存层）；
5. 缓存缺失/损坏/刷新失败 → §6.5 降级口径，不假装权威。

### P4 一致性自查（v0.2 同款 + 缓存自身校验）
- M1：快照计数一致才写缓存并宣称全量；
- M3：报告必须标注结论依据（"缓存命中（<fetched_at>）" / "刷新后命中（<时间>）" / "刷新后仍无" / "降级：缓存可能过期"），禁止无来源结论。
